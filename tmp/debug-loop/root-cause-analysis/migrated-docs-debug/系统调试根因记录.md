#### ROOT-CAUSE-P0-2

本轮新的 live blocker 不是 screenshot 再次失败，而是 Orchestration 在 step 成功后到 transition success 落盘之间存在 silent stop 窗口。

控制链如下：

1. src/capabilities/orchestration/runtime/orchestration-executor-loop-iteration.ts
    `handleDispatchedStep(...)` 已经成功执行 `recordStepResult(...)`，因为 `CAPABILITY_CALL_COMPLETED(open-facebook-reels)` 已经真实写出。
2. 同一函数随后调用 `evaluateStepTransition(...)`，再进入 `handleTransitionSuccess(...)`。
3. `handleTransitionSuccess(...)` 在记录 `STEP_TRANSITION_EVALUATED` 之前，先执行 `buildTransitionSuccessOutcome(...)`。
4. `buildTransitionSuccessOutcome(...)` 又会先走 transition success 的 state/proof 构建与 `persistOutcome(...)`，只有这些都完成后，才会写出 `STEP_TRANSITION_EVALUATED`。

因此，只要 transition success 路径内部抛出未被结构化接住的异常，任务就会呈现当前观测到的形态：

- step 本身成功
- 没有 transition success 事件
- 没有 terminal failure 事件
- mission loop 不再继续向下一个 step 推进

当前最小根因表述是：

> Orchestration step-success 到 transition-success 的边界缺少足够近的 unexpected-error 结构化收口；一旦该段内部抛出异常，mission loop 会在成功 step 之后静默停住，而不会把真实异常固化成新的 terminal blocker。
