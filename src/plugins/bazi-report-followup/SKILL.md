# 八字报告续问

## 指令边界

本 Skill 只服务 `bazi_report_followup`：根据本次获准入场的父报告与命盘材料回答一组新的冻结问题。必须保持原人物、原命盘或候选集、父报告与证据边界；不得重算命盘或引用其他任务材料。

父节点只能是同一 consultation root 下已经取得 approved Delivery Manifest 的 `bazi_ai_full_analysis` 或 `bazi_report_followup`。执行前必须同时核对当前付费授权，以及 consultation root、直接前驱 task/result/hash、父授权、owner/subject、命盘版本/hash 和 manifest id/hash。每次续问形成新的商业任务与授权结果，并从全新的 Provider conversation 读取本轮获准的完整父报告材料；不得读取、选择或续接历史 Provider conversation，也不得把当前授权与父授权互相冒充。

## 材料与事实

- 先识别父报告已经确认的事实、原判断及其条件，再处理本次新问题。
- 新问题可以要求解释、限定、纠正或指出父报告不足，但不能静默改写父节点或伪造原报告未说过的内容。
- 若问题引入新人物、新命盘、新出生信息或超出原授权的独立事项，明确要求创建新的业务任务。
- 原材料不足以回答时，说明缺少的事实及影响，不用一般命理套话填补。

## 专业要求

回答必须直接针对本次问题，并保持原命盘的候选范围、古籍证据、时序条件和不确定性。清楚区分父报告事实、当前进一步解释、当前新增推断和现实核验事项；不得把用户期待当成规则成立的证据。

## 输出要求

只返回当前结果合同要求的一份续问结果，不重复整份父报告，不生成第二份全盘报告。专业术语紧跟白话解释；任何补充或修正都说明依据、影响范围和是否改变原结论的适用条件。

不得作宿命、健康、法律、投资或现实结果保证，不得销售法事解法。

## 复核动作

`accuracy_challenge` 与 `quality_reflection` 只检查当前 subject followup 的父子绑定、事实、证据和回答范围，返回可核验 finding。不得修改父报告、当前回答或网站裁决。

## 资料定位与结果提交

先定位 BZ04 的本次问题和明确直接父报告；父正文、全部候选和当前问题分别读取，不以较新报告或摘要替换。

资料载体、数量与顺序以本轮任务合同为准；本 Skill 不改程序的上传、恢复或调度规则。收到拆分压缩资料时，先读目录、身份、用途与交付说明，再按目录读对应事实、条件、问题、既有报告和完整有序记录页；逐页覆盖本轮强制分母，不把分页当成截取或摘要。古籍按书独立保留原文与原索引，索引用于定位所需原文，不合并书籍、不把索引当正文。不将压缩包、整库或超长 JSON 一次全部打印进对话；先定位再读取所需文件或记录，禁止用大小、前若干项或代表候选裁掉资料。

正式结果必须是当前结果合同接受的一份完整 JSON 正文。不得把附件卡片、下载链接、sandbox 路径、代码文件或压缩包当成结果；不得只说“已生成”而省略正文。PDF 面向客户的制作与交付由网站原链路承担。复核动作仍只返回其原合同要求的 finding，不套用正式生产资料包或重新研究。
