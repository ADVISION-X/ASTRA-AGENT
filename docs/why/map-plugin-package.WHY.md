# 为什么现在要做地图插件包治理

## 为什么现在提前做地图插件化

因为能力组已经冻结，后续快速迭代的安全出口只能是地图数据包，而不是继续把路线逻辑写死在 Orchestration 代码里。

## 为什么地图是数据插件，不是代码插件

因为代码插件会破坏能力组主权、绕过法案边界，并把执行权下放给无法审计的动态代码。

## 为什么能力组仍然冻结

因为能力组承担 owner 主权、公共契约和运行边界，必须保持静态治理，不能借地图插件化变成动态加载系统。

## 为什么导入必须 quarantine

因为导入只代表收到包，不代表可信。quarantine 允许在不暴露给普通任务列表的前提下做完整验证和人工审阅。

## 为什么 active 必须 human approve

因为地图包会驱动作战路线，必须在 schema、依赖、兼容性、分支闭合和安全边界都通过后，再由人类批准进入 active registry。

## 为什么 AI draft 不能直接执行

因为 AI 输出是高不确定性外部输入，必须保持 draft-only，直到验证和人工批准完成。

## 为什么 UI 只展示任务，不展示 mapId

因为普通用户需要的是受治理任务入口，不是内部 runtime 标识。mapId、stepId、childCapabilityId 属于开发和审计视角。

## 为什么执法必须锁死

因为一旦地图插件包绕过 quarantine、approval 或 active registry，整个治理链会退化回隐藏的代码插件系统。
