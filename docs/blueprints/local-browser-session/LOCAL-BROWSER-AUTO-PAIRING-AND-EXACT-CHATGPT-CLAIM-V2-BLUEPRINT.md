Website 已以精确 `RESULT_SETTLED_UNUSABLE` 或 `GPT_RESPONSE_STOPPED_EMPTY` 拒绝整个旧 result revision 时，Browser 仅在原 rejection receipt 授权的新 revision、原 WAL 相关旧 command 全部 terminal 且未决集合为空、旧 WAL 全历史已核的同 job 中允许新 effect 各至多一次输入。此分支由 Website 的 `prior_result_rejection` 授权，与“答案不可取得”的逐调用风险 grant 互斥；未被 Website 拒绝的旧结果仍先零输入读回。旧 effect 与原 WAL 动作取证原样保留，不将拒绝当作零输入证明。

Browser 只拥有现实页面资源：已获 grant且未闭环 job与 system Target的一对一进程内绑定、实时 current Document、一条 FIFO、一条物理 lane、一个全局 Provider observation节拍、Provider/控件 mutation的唯一 WAL，以及页面生命周期动作后的 fresh readback。它不理解 Product步骤、不保存 GPT回答、不决定 retry或当前 N，也不拥有 Website task。

活动 job—Target 执行绑定只在当前 Browser Authority 会话的 live registry。Target/Document/authority epoch/fence/permit 只决定此刻物理动作位置；`browser_mutations.target_ref/document_ref` 只保留原动作取证。Browser SQLite 不得再存在 `browser_target_claims`、旧 Tab 恢复 registry 或其索引。跨 job 新页面 mutation 门以原 WAL 未决 `DISPATCHED`、唯一 FIFO/lane 和原 WAL 全部相关旧 command 真实 terminal、未决集合为空的 input-quiescence 证明裁决；原 Target 缺失、历史 tabId、空 registry、socket 断线均不能证明原 WAL 相关旧 command 全部 terminal 且未决集合为空。旧数字 tabId 不得用于关闭或覆盖操作者 Tab。

Browser 另在同一 FIFO/lane 内唯一拥有 `chatgptPageAccessNotBefore`：任意两个不属于同一 coherent 原子周期的 chatgpt.com 普通逻辑 DOM observation、Tab/page activation、navigation 或页面 mutation，其起始单调时间差至少1.5秒，且该门跨job、Tab、Product共享；进程或扩展重启后的第一次普通访问也先等待1.5秒。一次coherent observation内部的CDP primitives不拆分，菜单、菜单项、fill、Enter仍是不同逻辑访问；deadline剩余不足1.5秒时不再读取DOM，返回最后事实的typed timeout。50ms、25—250ms及亚1.5秒尾读路径必须物理退出；2.5秒动作读回、40秒提交静默、Browser每轮一次抽取的70—90秒全局Provider observation间隔与业务backoff取更长者。

同一个 `chatgpt-page-access-gate` 还唯一拥有 GPT DOM 瞬态失败确认的 typed stage；调用方只能提交 `stage=1|2`，不得提交裸毫秒、次数或 deadline，固定映射为1.5秒和3秒。每个 stage 完成后，GPT 必须在同一 exact call、Target、current Document及需要时同一current URL上重新读取整包 coherent observation；任何身份漂移立即失败，后续等待与读取增量为零。stage 本身只读且不取得物理输入；候选缺席、stale、`NO_LAYOUT_BOX`及无矛盾 partial topology可进入，候选多义、属性/内容/hash/URL/授权/effect mismatch不可进入。普通动作已经输入后，现役2.5秒闸门后的直接后置节点仍瞬态缺席时可使用同一两级只读确认，但不得重放动作；submit 5秒 actionability、附件/Provider业务等待、限流、Tab/导航/授权/WAL/recovery明确排除。

指针、fill、keypress 与已知限流确认的物理输入在 candidate-set 阶段以 `BROWSER_DOM_CANDIDATE_MISSING` 拒收时，Browser 同时给出唯一原生 cause：scope 原始数为 0 为 `BROWSER_DOM_SCOPE_ABSENT`，scope 原始数大于 0 而合格数为 0 为 `BROWSER_DOM_SCOPE_INELIGIBLE`，scope 唯一而目标原始数为 0 为 `BROWSER_DOM_SELECTOR_ABSENT`，目标原始数大于 0 而合格数为 0 为 `BROWSER_DOM_CANDIDATE_INELIGIBLE`。判定只读计数，由两个页内候选函数共用同一分类源文本；主 failure code、合格与文本判定、瞬态确认 stage 与 256 上限均不变。原生 cause 随 authenticated receipt 由现役 `markRejected` 写入唯一 WAL `native_cause_code`，runtime log 只以 `authorityRef` 指向该行，不复制计数或 selector。file-input 回执仍只允许 null。

观察型后置条件（同一 typed command 内以多个 query 组成的 postcondition observation）失配时，Browser 同样在 `markRejected` 写入路径给出唯一原生 cause：固定为 `BROWSER_POSTCONDITION_Q<i>__<C>`，`i` 为首个 `eligibleCount` 不等于 `expectedEligibleCount` 的 query 序号（0 起算，按现役 query 数量上限封闭），`<C>` 为该 query 按现役规则得到的原生原因（`BROWSER_DOM_CANDIDATE_AMBIGUOUS`、`BROWSER_DOM_CANDIDATE_MISSING` 或既有 ineligible reason 之一）。该机制与 candidate-set 阶段的既有原生 cause 是两个正交事实：前者发生在物理输入前的候选判定阶段，后者发生在物理输入后的后置校验阶段，互不覆盖、互不替代。node 侧从回执自带的 `postconditionObservation` 包重算同一个码并要求相等；未知序号或未知 `<C>` 一律失败关闭为现役 `BROWSER_AUTH_TRANSCRIPT_INVALID`，不得放宽为宽正则或建第二诊断链。单匹配型后置条件与 exact-outgoing 分支不受影响，继续使用现役首个拒绝原因。

每个既有ChatGPT逻辑访问在同一central site-policy preflight/coherent observation内机械取得`KnownGptRateLimitDialogFact`。只有唯一`role=dialog`、标题“请求过于频繁”、两段冻结正文、唯一启用且可交互按钮“明白了”、Target/Document不漂移时为`exact_present`；其余为`absent|mismatch`，只返回固定枚举、计数、冻结文案hash与identity，不返回DOM正文。命中时原请求物理输入为零。唯一Product不可见内部ack intent必须携刚取得的fact identity，并在当前已执行logical cycle结束后优先于所有已排队普通访问取得同一lane的下一周期；它不得抢占正在执行的CDP调用，也不得并发建立第二lane。该周期revalidate后点击一次；detection→dispatch可豁免1.5秒且受控SLO不超过1秒，恢复时仍沿用原始`observed_at+1s`截止点，随后仍等待2.5秒fresh absent readback。仅在同一当前authority epoch、live Target/Document和原lane内可零点击读回；跨进程旧Target/Document不得复活成ack或clearance资格；原ack可信CONFIRMED WAL terminal才可零输入读回并沿同incident交付confirmed_absent；新当前页面fresh absent只证明该页面当前状态，不能清算原事故；缺原terminal时交付not_cleared并维持门关闭；ack使用现役唯一WAL独立identity，DISPATCHED/unknown只读回，不盲点第二次。该例外不得扩展到任何其它动作或形成第二lane、timer、probe Child、selector/坐标通道。

固定扩展只在 exact job已获 Website grant且需要 Browser时懒创建一个 `active:true` 的 visible、system-owned、job-bound ChatGPT production Tab；一 job最多一个 Tab且一 Tab最多一个 job，不建空闲池，不跨 job复用。物理 Tab丢失时只为同一 job补建一个并同样 `active:true`。创建、补建、激活、mutation、observation、恢复与关闭全部经过同一 FIFO/lane，任意时刻 activeTarget与 operatorTargetClaim各至多一个。`chrome.tabs.update(tabId,{active:true})`只把精确 system Tab选为所在 Chrome窗口当前 Tab；随后必须重读并证明同一 tab/window、active、discarded、load、Target/current Document未漂移。不得调用 `windows.update({focused:true})`或 `Page.bringToFront`，不认领、关闭或改写任何操作者 Tab，不以硬点、盲重试、备用通道、第二 lane或第二 registry重新引入并发物理操作。

已鉴权 Browser Authority WebSocket 因真实 `peer_close|tcp_close|tcp_error` 以 `BROWSER_EXTENSION_CHANNEL_UNAVAILABLE` 终止时，Browser supervisor 是唯一触发点，只调用构造注入的现役宿主窗口恢复能力一次。宿主先读取 Chrome 窗口数：已有窗口必须零动作，零窗口才打开一个载入现役 Workbench URL 的 Chrome 窗口；该动作不聚焦既有窗口、不创建额外 Tab、不进入 Browser FIFO/lane、不读写 WAL、不取得 Target、不决定 attempt 或重放任务。未鉴权连接、认证失败、非 transport revoke、正常 supervisor stop 不得触发。宿主调用失败只记录 `BROWSER_HOST_UNAVAILABLE`，不得重试、排队、改变 WAL 或建立 watchdog、timer、manager、第二 WebSocket及第二恢复链；后续 Browser Authority 是否恢复只以固定扩展沿现役自动配对重新认证的事实为准。

旧 DISPATCHED submit 尚无可信 WAL URL/userTurnId 时，全局 lane 不因 confirmed-readback mode 字符串放行新 acquisition，也不从新 Target 同文案观察伪造原 command terminal；须等原 writer 可信终态。Browser 在任何新页面准备或 Provider 输入前，从原 WAL 枚举同一 job/revision/稳定业务调用的全部旧 attempt 和风险授权行；WAL 文件或历史不完整就是 UNKNOWN，不能当零输入。全历史可证零物理输入时，Website 普通新 attempt 可用当前 Product Prompt/hash 首次输入；曾可能输入时先沿原 effect 和 WAL 中唯一 canonical URL + exact userTurnId 零输入读回，不因当前 hash、attempt 或 Target 不同盲发。可信 locator 缺失则出具 typed unaddressable，不能扫描 Tab/标题或声称旧答案不存在。可信 locator 的有界 exact negative readback只证明答案不可机械取得。旧 `DISPATCHED` 未决时，Browser 在唯一 lane 保留 UNKNOWN 并阻断所有 job 新Provider输入及target-local click/fill/attach/submit；原 confirmed effect 的零Provider输入读回可以用当前Target按canonical URL精确选择，其中必要的Page.navigate只属于该readback，仍须在CDP发送前重验current permit/Target/Document/命令活性，不得借机进行其它job或新effect的页面动作；真实旧终态仍只来自原WAL。只有原 WAL 全部相关旧 command 真实 terminal、未决集合为空时，才能出具绑定原 WAL 来源集合的 input-quiescence 证明；新会话、空 handler、断线、Target 缺席或新 fence 均不能代替终态。Website 原 claim/event/receipt 持久签发指定调用 `delivery_priority_replay_grant` 后，Browser 仍逐命令重验 current Target/Document/permit/原 WAL，才允许新 effect 一次可能重复输入；响应丢失时只读回同一行。`target_local` 未决只约束局部动作安全，不终止 Website demand；Browser 不签 attempt/revision/风险授权，也不把 unknown 改写成 no。

风险 grant 首次 `prepare` 的原 WAL 行若在实际 dispatch 以前因进程中断成为 `FAILED + no + physical_input_count=0`，Browser 可在同一事务重绑该唯一行的 command/fence/Target/Document；前提是同 job、accepted attempt、result revision、业务调用、effect identity、grant、request 与 payload 均未变，且旧行无 proof、terminal、recovery payload 或可能输入。重绑不新增 grant 行，重新通过现役 Target/permit 校验后才可推进 DISPATCHED；任何旧 DISPATCHED、CONFIRMED、UNKNOWN 或身份漂移都只允许原 effect 读回。

风险 grant 的上一 command 已经精确终局为 `REJECTED + mutation_outcome=no + physical_input_count=0` 时，旧 terminal/proof 保持不可变；Browser 仅在同一 grant 的全部旧 WAL command 均已可信证明零 Provider 输入、无未决、且同 job/attempt/revision/调用/effect/grant/request/payload 完全不变时，才可于原 WAL 写下一 command 并重新校验当前 permit/Target。任一 DISPATCHED 未决、CONFIRMED、REJECTED dispatched/confirmed 或身份漂移都只许零输入对账。grant 限制的是现实 Provider 输入总次数至多一次，不能以零输入的终局行制造隐藏停机。

永久删除只以 Website 对同一 exact job 返回权威不存在为授权，Runtime 才可签发 `website-admin-deletion`；Browser 在停写并确认 Website 对 exact job 返回权威不存在后，只对当前 live registry 中确属该 job 的 system Target 做可验证关闭；没有当前 live Target 视为资源已缺席，不扫描历史 tabId。随后原 Browser Owner 按同一 jobId 清除 WAL 并读回缺席。该整 job 撤权清除可包含未知 `DISPATCHED` 行，但不得把它结算为 terminal 或据此为其它 job、attempt 或 effect 签发输入资格；普通恢复与新输入仍要求原 WAL 相关旧 command 真实 terminal、未决集合为空。`PRIVACY_SUBJECT_CLOSED`、`business-admitted`、普通 `wait-new-attempt` 和其它 job 的普通 release 不取得永久删除资格；不得把未知 effect 改写为 `mutation_outcome=no`。新 attempt 不先释放或恢复历史 Target；它在 Runtime durable accept 后通过第一次 current production acquisition 进入唯一 lane，未决旧 `target_local` 仍须按原 WAL 和 terminal-only input-quiescence 门收束后才能产生新物理输入。

现役 GPT 轮次机械定位以所选 UUID 在当前页唯一对应的 `data-turn-key` 外层及有效 `fallback-turn-N` 顺序为准。提交后置选最大有效序号且不得有重复最大序号，核同外层唯一 `:user` 单元、匹配 UUID 的 message ids、唯一用户气泡内 Prompt hash；CONFIRMED WAL 只持久该 UUID 与同包 canonical URL。文本回答观察按同 UUID 外层的用户单元与真实紧邻唯一 `:assistant` 单元定位，其 message id 与正文节点必须精确绑定；文本 stop 与正文仍按原两门合同。图片只按 canonical URL、精确 userTurnId 后至下一个用户轮次前的范围读取 source，不等待 assistant role。旧 `conversation-turn-*` DOM 选择器和正则物理退出；旧 WAL 事实不删，无法以现役 DOM 定位的旧 effect 保持原输入事实并走现役 unaddressable/风险授权。

`FROZEN-GPT-RESPONSE-NO-PROMPT-REHASH-001` 的 Browser 部分固定：回答读取只用 canonical conversation URL 和 submit 已确认的精确 `userTurnId` 定位其真实紧邻 assistant turn，并把当前 Target/Document、observation revision、回答内容 hash 或媒体 bytes hash 绑定到一次原子 observation。Browser 不得在回答 checkpoint 再读取、解析或 hash 历史 user prompt，不得返回 `precedingPromptHash`，也不得把 Provider 的折叠、展开、截断或重新渲染状态变成回答准入条件。删除或替代本边界必须由用户明确解冻，并同步替换 GPT/Browser 施工图、实现与唯一质检；普通修复或 CI 授权不构成解冻。

`FROZEN-GPT-TEXT-RESPONSE-TWO-GATES-001` 的 Browser 部分固定：exact text response 读取只为 GPT 的两门合同提供同一原子 observation。Browser 只机械证明 confirmed canonical conversation URL、exact `userTurnId`、其真实紧邻且唯一的 assistant-role turn、Target/current Document/main-frame loader 与 observation revision，并在同包返回 stop button 状态、完整 DOM 与 deterministic semantic text；stop 存在不得清空已精确定位的 DOM/semantic text。构造 semantic text 时只允许对 user-role Prompt 投影把 U+00A0 逐字符映射为 U+0020，以消除 Provider 对普通空格的展示替换；assistant-role 内容必须逐字符保留。禁止 trim、NFKC、正则空白折叠、其它 Unicode 空白映射或把该规则扩展到 assistant；批准文本本身含 U+00A0 时不做反向或对称改写，不等即失败关闭。Browser 不得把页面末位、Composer/submit 数量、layout/visible/viewport/hit-test、hidden/aria-hidden/inert、Prompt rehash、固定 turn 编号/奇偶、标题、侧栏、时间、动画、展开状态或其它 UI 外壳变成候选存在、内容返回或 GPT 结算的第三门禁，也不得用 boolean、helper、hash、identity、candidate cardinality 或 eligibility 包装后重新阻断。协议真实性、authority、Document/revision 与 reply shape 继续失败关闭，但不得重解释回答语义。只有授权人明确原文“解冻 FROZEN-GPT-TEXT-RESPONSE-TWO-GATES-001”并同步替换现役法案、GPT/Browser 施工图、实现与唯一质检才允许改变；普通修复、Provider UI 变化、CI 或单仓代码授权均不构成解冻。

exact text response 的暂未取得结果只能把两类Browser机械事实分开报告：exact user turn 当前不可取得，或该user turn的真实紧邻assistant turn当前不存在。两者都保持现役非mutation observation/pending语义，不得改变两门裁决、增加门禁或扩大为其它DOM路径；assistant多义、URL/Document/revision/authority失真继续按现役失败关闭。该诊断只用精确typed error穿过现役单链，不进入成功`BrowserExactAssistantTurnReplyV3`、WAL、receipt、数据库或Runtime日志字段，也不得保留文本路径对通用candidate-missing的兼容fallback。

`FROZEN-GPT-IMAGE-SOURCE-EVENT-WAIT-001` 的 Browser 部分已按本次授权解冻替换并重新冻结：authenticated-media 读取先在 canonical conversation URL 与精确 `userTurnId` 之后、下一个 user turn 之前的范围内直接检查非空 `currentSrc/src`；尚未出现时，只能在同一次加密 command 的调用期 observation 内安装一个 `MutationObserver`，仅监听节点加入及 `src/srcset` 变化，单次最多等待 5000ms，source 出现即在同一次已登录页面调用中 fetch 原始 bytes 并按内容 hash 去重。单次期满仍无 source返回 typed pending并释放 lease/lane；下一次 observation立即进入唯一 FIFO，由 BrowserLaneCoordinator在请求资格与全局节拍满足后激活该 job精确绑定 Tab并 fresh observe，正常轮询不得导航。调用期 observer与 timeout必须结算即销毁，总期限只由 GPT Child现有 `probeBudgetMs`决定；不得形成 per-job timer、第二 timer Owner、持久状态或调度器。

`FROZEN-GPT-SUBMIT-TWO-PRECONDITIONS-001` 的 Browser 部分固定：真正 submit 前除 Product 已批准的“提示词 hash + 精确附件集合”和 Browser 自有的“current Target/Document/fence + 同 effect 尚未现实输入”外，不得再增加任何发送资格。批准附件集合允许为空。历史 user turn、固定 turn 编号或奇偶、按钮标签均不是发送前置条件，点击前不得读取历史 turn 决定发送资格；精确 submit 的同一 Browser command 在 `mouseReleased` 后立即发出一次无点击、无业务输入计数的固定中性 `mouseMoved(0,0)`，随后才开始 2500ms 闸门并从 fresh current Document 选取最大有效序号的 user turn，核对批准 prompt hash 与 Composer 已清空。撤离失败发生在 submit 可能已经输入之后，必须保留 `DISPATCHED` 并只允许同 effect 零 submit 读回；普通点击、模型、推理强度、附件、限流弹窗和恢复读回不得执行该撤离，也不得为此增加 DOM 读取、Tab 激活、导航、timer、WAL 或重试。按钮唯一、可见、可交互与 hit-test 仍是 Browser 执行物理点击的内部机械安全，不得上升为 GPT/Product 业务关卡。
