Browser 只拥有现实页面资源：已获 grant且未闭环 job与 system Target的一对一进程内绑定、实时 current Document、一条 FIFO、一条物理 lane、一个全局 Provider observation节拍、Provider/控件 mutation的唯一 WAL，以及页面生命周期动作后的 fresh readback。它不理解 Product步骤、不保存 GPT回答、不决定 retry或当前 N，也不拥有 Website task。

固定扩展只在 exact job已获 Website grant且需要 Browser时懒创建一个 `active:true` 的 visible、system-owned、job-bound ChatGPT production Tab；一 job最多一个 Tab且一 Tab最多一个 job，不建空闲池，不跨 job复用。物理 Tab丢失时只为同一 job补建一个并同样 `active:true`。创建、补建、激活、mutation、observation、恢复与关闭全部经过同一 FIFO/lane，任意时刻 activeTarget与 operatorTargetClaim各至多一个。`chrome.tabs.update(tabId,{active:true})`只把精确 system Tab选为所在 Chrome窗口当前 Tab；随后必须重读并证明同一 tab/window、active、discarded、load、Target/current Document未漂移。不得调用 `windows.update({focused:true})`或 `Page.bringToFront`，不认领、关闭或改写任何操作者 Tab，不以硬点、盲重试、备用通道、第二 lane或第二 registry重新引入并发物理操作。

全局存在任一 unresolved `DISPATCHED` 时，FIFO 对 acquire 和普通 release 一律失败关闭。只有新鲜 Website 读回已持久裁定同一 exact job 为 `PRIVACY_SUBJECT_CLOSED`，或 Website 对该 job 返回权威不存在，才可分别签发 `website-permanent-revocation` 或 `website-admin-deletion`；lane 还必须从唯一 Browser WAL 现场证明该同一 jobId 确有 `DISPATCHED`，并在 active claim 已零输入 park 后，允许这一个 release 经唯一 FIFO、预授权 WebSocket 与 exact jobRefHash ack 删除其 system Tab。`business-admitted`、普通 `wait-new-attempt`、`attempt-replaced`、其他 job 的永久裁定及全部 acquisition 都不得穿过该例外；WAL/effect fact必须保留。

`FROZEN-GPT-RESPONSE-NO-PROMPT-REHASH-001` 的 Browser 部分固定：回答读取只用 canonical conversation URL 和 submit 已确认的精确 `userTurnId` 定位其真实紧邻 assistant turn，并把当前 Target/Document、observation revision、回答内容 hash 或媒体 bytes hash 绑定到一次原子 observation。Browser 不得在回答 checkpoint 再读取、解析或 hash 历史 user prompt，不得返回 `precedingPromptHash`，也不得把 Provider 的折叠、展开、截断或重新渲染状态变成回答准入条件。删除或替代本边界必须由用户明确解冻，并同步替换 GPT/Browser 施工图、实现与唯一质检；普通修复或 CI 授权不构成解冻。

`FROZEN-GPT-IMAGE-SOURCE-EVENT-WAIT-001` 的 Browser 部分已按本次授权解冻替换并重新冻结：authenticated-media 读取先在 canonical conversation URL 与精确 `userTurnId` 之后、下一个 user turn 之前的范围内直接检查非空 `currentSrc/src`；尚未出现时，只能在同一次加密 command 的调用期 observation 内安装一个 `MutationObserver`，仅监听节点加入及 `src/srcset` 变化，单次最多等待 5000ms，source 出现即在同一次已登录页面调用中 fetch 原始 bytes 并按内容 hash 去重。单次期满仍无 source返回 typed pending并释放 lease/lane；下一次 observation立即进入唯一 FIFO，由 BrowserLaneCoordinator在请求资格与全局节拍满足后激活该 job精确绑定 Tab并 fresh observe，正常轮询不得导航。调用期 observer与 timeout必须结算即销毁，总期限只由 GPT Child现有 `probeBudgetMs`决定；不得形成 per-job timer、第二 timer Owner、持久状态或调度器。

`FROZEN-GPT-SUBMIT-TWO-PRECONDITIONS-001` 的 Browser 部分固定：真正 submit 前除 Product 已批准的“提示词 hash + 精确附件集合”和 Browser 自有的“current Target/Document/fence + 同 effect 尚未现实输入”外，不得再增加任何发送资格。批准附件集合允许为空。历史 user turn、固定 turn 编号或奇偶、按钮标签均不是发送前置条件，点击前不得读取历史 turn 决定发送资格；点击后等待 2500ms，只从 fresh current Document 选取最大有效序号的 user turn，核对批准 prompt hash 与 Composer 已清空。按钮唯一、可见、可交互与 hit-test 仍是 Browser 执行物理点击的内部机械安全，不得上升为 GPT/Product 业务关卡。

`FROZEN-GPT-SUBMIT-ACTIONABILITY-WAIT-001` 的 Browser 部分固定：精确待发送内容和 WAL/current Document 已通过后，精确发送按钮暂时 `disabled/aria-disabled` 时，在同一原子 command 的现有 5000ms 有界期限内重复 fresh mechanical qualification，恢复后至多输入一次；期限耗尽仍返回原生 disabled typed receipt、mutation=no、physical input=0。不得建立第三业务前置条件、持久 timer、第二 WAL、队列或重试器。

`FROZEN-GPT-MODEL-SELECTOR-SEMANTIC-MINIMUM-001` 的 Browser 部分固定：模型选择准备只机械观察精确批准模型选项，或点击唯一“选择模型”入口后等待该选项出现；随后只点击该唯一选项，并在同次 mutation 中直接读取保留的被点击节点 `aria-checked=true`，再确认该精确选项退出当前可选集合。Browser/GPT 不检查 popup、simple/advanced panel、旧面板形态、`data-active`、`inert` 或其它 UI 外壳拓扑。入口与选项自身的唯一性、可操作性以及被点击选项自身的 `aria-checked` 是 Browser 物理动作和直接后置证明，不属于被禁止的外壳拓扑，也不得扩展成新的菜单结构考试。

`document` 是 Target 当前状态的 live view。导航、刷新或 Target 交接后，所有合法消费者必须读到新的 Document；任何包装层不得用对象展开、缓存或复制把它冻结成旧 Document。

Browser mutation 的唯一规则不变：先写 WAL，再至多 dispatch 一次，最后一次输入后等待 2500ms，从 fresh current Document 做直接后置读回。GPT 只有真正提交属于 provider-effect scope；fresh/profile/model/menu/附件/Composer 等准备属于 target-local scope，身份包含 attempt 与当前 Target/Document generation，旧 attempt 不得阻断新 attempt 重建准备。provider_effect_identity 精确为 `job_id + result_revision + product_step_id + call_id + child_id + request_hash + payload_hash`，不含 Product Plugin名称/版本/Skill hash、attempt/process/lease/fence/Target/Document；同一 effect跨进程物理 dispatch总数至多一。WAL为 CONFIRMED submit加密保存同包清洗的 canonical conversation URL与精确 userTurnId；URL只负责“去哪里读”，effect identity只负责“是否已经发送”。confirmed readback先查询 WAL，再经唯一 lane为该 job取得精确 system Target；当前 URL命中时零导航，否则只执行一次 Browser-owned `Page.navigate`到该 URL，2500ms后 fresh readback必须相等。侧栏点击、标题/顺序/时间猜测、搜索、滚动、自动展开、重试与 fallback均不参与。该导航不写第二 WAL、不取得 provider effect identity。纯 observation和结果读取不建立第二 WAL、lane、timer或队列。

`FROZEN-GPT-ATTACHMENT-PROVIDER-DUPLICATE-SUFFIX-001` 的 Browser 部分固定：Product 批准附件集合是唯一语义权威并允许为空；Browser 只在同一个点击原子动作内机械执行 GPT 冻结语义。每个 Provider 可见名称先做 NFC 后让精确批准名称优先；只有精确未命中时，才允许删除最后扩展名前、无扩展名则文件名末尾恰好一个无空格 `(<纯十进制数字>)`，且删除后必须精确命中批准名称，才视为同一附件。附件数量、基础名、扩展名、非数字括号、空格括号和其它改名仍失败关闭。禁止恢复原始展示名硬比对而误杀重试，禁止 substring、模糊匹配、宽正则、第二附件身份或兼容分支；现役 Browser inspector 与真实注入函数正反验收必须共同失败关闭。改变、删除、改名、弱化、扩张或绕过本边界，只有用户明确原文“解冻 FROZEN-GPT-ATTACHMENT-PROVIDER-DUPLICATE-SUFFIX-001”并同步替换现役法案、GPT/Browser 施工图、实现与唯一质检后才允许；普通修复、代码迭代、CI 授权、Provider UI 变化或单仓变更均不构成解冻。

已确认提交、回答尚未出现时，正常轮询保留 job—Target绑定但 pending释放 FIFO lease与物理 lane。GPT Child只计算最早资格时间并立即提交 observation waiter；BrowserLaneCoordinator以 waiter `eligibleAt`、全局 `observationNotBefore`和一个 wake timer作为唯一计时 Owner，相邻真实 Provider observation至少 60秒且总频率不随 N增长。具备资格后只激活精确绑定 Tab、重验 Target/current Document并 fresh observe一次，pending再次释放，正常轮询 Page.navigate=0。只有进程重启、绑定 Target真正丢失或同等恢复现场，Website再次授权同一 accepted attempt后，Browser才按同一 provider_effect_identity从唯一 WAL读回 canonical URL与userTurnId，以 `confirmed-readback`为该 job取得精确 system Target，再按该 URL零次或一次精确导航后 fresh observation；不得跨业务任务使用该 URL，不得再次写 Prompt、附件或提交。该恢复路径 physical submit delta=0，不建立 park object、第二状态、逐任务时钟或第二调度。

`FROZEN-EXACT-TARGET-POLL-RESULT-REVISION-001` 的 Browser 部分已按本次授权精准解冻替换并重新冻结：正常 Provider回答轮询保留 exact job—system Target独占绑定，40秒静默门后 observation waiter立即进入唯一 FIFO，由 BrowserLaneCoordinator唯一计时；请求具备资格后只取得并激活精确绑定 Tab、重验实时 current Document、fresh observe一次，pending释放 lease/lane并重新排队。正常轮询不得读取 canonical locator或执行 Page.navigate。只有进程重启、绑定 Target真正丢失或同等恢复现场，才从同一 WAL effect取得 canonical URL与 userTurnId，再以 `confirmed-readback`为该 job取得精确 system Target；不得执行固定 GPT start URL/首页导航，不按旧新 targetRef或扫描旧标签猜选，同 URL零导航，不同 URL最多一次精确 Browser-owned `Page.navigate`，2500ms后 fresh readback不等即 typed fail-close。Browser WAL的 `logical_mutation_id`仍是唯一公开 `provider_effect_identity_hash`，不得复制列、台账或第二 store。

任一 typed 失败、进程重启、lease/fence/abort 失效或提交结果不明时，Browser 只返回 terminal/effect fact。`REJECTED + mutation_outcome=no + physical_input_count=0` 不消耗 provider effect，Website 签发新 attempt 后可在唯一 WAL 中保留原审计行并重新准备同一 effect；DISPATCHED、CONFIRMED 或任何已发生/不明现实输入不得重做，只可按 Website 新授权读取同一结果。Browser 不选择 consultation root，不保存或恢复跨任务 Provider conversation，也不得按当前页面或 latest URL 猜测。

验收必须通过真实调用证明：N=1..4 时每个未闭环 job至多一个独占 system Tab，任意时刻 active claim与 Browser物理动作至多一个；所有创建、激活、输入、observation、恢复和关闭只走唯一 FIFO/lane，相邻 Provider observation至少 60秒且频率不随 N增长；正常轮询 `Page.navigate=0`，输出 receipt绑定当前授权与跨 attempt稳定的 effect identity；CONFIRMED后进程重启仍零 submit，Browser WAL中 job—Tab绑定、跨任务 consultation identity、source task、checkpoint与 frontier均为零。
