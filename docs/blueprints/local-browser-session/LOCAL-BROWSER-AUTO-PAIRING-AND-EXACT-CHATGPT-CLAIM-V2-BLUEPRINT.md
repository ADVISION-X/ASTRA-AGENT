活动 job—Target 执行绑定只在当前 Browser Authority live registry。Target/Document/epoch/fence/permit只决定当前物理位置，原WAL target_ref/document_ref仅历史取证；持久Target claim/旧Tab恢复registry为零。历史DISPATCHED不参与跨job acquisition/lane/prepare资格；当前操作只取唯一FIFO/lane、有效permit与每次native前的真实guard，真实仍在途native不并行。旧终态只能原事实CAS，未知不伪成零输入，旧tabId不得猜删操作者Tab。

Browser 另在同一 FIFO/lane 内唯一拥有 `chatgptPageAccessNotBefore`：任意两个不属于同一 coherent 原子周期的 chatgpt.com 普通逻辑 DOM observation、Tab/page activation、navigation 或页面 mutation，其起始单调时间差至少1.5秒，且该门跨job、Tab、Product共享；进程或扩展重启后的第一次普通访问也先等待1.5秒。一次coherent observation内部的CDP primitives不拆分，菜单、菜单项、fill、Enter仍是不同逻辑访问；deadline剩余不足1.5秒时不再读取DOM，返回最后事实的typed timeout。50ms、25—250ms及亚1.5秒尾读路径必须物理退出；2.5秒动作读回、40秒提交静默、本请求至少70秒资格与业务backoff取更长者。

同一个 `chatgpt-page-access-gate` 还唯一拥有 GPT DOM 瞬态失败确认的 typed stage；调用方只能提交 `stage=1|2`，不得提交裸毫秒、次数或 deadline，固定映射为1.5秒和3秒。每个 stage 完成后，GPT 必须在同一 exact call、Target、current Document及需要时同一current URL上重新读取整包 coherent observation；任何身份漂移立即失败，后续等待与读取增量为零。stage 本身只读且不取得物理输入；候选缺席、stale、`NO_LAYOUT_BOX`及无矛盾 partial topology可进入，候选多义、属性/内容/hash/URL/授权/effect mismatch不可进入。普通动作已经输入后，现役2.5秒闸门后的直接后置节点仍瞬态缺席时可使用同一两级只读确认，但不得重放动作；submit 5秒 actionability、附件/Provider业务等待、限流、Tab/导航/授权/WAL/recovery明确排除。

指针、fill、keypress 与已知限流确认的物理输入在 candidate-set 阶段以 `BROWSER_DOM_CANDIDATE_MISSING` 拒收时，Browser 同时给出唯一原生 cause：scope 原始数为 0 为 `BROWSER_DOM_SCOPE_ABSENT`，scope 原始数大于 0 而合格数为 0 为 `BROWSER_DOM_SCOPE_INELIGIBLE`，scope 唯一而目标原始数为 0 为 `BROWSER_DOM_SELECTOR_ABSENT`，目标原始数大于 0 而合格数为 0 为 `BROWSER_DOM_CANDIDATE_INELIGIBLE`。判定只读计数，由两个页内候选函数共用同一分类源文本；主 failure code、合格与文本判定、瞬态确认 stage 与 256 上限均不变。原生 cause 随 authenticated receipt 由现役 `settleTerminalReceipt` 写入唯一 WAL `native_cause_code`，runtime log 只以 `authorityRef` 指向该行，不复制计数或 selector。file-input 回执仍只允许 null。

观察型后置条件由现役 browser-observation-receipt Owner 对同一 coherent 包作唯一机械决定，Extension 生产与 Node 验证共同调用。packet/header/hash/Target/Document/currentUrl 结构先严格验真；URL 清洗同 Owner 唯一承载，合法首页或单一有界 opaque conversation segment 不冒充 canonical locator，query/fragment 在页内物理去除，非法 URL 仍失败关闭。query 失配一律取首个 eligibleCount 不等于 expectedEligibleCount 的 query，原因固定 BROWSER_POSTCONDITION_Q<i>__<C>（现役 Q0..19 与原生原因闭集）；exact-outgoing 不豁免。全部 query 合格后，批准 hash 一致即完成 exact 新消息证明；合法首页或临时 opaque URL 不否决发送。正式URL仅在后续独立定位要求中检查，真实输入计数/unknown/原WAL与ACK保持。单匹配后置继续原首因；不新增 submit 前置门、第二判定或诊断链。

每个既有ChatGPT逻辑访问在同一central site-policy preflight/coherent observation内机械取得`KnownGptRateLimitDialogFact`。只有唯一`role=dialog`、标题“请求过于频繁”、两段冻结正文、唯一启用且可交互按钮“明白了”、Target/Document不漂移时为`exact_present`；其余为`absent|mismatch`，只返回固定枚举、计数、冻结文案hash与identity，不返回DOM正文。命中时原请求物理输入为零。唯一Product不可见内部ack intent必须携刚取得的fact identity，并在当前已执行logical cycle结束后优先于所有已排队普通访问取得同一lane的下一周期；它不得抢占正在执行的CDP调用，也不得并发建立第二lane。该周期revalidate后点击一次；detection→dispatch可豁免1.5秒且受控SLO不超过1秒，恢复时仍沿用原始`observed_at+1s`截止点，随后仍等待2.5秒fresh absent readback。仅在同一当前authority epoch、live Target/Document和原lane内可零点击读回；跨进程旧Target/Document不得复活成ack或clearance资格；原ack可信CONFIRMED WAL terminal才可零输入读回并沿同incident交付confirmed_absent；新当前页面fresh absent只证明该页面当前状态，不能清算原事故；缺原terminal如实交付not_cleared，历史clearance不作当前永久门，当前危险输入仍须Website当前资格与中央fresh preflight，新incident先精确落账；ack使用现役唯一WAL独立identity，DISPATCHED/unknown只读回，不盲点第二次。该例外不得扩展到任何其它动作或形成第二lane、timer、probe Child、selector/坐标通道。

固定扩展只在 exact job已获 Website grant且需要 Browser时懒创建一个 `active:true` 的 visible、system-owned、job-bound ChatGPT production Tab；一 job最多一个 Tab且一 Tab最多一个 job，不建空闲池，不跨 job复用。物理 Tab丢失时只为同一 job补建一个并同样 `active:true`。创建、补建、激活、mutation、observation、恢复与关闭全部经过同一 FIFO/lane，任意时刻 activeTarget与 operatorTargetClaim各至多一个。`chrome.tabs.update(tabId,{active:true})`只把精确 system Tab选为所在 Chrome窗口当前 Tab；随后必须重读并证明同一 tab/window、active、discarded、load、Target/current Document未漂移。不得调用 `windows.update({focused:true})`或 `Page.bringToFront`，不认领、关闭或改写任何操作者 Tab，不以硬点、盲重试、备用通道、第二 lane或第二 registry重新引入并发物理操作。

已鉴权 Browser Authority WebSocket 因真实 `peer_close|tcp_close|tcp_error` 以 `BROWSER_EXTENSION_CHANNEL_UNAVAILABLE` 终止时，Browser supervisor 是唯一触发点，只调用构造注入的现役宿主窗口恢复能力一次。宿主先读取 Chrome 窗口数：已有窗口必须零动作，零窗口才打开一个载入现役 Workbench URL 的 Chrome 窗口；该动作不聚焦既有窗口、不创建额外 Tab、不进入 Browser FIFO/lane、不读写 WAL、不取得 Target、不决定 attempt 或重放任务。未鉴权连接、认证失败、非 transport revoke、正常 supervisor stop 不得触发。宿主调用失败只记录 `BROWSER_HOST_UNAVAILABLE`，不得重试、排队、改变 WAL 或建立 watchdog、timer、manager、第二 WebSocket及第二恢复链；后续 Browser Authority 是否恢复只以固定扩展沿现役自动配对重新认证的事实为准。

Browser在每次Product页面准备前沿稳定业务调用键核完整WAL effect历史；全历史可信零输入才普通首次输入，已输入/未知的同一effect不重发。原答案先由原canonical URL及文本turnMarker或图片userTurnId有界exact读回；无可信locator只出typed unaddressable，不能扫描历史Tab或声称答案不存在。读回耗尽或unaddressable与完整source seal交Website唯一Owner，持久签指定调用的新revision风险grant后仅新effect可一次输入。历史DISPATCHED原样保留但不阻断兄弟job/新effect；input_quiescence_proof仅原真实terminal_wal完整成立才附带，否则required字段为null，unknown/possible允许null且绝不当zero。当前lane/permit/每次native guard仍严格串行，无新恢复writer或静止证明生产者。

风险 grant 首次 `prepare` 的原 WAL 行若在实际 dispatch 以前因进程中断成为 `FAILED + no + physical_input_count=0`，Browser 可在同一事务重绑该唯一行的 command/fence/Target/Document；前提是同 job、accepted attempt、result revision、业务调用、effect identity、grant、request 与 payload 均未变，且旧行无 proof、terminal、recovery payload 或可能输入。重绑不新增 grant 行，重新通过现役 Target/permit 校验后才可推进 DISPATCHED；任何旧 DISPATCHED、CONFIRMED、UNKNOWN 或身份漂移都只允许原 effect 读回。

风险 grant 的上一 command 已经精确终局为 `REJECTED + mutation_outcome=no + physical_input_count=0` 时，旧 terminal/proof 保持不可变；Browser 仅在同一 grant 的全部旧 WAL command 均已可信证明零 Provider 输入、无未决、且同 job/attempt/revision/调用/effect/grant/request/payload 完全不变时，才可于原 WAL 写下一 command 并重新校验当前 permit/Target。任一 DISPATCHED 未决、CONFIRMED、REJECTED dispatched/confirmed 或身份漂移都只许零输入对账。grant 限制的是现实 Provider 输入总次数至多一次，不能以零输入的终局行制造隐藏停机。
