Browser 只拥有现实页面资源：已获 grant且未闭环 job与 system Target的一对一进程内绑定、实时 current Document、一条 FIFO、一条物理 lane、一个全局 Provider observation节拍、Provider/控件 mutation的唯一 WAL，以及页面生命周期动作后的 fresh readback。它不理解 Product步骤、不保存 GPT回答、不决定 retry或当前 N，也不拥有 Website task。

Browser 另在同一 FIFO/lane 内唯一拥有 `chatgptPageAccessNotBefore`：任意两个不属于同一 coherent 原子周期的 chatgpt.com 普通逻辑 DOM observation、Tab/page activation、navigation 或页面 mutation，其起始单调时间差至少1.5秒，且该门跨job、Tab、Product共享；进程或扩展重启后的第一次普通访问也先等待1.5秒。一次coherent observation内部的CDP primitives不拆分，菜单、菜单项、fill、Enter仍是不同逻辑访问；deadline剩余不足1.5秒时不再读取DOM，返回最后事实的typed timeout。50ms、25—250ms及亚1.5秒尾读路径必须物理退出；2.5秒动作读回、40秒提交静默、Browser每轮一次抽取的70—90秒全局Provider observation间隔与业务backoff取更长者。

同一个 `chatgpt-page-access-gate` 还唯一拥有 GPT DOM 瞬态失败确认的 typed stage；调用方只能提交 `stage=1|2`，不得提交裸毫秒、次数或 deadline，固定映射为1.5秒和3秒。每个 stage 完成后，GPT 必须在同一 exact call、Target、current Document及需要时同一current URL上重新读取整包 coherent observation；任何身份漂移立即失败，后续等待与读取增量为零。stage 本身只读且不取得物理输入；候选缺席、stale、`NO_LAYOUT_BOX`及无矛盾 partial topology可进入，候选多义、属性/内容/hash/URL/授权/effect mismatch不可进入。普通动作已经输入后，现役2.5秒闸门后的直接后置节点仍瞬态缺席时可使用同一两级只读确认，但不得重放动作；submit 5秒 actionability、rename 10秒协议、附件/Provider业务等待、限流、Tab/导航/授权/WAL/recovery明确排除。

每个既有ChatGPT逻辑访问在同一central site-policy preflight/coherent observation内机械取得`KnownGptRateLimitDialogFact`。只有唯一`role=dialog`、标题“请求过于频繁”、两段冻结正文、唯一启用且可交互按钮“明白了”、Target/Document不漂移时为`exact_present`；其余为`absent|mismatch`，只返回固定枚举、计数、冻结文案hash与identity，不返回DOM正文。命中时原请求物理输入为零。唯一Product不可见内部ack intent必须携刚取得的fact identity，并在当前已执行logical cycle结束后优先于所有已排队普通访问取得同一lane的下一周期；它不得抢占正在执行的CDP调用，也不得并发建立第二lane。该周期revalidate后点击一次；detection→dispatch可豁免1.5秒且受控SLO不超过1秒，恢复时仍沿用原始`observed_at+1s`截止点，随后仍等待2.5秒fresh absent readback。若恢复时同Target/Document精确重验成立且dialog已不存在，则以零点击、零mutation的absent receipt闭合同一事故；ack使用现役唯一WAL独立identity，DISPATCHED/unknown只读回，不盲点第二次。该例外不得扩展到任何其它动作或形成第二lane、timer、probe Child、selector/坐标通道。

固定扩展只在 exact job已获 Website grant且需要 Browser时懒创建一个 `active:true` 的 visible、system-owned、job-bound ChatGPT production Tab；一 job最多一个 Tab且一 Tab最多一个 job，不建空闲池，不跨 job复用。物理 Tab丢失时只为同一 job补建一个并同样 `active:true`。创建、补建、激活、mutation、observation、恢复与关闭全部经过同一 FIFO/lane，任意时刻 activeTarget与 operatorTargetClaim各至多一个。`chrome.tabs.update(tabId,{active:true})`只把精确 system Tab选为所在 Chrome窗口当前 Tab；随后必须重读并证明同一 tab/window、active、discarded、load、Target/current Document未漂移。不得调用 `windows.update({focused:true})`或 `Page.bringToFront`，不认领、关闭或改写任何操作者 Tab，不以硬点、盲重试、备用通道、第二 lane或第二 registry重新引入并发物理操作。

全局存在 unresolved `DISPATCHED` 时，其他 job 的 acquisition 与普通 release 一律失败关闭；同一 job 也只能在 Website 当前生产授权已 fresh readback、AGENT 已 durable accept且唯一 FIFO/lane现场证明身份完全一致时进入收尾。`provider_effect` 只允许零输入 postcondition/readback：fresh DOM 精确证明已发生时，由同一 Child 调用现役 Browser resolver 把原 WAL 行原位结算为 `CONFIRMED + mutation_outcome=confirmed`，再读回终态 authority hash并继续读取原结果；已证明未发生则返回 `mutation_outcome=no` 交由 Website 决定以后是否签发新 attempt；无法证明则返回 `PROVIDER_EFFECT_OUTCOME_UNPROVEN` 并保持原行 `DISPATCHED`、保留原 accepted attempt。任何新进程、Tab、fence或attempt都不得重发。`target_local` 只有旧 execution fence 已失效、当前 fence 不同且全局恰有这一条同 job unresolved target-local时，才可在任何新 acquisition 前把旧 WAL 行原位终结为 `REJECTED + mutation_outcome=dispatched`，保留原 `physical_input_count` 与完整 WAL事实，再对当前 Target/Document执行fresh typed precondition；多条、混合scope、同fence、非生产binding或身份漂移全部失败关闭。Browser不得据此签发新attempt或result revision，也不得把unknown改写成no。

永久删除仍只有新鲜 Website 读回已持久裁定同一 exact job 为 `PRIVACY_SUBJECT_CLOSED`，或 Website 对该 job 返回权威不存在，才可分别签发 `website-permanent-revocation` 或 `website-admin-deletion`；lane 还必须从唯一 Browser WAL 现场证明该同一 jobId 确有 `DISPATCHED`，并在 active claim 已零输入 park 后，允许这一个 release 经唯一 FIFO、预授权 WebSocket 与 exact jobRefHash ack 删除其 system Tab。`business-admitted`、普通 `wait-new-attempt`、`attempt-replaced`和其他 job 的永久裁定都不得穿过该例外；WAL/effect fact必须保留。

`FROZEN-GPT-RESPONSE-NO-PROMPT-REHASH-001` 的 Browser 部分固定：回答读取只用 canonical conversation URL 和 submit 已确认的精确 `userTurnId` 定位其真实紧邻 assistant turn，并把当前 Target/Document、observation revision、回答内容 hash 或媒体 bytes hash 绑定到一次原子 observation。Browser 不得在回答 checkpoint 再读取、解析或 hash 历史 user prompt，不得返回 `precedingPromptHash`，也不得把 Provider 的折叠、展开、截断或重新渲染状态变成回答准入条件。删除或替代本边界必须由用户明确解冻，并同步替换 GPT/Browser 施工图、实现与唯一质检；普通修复或 CI 授权不构成解冻。

`FROZEN-GPT-TEXT-RESPONSE-TWO-GATES-001` 的 Browser 部分固定：exact text response 读取只为 GPT 的两门合同提供同一原子 observation。Browser 只机械证明 confirmed canonical conversation URL、exact `userTurnId`、其真实紧邻且唯一的 assistant-role turn、Target/current Document/main-frame loader 与 observation revision，并在同包返回 stop button 状态、完整 DOM 与 deterministic semantic text；stop 存在不得清空已精确定位的 DOM/semantic text。Browser 不得把页面末位、Composer/submit 数量、layout/visible/viewport/hit-test、hidden/aria-hidden/inert、Prompt rehash、固定 turn 编号/奇偶、标题、侧栏、时间、动画、展开状态或其它 UI 外壳变成候选存在、内容返回或 GPT 结算的第三门禁，也不得用 boolean、helper、hash、identity、candidate cardinality 或 eligibility 包装后重新阻断。协议真实性、authority、Document/revision 与 reply shape 继续失败关闭，但不得重解释回答语义。只有授权人明确原文“解冻 FROZEN-GPT-TEXT-RESPONSE-TWO-GATES-001”并同步替换现役法案、GPT/Browser 施工图、实现与唯一质检才允许改变；普通修复、Provider UI 变化、CI 或单仓代码授权均不构成解冻。

exact text response 的暂未取得结果只能把两类Browser机械事实分开报告：exact user turn 当前不可取得，或该user turn的真实紧邻assistant turn当前不存在。两者都保持现役非mutation observation/pending语义，不得改变两门裁决、增加门禁或扩大为其它DOM路径；assistant多义、URL/Document/revision/authority失真继续按现役失败关闭。该诊断只用精确typed error穿过现役单链，不进入成功`BrowserExactAssistantTurnReplyV3`、WAL、receipt、数据库或Runtime日志字段，也不得保留文本路径对通用candidate-missing的兼容fallback。

`FROZEN-GPT-IMAGE-SOURCE-EVENT-WAIT-001` 的 Browser 部分已按本次授权解冻替换并重新冻结：authenticated-media 读取先在 canonical conversation URL 与精确 `userTurnId` 之后、下一个 user turn 之前的范围内直接检查非空 `currentSrc/src`；尚未出现时，只能在同一次加密 command 的调用期 observation 内安装一个 `MutationObserver`，仅监听节点加入及 `src/srcset` 变化，单次最多等待 5000ms，source 出现即在同一次已登录页面调用中 fetch 原始 bytes 并按内容 hash 去重。单次期满仍无 source返回 typed pending并释放 lease/lane；下一次 observation立即进入唯一 FIFO，由 BrowserLaneCoordinator在请求资格与全局节拍满足后激活该 job精确绑定 Tab并 fresh observe，正常轮询不得导航。调用期 observer与 timeout必须结算即销毁，总期限只由 GPT Child现有 `probeBudgetMs`决定；不得形成 per-job timer、第二 timer Owner、持久状态或调度器。

`FROZEN-GPT-SUBMIT-TWO-PRECONDITIONS-001` 的 Browser 部分固定：真正 submit 前除 Product 已批准的“提示词 hash + 精确附件集合”和 Browser 自有的“current Target/Document/fence + 同 effect 尚未现实输入”外，不得再增加任何发送资格。批准附件集合允许为空。历史 user turn、固定 turn 编号或奇偶、按钮标签均不是发送前置条件，点击前不得读取历史 turn 决定发送资格；精确 submit 的同一 Browser command 在 `mouseReleased` 后立即发出一次无点击、无业务输入计数的固定中性 `mouseMoved(0,0)`，随后才开始 2500ms 闸门并从 fresh current Document 选取最大有效序号的 user turn，核对批准 prompt hash 与 Composer 已清空。撤离失败发生在 submit 可能已经输入之后，必须保留 `DISPATCHED` 并只允许同 effect 零 submit 读回；普通点击、模型、推理强度、附件、限流弹窗和恢复读回不得执行该撤离，也不得为此增加 DOM 读取、Tab 激活、导航、timer、WAL 或重试。按钮唯一、可见、可交互与 hit-test 仍是 Browser 执行物理点击的内部机械安全，不得上升为 GPT/Product 业务关卡。

`FROZEN-GPT-SUBMIT-ACTIONABILITY-WAIT-001` 的 Browser 部分固定：精确待发送内容和 WAL/current Document 已通过后，精确发送按钮暂时 `disabled/aria-disabled` 时，在同一原子 command 的现有 5000ms 有界期限内重复 fresh mechanical qualification，恢复后至多输入一次；期限耗尽仍返回原生 disabled typed receipt、mutation=no、physical input=0。不得建立第三业务前置条件、持久 timer、第二 WAL、队列或重试器。

`FROZEN-GPT-MODEL-SELECTOR-SEMANTIC-MINIMUM-001` 的 Browser 部分固定：模型选择准备只机械观察精确批准模型选项，或点击唯一“选择模型”入口后等待该选项出现；随后只点击该唯一选项，并在同次 mutation 中直接读取保留的被点击节点 `aria-checked=true`，再确认该精确选项退出当前可选集合。Browser/GPT 不检查 popup、simple/advanced panel、旧面板形态、`data-active`、`inert` 或其它 UI 外壳拓扑。入口与选项自身的唯一性、可操作性以及被点击选项自身的 `aria-checked` 是 Browser 物理动作和直接后置证明，不属于被禁止的外壳拓扑，也不得扩展成新的菜单结构考试。

`document` 是 Target 当前状态的 live view。导航、刷新或 Target 交接后，所有合法消费者必须读到新的 Document；任何包装层不得用对象展开、缓存或复制把它冻结成旧 Document。

Browser mutation 的唯一规则不变：先写 WAL，再至多 dispatch 一次，最后一次输入后等待 2500ms，从 fresh current Document 做直接后置读回。GPT 只有真正提交属于 provider-effect scope；fresh/profile/model/menu/附件/Composer 等准备属于 target-local scope，身份包含 attempt 与当前 Target/Document generation，旧 attempt 不得阻断新 attempt 重建准备。provider_effect_identity 精确为 `job_id + result_revision + product_step_id + call_id + child_id + request_hash + payload_hash`，不含 Product Plugin名称/版本/Skill hash、attempt/process/lease/fence/Target/Document；同一 effect跨进程物理 dispatch总数至多一。WAL为CONFIRMED submit加密保存同包清洗的canonical conversation URL、精确userTurnId与实际prompt hash；URL只负责“去哪里读”，effect identity只负责“是否已经发送”。confirmed readback先按`job_id + result_revision + product_step_id + call_id + child_id`查询唯一既有effect：不存在时才由当前调用构造新身份；存在非零输入、DISPATCHED或CONFIRMED事实时，直接沿该WAL行的既有原子身份零输入读回，当前代码或提示词生成变化不得把它改判为缺失或非法。authorized-continuation只按Website当前route relation查询exact parent job、当前product step、`turn-submit` call与`submit_exact_gpt_turn_once` Child的唯一CONFIRMED effect，父attempt不参与定位。两种模式都经唯一lane为当前job建立或取得其独占system Target；当前URL命中时零导航，否则只执行一次Browser-owned `Page.navigate`到该URL，2500ms后fresh readback必须相等。authorized-continuation不读取父userTurnId/回答、不复用父Target、不授予当前submit。侧栏点击、标题/顺序/时间猜测、搜索、滚动、自动展开、重试与fallback均不参与。该导航不写第二WAL、不取得provider effect identity。纯observation和结果读取不建立第二WAL、lane、timer或队列。

唯一 settled-title 例外仍服从同一 mutation 规则：`renameExactGptConversation` 是源码冻结、caller 无 selector/坐标/脚本/步骤控制的 target-local typed intent。它先证明 currentUrl 精确等于 active call 的 confirmed canonical URL、该 URL 对应侧栏行唯一、菜单与编辑器无残留；标题已精确相等时以零输入结算，否则在一个 WAL command 和固定10秒预算内依次执行打开当前行菜单、点击唯一“重命名”、填入 NFC targetTitle、Enter 保存四个物理输入，每一步逻辑访问开始前复用账号级1.5秒门，中间不得离开 Browser 或穿插别的 Child。最后一个输入后只在2500ms总闸门满时fresh读取同一canonical行标题，精确相等才CONFIRMED。

现役 `physical_input_count` 原位扩为 `0..4`，authenticated terminal receipt 写入实际累计值；旧 SQLite 表只做事务性单向 rebuild 并保持全部既有行，不新增表、列、dual read 或普通 Runtime migration。部分执行以 1..3 和 REJECTED 结算。若该精确 cleanup command dispatch 后没有 authenticated terminal reply，Browser 可在同一 WAL 原位终结 `REJECTED + dispatched + BROWSER_COMMAND_RECEIPT_MISSING`，计数 0 表示未取得已鉴权计数而不是现实零输入；不得重放，pending 必须归零。此例外不得扩展至 Provider submit、附件、Prompt、模型或任意其它 mutation。

`FROZEN-GPT-ATTACHMENT-PROVIDER-DUPLICATE-SUFFIX-001` 的 Browser 部分固定：Product 批准附件集合是唯一语义权威并允许为空；Browser 只在同一个点击原子动作内机械执行 GPT 冻结语义。每个 Provider 可见名称先做 NFC 后让精确批准名称优先；只有精确未命中时，才允许删除最后扩展名前、无扩展名则文件名末尾恰好一个无空格 `(<纯十进制数字>)`，且删除后必须精确命中批准名称，才视为同一附件。附件数量、基础名、扩展名、非数字括号、空格括号和其它改名仍失败关闭。禁止恢复原始展示名硬比对而误杀重试，禁止 substring、模糊匹配、宽正则、第二附件身份或兼容分支；现役 Browser inspector 与真实注入函数正反验收必须共同失败关闭。改变、删除、改名、弱化、扩张或绕过本边界，只有用户明确原文“解冻 FROZEN-GPT-ATTACHMENT-PROVIDER-DUPLICATE-SUFFIX-001”并同步替换现役法案、GPT/Browser 施工图、实现与唯一质检后才允许；普通修复、代码迭代、CI 授权、Provider UI 变化或单仓变更均不构成解冻。

已确认提交、回答尚未出现时，正常轮询保留 job—Target绑定但在第一次及后续observation前都释放 FIFO lease与物理 lane。GPT Child只计算至少70秒的最早资格时间并立即提交 observation waiter；BrowserLaneCoordinator以 waiter `eligibleAt`、全局 `observationNotBefore`和一个 wake timer作为唯一计时 Owner，并在每次真实observation终结时只抽取一次70—90秒全局间隔。随机值不按job、Tab、Product或Child生成和保存，相邻真实Provider observation至少70秒且总频率不随N增长；剩余deadline不足70秒时不再park或acquire。具备资格后只激活精确绑定 Tab、重验 Target/current Document并 fresh observe一次，pending再次释放，正常轮询 Page.navigate=0。只有进程重启、绑定 Target真正丢失或同等恢复现场，Website再次授权同一 accepted attempt后，Browser才按同一 provider_effect_identity从唯一 WAL读回 canonical URL与userTurnId，以 `confirmed-readback`为该 job取得精确 system Target，再按该 URL零次或一次精确导航后 fresh observation；不得跨业务任务使用该 URL，不得再次写 Prompt、附件或提交。该恢复路径 physical submit delta=0，不建立 park object、第二状态、逐任务时钟或第二调度。

pending park 只释放物理 lease，不释放本次 Product/Child 调用的原子身份。现役 production call facade 是该调用期 identity 的唯一内存 Owner；每次 reacquire 后，必须在新 physical lease 上以同一 `productStepId + callId + childCapabilityId + inputHash + actionOrdinal` 重新进入 `runAtomicStep` 再执行 Browser command。不得从新 lease 的空 `atomicStep` 降级到 `browser-lifecycle` 或 Browser command 名称，也不得新增持久身份、park object、第二 facade 或兼容分支。`checkpoint_gpt_text_response` 与对应图片读取 Child 的既有 typed candidate/source missing 只表示本次 observation 尚未取得结果；只有这些精确 Child/错误组合可继续等待，其它 DOM candidate missing 与 Browser 错误继续按真实身份失败关闭。

`FROZEN-EXACT-TARGET-POLL-RESULT-REVISION-001` 的 Browser 部分已按本次授权精准解冻替换并重新冻结：正常 Provider回答轮询保留 exact job—system Target独占绑定，40秒静默门后 observation waiter立即进入唯一 FIFO，由 BrowserLaneCoordinator唯一计时；请求具备资格后只取得并激活精确绑定 Tab、重验实时 current Document、fresh observe一次，pending释放 lease/lane并重新排队。正常轮询不得读取 canonical locator或执行 Page.navigate。只有进程重启、绑定 Target真正丢失或同等恢复现场，才从同一 WAL effect取得 canonical URL与 userTurnId，再以 `confirmed-readback`为该 job取得精确 system Target；不得执行固定 GPT start URL/首页导航，不按旧新 targetRef或扫描旧标签猜选，同 URL零导航，不同 URL最多一次精确 Browser-owned `Page.navigate`，2500ms后 fresh readback不等即 typed fail-close。Browser WAL的 `logical_mutation_id`仍是唯一公开 `provider_effect_identity_hash`，不得复制列、台账或第二 store。
