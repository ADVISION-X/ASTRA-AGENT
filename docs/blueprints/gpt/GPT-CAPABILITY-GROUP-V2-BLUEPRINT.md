## 唯一 Owner 与职责

GPT 只把 Product 已决定的当前 Provider turn 变成 typed result，不拥有跨任务 Provider conversation、continuation identity、predecessor、frontier 或持久状态。Product 决定 Prompt、每个技能的精确模型与 0..5 整数推理目标、附件、步骤和结果组装；GPT 不更换 Product 指定的模型，只按当前已选模型页面滑杆上限向下截断推理数值。Website Bazi sender 提供已入库且精确绑定的父报告材料，Website仅为文章本地化签发严格direct parent；固定catalog每个locale/cohort及补译任务均fresh；Browser决定Target、current Document、FIFO、现实副作用和唯一WAL持久fact；Forensics保存回答artifact；Runtime运输结果；Website唯一裁决业务恢复与完成。

文本主链固定为：

```text
BZ05/BZ03/BZ04: fresh prepare/attach/write
  -> submit_exact_gpt_turn_once -> checkpoint_gpt_text_response

BZ03/BZ04 的本轮附件必须包含 Website 已入库、与 consultation root 及 direct predecessor 精确绑定的完整父报告；不得读取或选择历史 Provider conversation。

SEO article localization: Website route relation=provider_continuation
  -> zh-HK parent = 同一文章已领域接纳的 zh-CN produce_article job
  -> zh-TW/en-US/ja-JP/ko-KR parent = 同一文章严格前序 locale job
  -> Runtime 机械验证 parent result ref/hash，并从本地 completed 父任务读取 current parent attempt
  -> 文章生成与五语翻译统一使用 article_synthesis product step
  -> Browser 从 exact parent job + completed parent attempt + article_synthesis + 固定 call/Child 的唯一 CONFIRMED WAL effect 取 canonical URL
  -> 为当前 job 建立独占 Target并精确导航
  -> 当前 translation turn submit/checkpoint

Static catalog localization: Website route relation=provider_continuation
  -> zh-HK 链首无 parent 并 fresh
  -> zh-TW/en-US/ja-JP/ko-KR parent = 同一 source/version/hash、policy、authorization、有序 message-id cohort 与 role 的严格前序 locale task
  -> Browser 只按 exact parent job + completed parent attempt + 当前 locale-neutral product step + 固定 submit call/Child 取唯一 CONFIRMED canonical URL
  -> 当前 locale turn submit/checkpoint；五个 locale task/result/admission 仍各自独立
```

这条链不把父回答作为翻译源：五次翻译始终消费Website下发的同一份zh-CN canonical article material。Runtime先用本地completed父任务机械核对Website parent ref/hash，再读取该父任务的current attempt；GPT只把route-authorized exact parent job、该completed parent attempt与当前Product给出的`article_synthesis` step整体交给Browser acquisition，不接触父URL、父Target、父userTurnId或父回答。parent attempt只用于WAL locator只读选择，永不进入provider effect identity。任何父结果绑定缺失或不等、父attempt缺失、WAL缺失/多义/未决都在Provider输入前失败关闭。

`submit_exact_gpt_turn_once` 在自己的直接后置一次返回 CONFIRMED、canonical conversation URL、精确 user turn 身份和 Browser effect receipt。provider_effect_identity 不含 attempt/process/lease/fence/Target/Document；Browser WAL 已有 CONFIRMED 时该 Child 只读回同一 receipt/URL，绝不再次输入。`checkpoint_gpt_text_response` 正常轮询保留 exact job 与其独占 system Target 的双向唯一绑定，但 pending 立即释放 Browser lease 与唯一物理 lane。GPT Child 只计算下一次 observation 的最早资格时间并立即调用现役 Browser typed 入口，不创建或等待 timer；请求进入唯一 FIFO 后，由 BrowserLaneCoordinator 以 waiter `eligibleAt`、一个全局 `observationNotBefore` 和一个 wake timer 作为唯一计时 Owner。具备资格后只取得并激活精确绑定 Tab、重验实时 current Document、fresh observe 一次；pending 再释放，正常轮询 `Page.navigate=0`。ready 时由同一 coherent observation 一次取得紧邻 assistant turn 的 observed DOM + semantic text，写入且读回一份 artifact。同一 attempt、exact call 的该 artifact 已存在且完整性成立时，必须先按现役 idempotency identity 精确读回并直接返回，Browser 页面 observation 增量为零；仅 artifact 不存在时才允许首次观察并 append，已存在但内容或完整性不成立时 typed fail-close，绝不覆盖。

每个 Production GPT Child 的既有 ChatGPT 逻辑访问必须先消费 Browser 同一 coherent cycle 返回的 known-rate-limit blocker。该覆盖不仅包含Browser acquisition与atomic phase，也包含atomic success后的confirmed provider-effect记录与`selectExactGptConversation`精确恢复选择；任一阶段得到`BROWSER_KNOWN_GPT_RATE_LIMIT`都必须由`ProductionGptChildTools.closeKnownRateLimitAndReadGate`唯一关闭Owner进入同一`closeKnownProviderRateLimit`，若原effect已CONFIRMED则必须保留该effect事实且不得退化为target-local/未发送failure。Browser 精确识别唯一 `role=dialog`、标题“请求过于频繁”、两段冻结正文和唯一启用且可交互的“明白了”按钮时，原 Child 本次物理输入为零；`ProductionGptChildTools` 不把 blocker 交给 Product Flow，而是先调用 Runtime 注入的唯一 `ProviderRateLimitControlPort`，用现役 Outbox 持久关闭无关新 claim/submit，再执行唯一 Product 不可见的 `acknowledge_known_gpt_rate_limit` 内部 Child。该 Child 在当前logical cycle后优先取得同一lane的下一周期，只对刚取得的同 Target/Document/fact revalidate并点击一次，分类完成到 dispatch 的受控 SLO使用原始`observed_at+1s`截止点；点击后仍等待至少2.5秒做fresh absent readback。若进程恢复时dialog已精确不存在，则以零点击absent receipt闭合；若点击/重验失败，则必须先按同一incident把`not_cleared`送达Website并保持本地submit门关闭，后续仍只按同一WAL identity读回，不重复点击。若同一ack WAL已经是`REJECTED`或`DISPATCHED`等不可复写终态，恢复只能沿同一Browser lane执行普通1.5秒节流的`readKnownGptRateLimitClearance`只读意图；它不进入mutation WAL、不执行物理输入，只有同Target/Document复核为精确absent才生成认证browser fact并沿原incident交付`confirmed_absent`，仍存在、文案mismatch或身份漂移均保持`not_cleared`。原 submit 已发生的 job 继续同 effect checkpoint、Outbox 和 Website admission，未发生 submit 的 job 等 Website 冷却后对同 job的新 attempt授权。旧 `web/children/rate-limit-dialog.ts` 与 Product 可调用确认能力继续物理不存在。

唯一关闭Owner在建立incident前必须先读现役submit gate：门已因首个incident关闭时，后续并发或多Tab的exact blocker只返回“现役cooldown已关门”，不新建incident、不再点击、不向Website写第二notice。若首个incident在Outbox持久化阶段失败且gate尚未关闭，本次失败仍必须携带已有CONFIRMED provider effect的identity、Browser authority与mutation outcome；不得以裸closure error把已发送事实降级或允许新attempt重放。

同一 preflight 返回 `mismatch` 时，GPT 只在 `ProductionGptChildTools.executeOne` 覆盖 Browser acquisition 与 atomic phase 的唯一归一化边界，把 `BROWSER_GPT_DIALOG_UNRECOGNIZED` 及同源 Browser authority ref/hash、三态机械 fact 转为当前执行内存中的失败 `ProductionGptAtomicCallResult`，再沿现役 `throwGptChildFailure` 报告 stable Child failure。该分支物理输入、ack、cooldown incident、Forensics artifact、attempt failure 与 lease release 增量全部为零；不得调用 `ProviderRateLimitControlPort` 或 `closeKnownProviderRateLimit`。只有后续 fresh 同Target/current Document preflight返回typed `absent`时，新的逻辑访问才可继续。普通Child proof只在当前调用链内消费；Forensics仍只持久已完成答案raw artifact，不得新增failure artifact或逐Child ledger。

协调 Owner 固定为调用 GPT facade 的 Runtime。Runtime 通过构造注入的唯一窄 `ProviderRateLimitControlPort` 先持久关门；`ProductionGptChildTools` 只回调该端口，不 import Runtime 私有模块。该控制反转仍是现役 `agent-production-runtime -> gpt` 依赖，不形成 `gpt -> agent-production-runtime` 反向 dependency edge或环。

除上述 detection→ack 唯一紧急对外动作外，所有 ChatGPT 普通逻辑访问跨 job、Tab、Product 共用 Browser 一个账号级至少 1.5 秒起始节拍；50ms、25—250ms 和 deadline 尾部不足 1.5 秒的重读物理退出。一次 coherent observation 内的 CDP primitives不拆分计时，更长的2.5秒动作读回、40秒提交静默和Browser每轮一次抽取的70—90秒全局Provider observation间隔继续优先。GPT Child只提交至少70秒的typed资格请求，不保存随机值、第二timer或每Child节拍。

GPT 准备动作对一次 fresh coherent observation 的裁决统一为 `STABLE_DONE|STABLE_ACT|TRANSIENT_DOM|HARD_FAIL`。正常 DONE/ACT 立即继续，零新增等待；只有候选当次缺席、节点 stale、`NO_LAYOUT_BOX` 或无矛盾 partial topology 可判为 `TRANSIENT_DOM`，并通过 Browser 唯一 typed stage 依次等待 1.5 秒、3 秒后各做一次整包 fresh 只读复核。任一复核恢复即继续；任一复核出现多候选、文案/模型/推理强度/Prompt/附件/URL/授权/Target/Document/effect mismatch 即立即失败；第三次仍 transient 才以最后 observation 正式失败。该协议只覆盖 `prepare_clean_gpt_chat`、profile/model/reasoning、attachment control/file input、Composer 准备以及非冻结普通动作的直接 DOM 后置证明；每次复核不点击、不输入、不上传、不导航、不换 Tab，动作已经发生后也绝不重放。submit 的现役 5 秒 actionability、附件 uploading、Provider generating、70—90 秒回答观察、限流确认、Tab/导航/授权/WAL/recovery 均不得叠加该 stage。

`FROZEN-GPT-RESPONSE-NO-PROMPT-REHASH-001` 固定：提示词 hash 只属于发送 Child 的发送前内容身份和发送后新 user turn 证明。文本与图片回答读取 Child 不得接收 `expectedPromptHash`，不得从已折叠或重新渲染的历史 user message DOM 提取、规范化、重算或比较 `precedingPromptHash`，也不得把该二次 hash 写入回答或图片 receipt。回答身份只由发送 Child 已确认的 canonical conversation URL、精确 `userTurnId`、其真实紧邻 assistant turn，以及 Browser 当前 Target/Document/revision 共同确定；回答的 `rawDomHash`、`semanticTextHash` 与图片媒体 bytes hash 继续保留。改变或删除本冻结边界，必须由用户在未来任务中明确解冻，并同步替换施工图、实现与唯一质检；普通修复或 CI 授权不构成解冻。

`FROZEN-GPT-TEXT-RESPONSE-TWO-GATES-001` 固定：`checkpoint_gpt_text_response` 只允许两个阻断判据。回答身份安全门在同一原子 observation 内整体消费 confirmed canonical conversation URL、exact `userTurnId`、其真实紧邻且唯一的 assistant-role turn、Target/current Document/main-frame loader 与 observation revision；回答结算完成门只消费同包 stop button 状态与 semantic text，stop 存在一律 pending，stop 消失且正文非空立即 DONE，stop 消失且正文连续为空只沿现役 20 分钟窗口 pending 或产生 `GPT_RESPONSE_STOPPED_EMPTY`，stop 再出现、正文非空或身份失真都将窗口归零。页面末位、Composer/submit 数量、layout/visible/viewport/hit-test、hidden/aria-hidden/inert、Prompt rehash、固定 turn 编号/奇偶、标题、侧栏、时间、动画、展开状态及其它 UI 外壳不得成为候选存在、内容返回、DONE、pending 或 failure 的第三门禁，stop 状态也不得在 Browser 读取阶段清空已精确定位的 DOM/semantic text；不得以 boolean、helper、hash、identity、candidate cardinality 或 eligibility 包装规避两门上限。只有授权人明确原文“解冻 FROZEN-GPT-TEXT-RESPONSE-TWO-GATES-001”并同步替换现役法案、GPT/Browser 施工图、实现与唯一质检才允许改变；普通修复、Provider UI 变化、CI 或单仓代码授权均不构成解冻。

Provider 对已发送 user-role Prompt 的 DOM 展示只允许一项确定性投影：逐字符把 U+00A0 映射为 U+0020 后再与批准 Prompt 比较。该投影不 trim、不做 NFKC、不折叠连续空白、不映射其它 Unicode 空白，也不得作用于 assistant-role 回答；批准 Prompt 自身含 U+00A0 时仍保持原批准值，不做反向或对称改写，不等即失败关闭。该规则只修复 Provider 将普通空格展示为 NBSP 的已证实边界，不建立第二 parser、模糊比较或兼容链。

文本回答的 Provider observation 等待必须只投影一个封闭诊断原因：第一次 observation 尚未发生、exact user turn 当前不可取得、其真实紧邻 assistant turn 当前不存在、stop button 仍存在、或 stop 已消失但正文为空且现役20分钟窗口仍在确认。每次等待只发一个固定事件码，不得同时保留统一文本 wait 事件；原因只由上一次现役两门裁决产生并只供日志观察，不得反向决定 DONE、pending、failure、窗口、deadline、lane、Target、导航或重试。第一次 observation 前必须诚实记录尚未观察，不得伪造页面原因。原因不进入result、artifact、WAL、数据库或typed identity，不新增Runtime日志字段；图片等待继续使用其现役统一事件。

`FROZEN-GPT-IMAGE-SOURCE-EVENT-WAIT-001` 已按本次授权解冻替换并重新冻结：图片 checkpoint 不得按 fixed sleep 猜测图片已经生成。Browser authenticated-media observation 必须在 canonical conversation URL 与精确 `userTurnId` 之后、下一个 user turn 之前的范围内先直接检查非空 `currentSrc/src`；尚未出现时，只能在同一次调用期 observation 内以一个 `MutationObserver` 监听节点加入及 `src/srcset` 变化，单次最多等待 5000ms，出现即在同一次已登录页面调用中 fetch 原始 bytes 并按内容 hash 去重。单次期满仍无 source 只返回现有 typed pending并释放 lease/lane；下一次请求经唯一 FIFO、唯一全局 observation 节拍取得并激活该 job精确绑定 Tab后 fresh observe，正常轮询不得导航，总期限只复用现有 `probeBudgetMs`。不得等待 assistant role、预览/分享/下载控件、`img[alt]`、图片完成标志、布局、可见性、宽高或固定 turn 编号；不得新增 wait Child、per-job timer、队列、WAL、状态机或下载链。未来改变仍须用户明确解冻并同步替换 GPT/Browser 法案、施工图、实现与唯一质检。

`FROZEN-GPT-SUBMIT-TWO-PRECONDITIONS-001` 固定真正 submit 前只能确认两件事。第一，当前 Composer 提示词 hash 与 Product 批准值相等，当前附件集合按 `FROZEN-GPT-ATTACHMENT-PROVIDER-DUPLICATE-SUFFIX-001` 与批准集合相等。第二，Browser 当前 Target/Document/fence 有效，且唯一 WAL 证明同一 provider effect 尚未发生现实输入。历史聊天、既有 user turn、固定 turn 编号或奇偶、按钮标签以及 Browser 内部可操作性检查均不得成为新增业务前置关卡，也不得在点击前读取历史 turn 来决定发送资格。点击后等待 2500ms，再从 fresh current Document 只取最大有效序号的 user turn，确认其 prompt hash 等于批准值且 Composer 已清空；这是发送后的直接证明，不是第三个前置条件。改变或删除本冻结边界，必须由用户在未来任务中明确解冻，并同步替换施工图、实现与唯一质检；普通修复或 CI 授权不构成解冻。

`FROZEN-GPT-ATTACHMENT-PROVIDER-DUPLICATE-SUFFIX-001` 已按本次授权精准解冻、替换并重新冻结：Product 批准附件集合是唯一语义权威并允许为空。非空时，每个 Provider 可见名称先做 NFC，再让精确批准名称优先；只有精确未命中时，才允许删除最后扩展名前、无扩展名则文件名末尾恰好一个无空格尾缀；尾缀只能是 `(<纯十进制数字>)` 或 `(<8位十进制日期>-<6位十进制时间>)`，且删除后必须精确命中批准名称，才视为同一附件。GPT 的上传后附件对账与 Browser 的最终 submit guard 必须使用这一条语义；附件数量、基础名、扩展名、其它括号形状、空格括号、多重尾缀和其它改名仍失败关闭。不得出现 substring、模糊匹配、宽正则、第二附件身份、兼容分支或因 Provider 后缀误判而重传。未来改变、删除、改名、弱化、扩张或绕过本边界，仍只有用户明确原文“解冻 FROZEN-GPT-ATTACHMENT-PROVIDER-DUPLICATE-SUFFIX-001”并同步替换现役法案、GPT/Browser 施工图、实现与唯一质检后才允许；普通修复、代码迭代、CI 授权、Provider UI 变化或单仓变更均不构成解冻。

## 删除边界

以下对象必须物理不存在：private base、reusable/derived reservation、semantic read grant、fork、child conversation、GPT Session Controller、continuation identity/store/row/frontier/CAS、独立 submission locator、document transition policy、恢复型 park、取消后自发重跑和通用旧 attempt recovery。只保留submit Child内对同一provider effect的confirmed receipt readback，以及Browser按Website provider_continuation从exact parent job、Runtime验证的completed parent attempt与当前product step唯一CONFIRMED WAL effect读取canonical URL的产品中性Target acquisition；parent attempt只作locator且不进入effect identity，不得用兼容wrapper、alias、feature flag、dual-read/write、第二lane/store/scheduler或状态机扩张。

## Browser 边界

GPT 只消费 Browser 签发的实时 current Document 和 typed command terminal。Browser 的 Target lease 对外暴露的 `document` 必须是 live getter；包装它时不得用 spread 把 getter 求值成旧快照。Provider/控件 mutation 仍先经唯一 FIFO、每 provider effect 一条权威 WAL、跨 attempt/进程至多一次 physical dispatch 和 2500ms 后的 fresh postcondition；Browser-owned canonical URL 导航只做可逆页面生命周期收敛，当前命中零导航，否则唯一一次精确 Page.navigate 后同样经过 2500ms 与 fresh currentUrl readback，但不取得 Provider effect 或第二 WAL。纯读结果不新建 WAL、队列或第二恢复权限。


## 证据、失败与验收

可持久化的必要事实只有回答 artifact，以及 Browser WAL 同一 provider-effect 行中的 confirmed effect 与加密 locator。两者分别证明回答内容和同一物理副作用/页面 locator；GPT 不保存跨任务会话状态，Browser 不保存 Website direct predecessor，日志只保存脱敏 ref/hash，Website 不接收 Provider locator。
