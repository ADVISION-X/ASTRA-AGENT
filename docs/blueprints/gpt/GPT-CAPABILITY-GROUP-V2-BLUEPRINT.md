## 唯一 Owner 与职责

GPT 只把 Product 已决定的当前 Provider turn 变成 typed result，不拥有跨任务 Provider conversation、continuation identity、predecessor、frontier 或持久状态。Product 决定 Prompt、每个技能的精确模型与 0..5 整数推理目标、附件、步骤和结果组装；GPT 不更换 Product 指定的模型，只按当前已选模型页面滑杆上限向下截断推理数值。Website Bazi sender 提供已入库且精确绑定的父报告材料，Website为文章本地化及固定catalog同cohort后继签发严格direct parent；固定catalog首任务fresh；Browser决定Target、current Document、FIFO、现实副作用和唯一WAL持久fact；Forensics保存回答artifact；Runtime运输结果；Website唯一裁决业务恢复与完成。图片成功 checkpoint 在同一个 Forensics Owner 中保存原始媒体字节，并只为该已完成回答附加一份与原图 ref/hash 绑定的最小身份描述 artifact；它只保存 assistant turn、媒体语义、Browser authority 与原输入身份 hash，不保存 canonical URL、图片副本或恢复决定。GPT 在 source 授权下从原 WAL 取得 URL/user turn，核描述与原图后零提交归还原图片；Product 只见原图 ref，不能取得描述作为旧业务输入。

上述 SEO 文章链不把父回答作为翻译源：五次翻译始终消费Website下发的同一份zh-CN canonical article material。Runtime先用本地completed父任务机械核对Website parent ref/hash，再读取该父任务的current attempt；GPT只把route-authorized exact parent job、该completed parent attempt与当前Product给出的`article_synthesis` step整体交给Browser acquisition，不接触父URL、父Target、父userTurnId或父回答。parent attempt只用于WAL locator只读选择，永不进入provider effect identity。任何父结果绑定缺失或不等、父attempt缺失、WAL缺失/多义/未决都在Provider输入前失败关闭。

`submit_exact_gpt_turn_once` 在自己的直接后置一次返回 CONFIRMED、canonical conversation URL、精确 user turn 身份和 Browser effect receipt。provider_effect_identity 不含 attempt/process/lease/fence/Target/Document；Browser WAL 已有 CONFIRMED 时该 Child 只读回同一 receipt/URL，绝不再次输入。`checkpoint_gpt_text_response` 正常轮询保留 exact job 与其独占 system Target 的双向唯一绑定，但 pending 立即释放 Browser lease 与唯一物理 lane。GPT Child 只计算下一次 observation 的最早资格时间并立即调用现役 Browser typed 入口，不创建或等待 timer；请求进入唯一 FIFO 后，由 BrowserLaneCoordinator 以 waiter `eligibleAt`、一个全局 `observationNotBefore` 和一个 wake timer 作为唯一计时 Owner。具备资格后取得当前 live Target 或直接创建当前 Target，按原 confirmed effect 的 canonical URL 精确选择会话，并以原 Product turnMarker 唯一定位文本回答；图片仍用原 exact userTurnId 定位；当前 URL 相等时 `Page.navigate=0`，不同时最多一次精确导航；随后重验 current Document 并 fresh observe 一次，pending 再释放。ready 时由同一 coherent observation 一次取得紧邻 assistant turn 的 observed DOM + semantic text，写入且读回一份 artifact。同一 attempt、exact call 的该 artifact 已存在且完整性成立时，必须先按现役 idempotency identity 精确读回并直接返回，Browser 页面 observation 增量为零；仅 artifact 不存在时才允许首次观察并 append，已存在但内容或完整性不成立时 typed fail-close，绝不覆盖。

每个 Production GPT Child 的既有 ChatGPT 逻辑访问必须先消费 Browser 同一 coherent cycle 返回的 known-rate-limit blocker。该覆盖不仅包含Browser acquisition与atomic phase，也包含atomic success后的confirmed provider-effect记录与`selectExactGptConversation`精确恢复选择；任一阶段得到`BROWSER_KNOWN_GPT_RATE_LIMIT`都必须由`ProductionGptChildTools.closeKnownRateLimitAndReadGate`唯一关闭Owner进入同一`closeKnownProviderRateLimit`，若原effect已CONFIRMED则必须保留该effect事实且不得退化为target-local/未发送failure。Browser 精确识别唯一 `role=dialog`、标题“请求过于频繁”、两段冻结正文和唯一启用且可交互的“明白了”按钮时，原 Child 本次物理输入为零；`ProductionGptChildTools` 不把 blocker 交给 Product Flow，而是先调用 Runtime 注入的唯一 `ProviderRateLimitControlPort`，用现役 Outbox 持久关闭无关新 claim/submit，再执行唯一 Product 不可见的 `acknowledge_known_gpt_rate_limit` 内部 Child。该 Child 在当前logical cycle后优先取得同一lane的下一周期，只对刚取得的同 Target/Document/fact revalidate并点击一次；当前 Target/Document hash只允许用于本次Browser动作安全，不能写入持久cooldown intent、跨仓notice/receipt或作为重启后的ack恢复身份；旧incident重启不得跨1秒窗口重放点击；原ack可信CONFIRMED WAL terminal才可零输入读回并沿同incident交付confirmed_absent；新当前页面fresh absent不足以清算原事故，缺原terminal时交付not_cleared维持关门，分类完成到 dispatch 的受控 SLO使用原始`observed_at+1s`截止点；点击后仍等待至少2.5秒做fresh absent readback。进程恢复时不得凭旧 Target/Document 或旧观察继续 ack；新的当前 coherent observation 只可证明当前页面事实，不得为旧事故签clearance或重放旧点击；若点击/重验失败，则必须先按同一incident把`not_cleared`送达Website并保持本地submit门关闭，后续仍只按同一WAL identity读回，不重复点击。若同一当前authority epoch内ack WAL已经是`REJECTED`或`DISPATCHED`等不可复写终态，只能在该当前lane与仍live的当前Target/Document下执行节流的零输入clearance读回；跨进程、Target丢失或身份漂移时不能恢复旧Target；只有精确读回原ack已确认WAL terminal，才能给原incident签`confirmed_absent`，否则保持`not_cleared`。原 submit 已发生的 job 继续同 effect checkpoint、Outbox 和 Website admission，未发生 submit 的 job 等 Website 冷却后对同 job的新 attempt授权。旧 `web/children/rate-limit-dialog.ts` 与 Product 可调用确认能力继续物理不存在。

唯一关闭Owner在建立incident前必须先读现役submit gate：门已因首个incident关闭时，后续并发或多Tab的exact blocker只返回“现役cooldown已关门”，不新建incident、不再点击、不向Website写第二notice。若首个incident在Outbox持久化阶段失败且gate尚未关闭，本次失败仍必须携带已有CONFIRMED provider effect的identity、Browser authority与mutation outcome；不得以裸closure error把已发送事实降级或允许新attempt重放。

同一 preflight 返回 `mismatch` 时，GPT 只在 `ProductionGptChildTools.executeOne` 覆盖 Browser acquisition 与 atomic phase 的唯一归一化边界，把 `BROWSER_GPT_DIALOG_UNRECOGNIZED` 及同源 Browser authority ref/hash、三态机械 fact 转为当前执行内存中的失败 `ProductionGptAtomicCallResult`，再沿现役 `throwGptChildFailure` 报告 stable Child failure。该分支物理输入、ack、cooldown incident、Forensics artifact、attempt failure 与 lease release 增量全部为零；不得调用 `ProviderRateLimitControlPort` 或 `closeKnownProviderRateLimit`。只有后续 fresh 同Target/current Document preflight返回typed `absent`时，新的逻辑访问才可继续。普通Child proof只在当前调用链内消费；Forensics仍只持久已完成答案raw artifact，不得新增failure artifact或逐Child ledger。

协调 Owner 固定为调用 GPT facade 的 Runtime。Runtime 通过构造注入的唯一窄 `ProviderRateLimitControlPort` 先持久关门；`ProductionGptChildTools` 只回调该端口，不 import Runtime 私有模块。该控制反转仍是现役 `agent-production-runtime -> gpt` 依赖，不形成 `gpt -> agent-production-runtime` 反向 dependency edge或环。

除上述 detection→ack 唯一紧急对外动作外，所有 ChatGPT 普通逻辑访问跨 job、Tab、Product 共用 Browser 一个账号级至少 1.5 秒起始节拍；50ms、25—250ms 和 deadline 尾部不足 1.5 秒的重读物理退出。一次 coherent observation 内的 CDP primitives不拆分计时，更长的2.5秒动作读回、40秒提交静默和Browser每轮一次抽取的70—90秒全局Provider observation间隔继续优先。GPT Child只提交至少70秒的typed资格请求，不保存随机值、第二timer或每Child节拍。

GPT 准备动作对一次 fresh coherent observation 的裁决统一为 `STABLE_DONE|STABLE_ACT|TRANSIENT_DOM|HARD_FAIL`。正常 DONE/ACT 立即继续，零新增等待；只有候选当次缺席、节点 stale、`NO_LAYOUT_BOX` 或无矛盾 partial topology 可判为 `TRANSIENT_DOM`，并通过 Browser 唯一 typed stage 依次等待 1.5 秒、3 秒后各做一次整包 fresh 只读复核。任一复核恢复即继续；任一复核出现多候选、文案/模型/推理强度/Prompt/附件/URL/授权/Target/Document/effect mismatch 即立即失败；第三次仍 transient 才以最后 observation 正式失败。该协议只覆盖 `prepare_clean_gpt_chat`、profile/model/reasoning、attachment control/file input、Composer 准备以及非冻结普通动作的直接 DOM 后置证明；每次复核不点击、不输入、不上传、不导航、不换 Tab，动作已经发生后也绝不重放。submit 的现役 5 秒 actionability、附件 uploading、Provider generating、70—90 秒回答观察、限流确认、Tab/导航/授权/WAL/recovery 均不得叠加该 stage。

ChatGPT 页面控件变更时，GPT Child 只在原有 coherent observation、一次 Browser action 与原后置读回链中替换经当前页面验证的精确控件合同；Browser 继续提供节点属性与原子 mutation fact，不解释聊天、模型或附件语义。根页的 Chat/Work 互斥状态以两个按钮的 `aria-pressed` 事实判定，Composer 以当前唯一可编辑节点及其空标记判定；配置弹层、模型候选、强度控件、附件入口与发送按钮各自以所在页面的当前唯一结构和原业务身份验证。旧 DOM selector 和与之绑定的质检在同一变更中物理退出，不保留双轨 selector、兼容猜测或额外恢复链。真实根页观察只证明根页控件；续聊、上传、发送后 user turn 与 Website admission 仍按各自现役门槛读回，不得由页面静态观察代替。

现役发送后的轮次身份由当前页唯一匹配其 `data-turn-key` UUID 的外层与有效 `fallback-turn-N` 顺序共同证明；Browser 从 fresh 同包 DOM 选最大有效序号并核唯一用户单元、message ids 与批准 Prompt hash，GPT 只消费已确认的 UUID、canonical URL 和原 effect receipt。文本回答读取在原 canonical URL 的当前 Document 内按 Product 已写入用户消息的原 `turnMarker` 唯一定位 `:user`，并证明其后唯一真实紧邻的 `:assistant` 单元；当前 UUID 只作本次页面事实，原 UUID 仍在 WAL 证明提交，并以 assistant message id 绑定正文；图片只以 canonical URL 与 userTurnId 之后、下一个用户轮次之前为范围直接取原媒体，不等待 assistant role。旧 `conversation-turn-*` 身份不得留作运行时兼容。旧 WAL effect 不因新页面无旧标记就被当作未输入；无法读回时只沿现役 unaddressable 与 Website 风险授权收敛。

`FROZEN-GPT-RESPONSE-NO-PROMPT-REHASH-001` 固定：提示词 hash 只属于发送 Child 的发送前内容身份和发送后新 user turn 证明。文本与图片回答读取 Child 不得接收 `expectedPromptHash`，仅允许 Browser 在当前 user bubble 的文本节点精确查找原 marker；不得从已折叠或重新渲染的历史 user message DOM 提取完整 Prompt、规范化、重算或比较 `precedingPromptHash`，也不得把该二次 hash 写入回答或图片 receipt。文本回答身份由发送 Child 已确认的 canonical conversation URL、原 Product `turnMarker` 在当前 Document 唯一对应的 user turn、其真实紧邻 assistant turn，以及 Browser 当前 Target/Document/revision 共同确定；图片仍由原精确 `userTurnId` 定位；提交 UUID 继续用于原 WAL 收据、既有 artifact lineage 与 submit/checkpoint 一致性核对，不再用于当前 DOM 文本定位或重发资格；回答的 `rawDomHash`、`semanticTextHash` 与图片媒体 bytes hash 继续保留。改变或删除本冻结边界，必须由用户在未来任务中明确解冻，并同步替换施工图、实现与唯一质检；普通修复或 CI 授权不构成解冻。

`FROZEN-GPT-TEXT-RESPONSE-TWO-GATES-001` 固定：`checkpoint_gpt_text_response` 只允许两个阻断判据。回答身份安全门在同一原子 observation 内整体消费 confirmed canonical conversation URL、原 Product `turnMarker` 唯一对应的当前 user turn、其真实紧邻且唯一的 assistant-role turn、Target/current Document/main-frame loader 与 observation revision；回答结算完成门只消费同包 stop button 状态与 semantic text，stop 存在一律 pending，stop 消失且正文非空立即 DONE，stop 消失且正文连续为空只沿现役 20 分钟窗口 pending 或产生 `GPT_RESPONSE_STOPPED_EMPTY`，stop 再出现、正文非空或身份失真都将窗口归零。页面末位、Composer/submit 数量、layout/visible/viewport/hit-test、hidden/aria-hidden/inert、Prompt rehash、固定 turn 编号/奇偶、标题、侧栏、时间、动画、展开状态及其它 UI 外壳不得成为候选存在、内容返回、DONE、pending 或 failure 的第三门禁，stop 状态也不得在 Browser 读取阶段清空已精确定位的 DOM/semantic text；不得以 boolean、helper、hash、identity、candidate cardinality 或 eligibility 包装规避两门上限。只有授权人明确原文“解冻 FROZEN-GPT-TEXT-RESPONSE-TWO-GATES-001”并同步替换现役法案、GPT/Browser 施工图、实现与唯一质检才允许改变；普通修复、Provider UI 变化、CI 或单仓代码授权均不构成解冻。

Provider 对已发送 user-role Prompt 的 DOM 展示只允许一项确定性投影：逐字符把 U+00A0 映射为 U+0020 后再与批准 Prompt 比较。该投影不 trim、不做 NFKC、不折叠连续空白、不映射其它 Unicode 空白，也不得作用于 assistant-role 回答；批准 Prompt 自身含 U+00A0 时仍保持原批准值，不做反向或对称改写，不等即失败关闭。该规则只修复 Provider 将普通空格展示为 NBSP 的已证实边界，不建立第二 parser、模糊比较或兼容链。

文本回答的 Provider observation 等待必须只投影一个封闭诊断原因：第一次 observation 尚未发生、exact user turn 当前不可取得、其真实紧邻 assistant turn 当前不存在、stop button 仍存在、或 stop 已消失但正文为空且现役20分钟窗口仍在确认。每次等待只发一个固定事件码，不得同时保留统一文本 wait 事件；原因只由上一次现役两门裁决产生并只供日志观察，不得反向决定 DONE、pending、failure、窗口、deadline、lane、Target、导航或重试。第一次 observation 前必须诚实记录尚未观察，不得伪造页面原因。原因不进入result、artifact、WAL、数据库或typed identity，不新增Runtime日志字段；图片等待继续使用其现役统一事件。
