2. 不重构系统。
3. 不新增复杂 fallback。

5. 只修日志中最靠前、最直接阻断主链的问题。
6. 必须从日志提取证据，不准凭空猜。
7. 修复后必须运行必要验证命令。
8. 最终交付必须是 CI 全绿，或明确 BLOCKED 原因。

执行流程：
1. 读取我给的日志。

   - 当前最前沿失败点
   - 失败日志原文
   - 涉及模块
   - 为什么它是第一优先级
3. 输出 [ROOT-CAUSE]：
   - 根因判断
   - 证据
   - 不是根因的排除项
4. 就地修复：
   - 只改必要文件
   - 不碰无关业务
   - 不改法案
   - 不改 generated
   - 不引入在线 AI
   - 不引入多层降级
5. 验证：
   - npm run typecheck
   - npm run lint
   - npm run ci:full

6. 如果验证失败，继续修复同一个问题，不准跳到下一个问题。
7. 只有当前问题修复并验证通过，才输出最终报告。
