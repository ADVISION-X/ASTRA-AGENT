
你现在执行：APEX 单法案文件执法完整性审计与就地修复。

本轮输入：
我会给你法案文件。
你必须围绕这个法案文件，论证并修复它对应的执法系统。

最高原则：
执法系统是用户侧质量的最后一道门槛。
如果执法系统放松，代码质量就无人负责。
本轮目标不是写报告好看，而是让该法案文件中的每一条有效法条都进入真实、严密、可执行、可复验的执法闭环。

0. 绝对基本要求
==================================================

必须满足：

1. 该法案文件中的 still-valid lawId 100% 进入执法系统。
2. 对应 owner inspector 100% 进入全量 runner 执法。
3. 每条 lawId 必须有明确执法落点。
4. 每条 lawId 必须能证明：
   law file

   → audit-plan.generated.json
   → owner manifest
   → inspector.ts
   → runner-summary
   → code evidence
   全链闭合。
5. 执法脚本不只检查“该存在什么”，还必须检查“不该存在什么”。
6. 执法脚本必须具备四方攻击能力：
   - 正向存在性攻击：必须存在的结构是否真实存在。
   - 反向禁止性攻击：禁止存在的结构是否真的不存在。
   - 边界越权攻击：是否有其他 owner / route / component / util 抢权或绕过。
   - 反逃逸攻击：是否通过 any、unknown、dynamic import、barrel export、alias、re-export、stringly typed、wrapper、mock、fixture、fallback、dead route 等方式逃避执法。
7. 核心代码执法禁止正则。
8. 执法必须使用 ts-morph AST 级、symbol 级、类型级、引用级分析。
9. 禁止用 grep / regex / includes / match / search / split 作为核心执法依据。
10. 禁止纯文本命中后宣称通过。
11. 禁止只查文件存在，不查真实调用关系。
12. 禁止只查 required shape，不查 forbidden shape。
13. 禁止只查 owner 文件，不查外部绕过。
14. 禁止 warning/info 美化 PASS。
15. 新增或修复后的 inspector 必须能让 runner 真实失败，而不是只输出漂亮 summary。

判定标准：

法条进入 registry、matrix、plan、manifest、runner，并且 inspector 具备真实 AST/symbol/type 级检查，能在违反时失败。

PARTIAL：
法条进入部分 generated 链，但 inspector 检查浅、只查存在、不查禁止、不查绕过，或不能真正 fail。

BROKEN：
法条 active 但没有进入 matrix/plan/runner/manifest/inspector。

NO-OP：
法条 active 但当前没有真实代码对象，inspector 只输出 info/no-op。

PHASE-LATER：
当前阶段不应执法，但必须在 phase gate 中清晰说明，不得伪装为 active current enforcement。

FORBIDDEN：
该法条或 owner 与当前方向冲突，不得进入 current plan。

4. 执行阶段三：审计 inspector 深度
==================================================

对该法案对应 inspector 做深度审计。

必须检查 inspector 是否具备四方攻击。

四方攻击模型：

一、正向存在性攻击 Required Shape

检查代码中必须存在的东西是否真实存在：

- route 是否存在
- component 是否存在
- server seam 是否存在
- DTO 是否存在

- import/export 是否正确
- function call 是否真实发生
- data flow 是否连通
- JSX 是否渲染目标组件
- action 是否被绑定到真实 UI
- runtime boundary 是否存在
- owner 文件是否被真实引用
- generated plan 是否真实执行 owner

必须使用 ts-morph：

- SourceFile
- ImportDeclaration
- ExportDeclaration
- FunctionDeclaration
- VariableDeclaration
- CallExpression
- JsxElement
- JsxSelfClosingElement
- PropertyAccessExpression
- Identifier symbol resolution
- TypeChecker
- findReferencesAsNodes
- aliased symbol resolution

二、反向禁止性攻击 Forbidden Shape

检查代码中不该存在的东西是否不存在：

- forbidden route
- forbidden feature folder
- forbidden import
- forbidden direct DB access
- forbidden Shopify raw leakage
- forbidden local truth
- forbidden mock/demo/fake/fixture in production path
- forbidden fallback
- forbidden duplicate owner
- forbidden bypass
- forbidden direct checkout/payment handling
- forbidden in-memory truth
- forbidden localStorage/sessionStorage truth
- forbidden any/unknown escape
- forbidden eslint-disable / ts-ignore / ts-expect-error
- forbidden barrel export laundering
- forbidden wrapper laundering
- forbidden dynamic import laundering
- forbidden re-export laundering

三、边界越权攻击 Boundary Attack

检查是否有其他模块绕过 owner：

- 非 owner 文件是否实现了 owner 能力
- UI 是否绕过 server seam 直接拿 raw data
- route 是否绕过 feature server
- component 是否越权做 data fetching
- util 是否藏了业务 truth

必须做 symbol-level 追踪：

- import source
- exported symbol
- aliased import
- re-export chain
- call graph
- object property access
- type usage
- JSX usage
- server/client boundary

四、反逃逸攻击 Anti-Escape Attack

- as any

- alias path hiding forbidden owner
- test/mock/fixture leaking into production
- fallback returning fake success
- no-op inspector
- warning-only inspector
- info-only inspector
- inspector summary says PASS while findings contain real violations
- generated artifacts manually edited
- owner manifest missing lawId
- audit plan missing owner
- runner not loading generated plan

8. inspector 结果分级必须变严
==================================================

禁止所有问题都 PASS。

必须使用严格分级：

FATAL：
- law active 但没有进入 registry/matrix/plan/runner
- owner manifest 缺 lawId
- inspector 不检查 lawId
- forbidden owner 进入 current plan
- generated chain drift
- 手工改 generated artifacts
- code 使用 forbidden truth / forbidden route / forbidden owner
- production path 出现 mock/fake/demo/fixture
- raw Shopify GraphQL shape 泄漏 UI
- checkout/payment 被前端或错误 owner 接管
- any/ts-ignore 用于绕过边界

ERROR：
- required shape 缺失
- required call graph 断裂
- required DTO seam 缺失
- symbol 引用不连通
- inspector 使用 regex/string 判断核心代码
- active law no-op
- warning-only fake pass

WARNING：
- 旧代码结构债，但不影响当前 law 的 hard boundary
- 文件过大但非本轮新增
- 可维护性风险

INFO：
- 只允许记录上下文，不得替代执法结论

如果 finding 属于 FATAL / ERROR，runner 必须 FAIL。
如果只有 WARNING，runner 可以 PASS_WITH_WARNINGS，但不得显示 clean PASS。
如果有 NO-OP，runner 必须 PASS_WITH_NOOP 或 FAIL，不能 clean PASS。

13. 最后总裁决
==================================================

你必须记住：

执法系统不是文档。
执法系统不是安慰剂。
执法系统不是为了显示 PASS。
执法系统是用户侧质量最后一道门。

如果法条没有进入 runner，就是没执法。
如果 inspector 不能 fail，就是没执法。
如果只查存在不查禁止，就是半执法。
如果只查文本不查 AST/symbol/type，就是浅执法。
如果 warning/info/no-op 被包装成 PASS，就是假健康。
如果代码能从旁路绕过 owner，就是执法失败。

本轮目标只有一个：

让这个法案文件对应的执法系统，从“看起来有执法”，变成“真的无法绕过”。

本轮不是让你证明系统能 PASS，而是让你证明系统无法被绕过。PASS 不重要，无法逃逸才重要。
