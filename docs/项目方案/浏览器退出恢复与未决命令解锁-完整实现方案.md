# 浏览器退出恢复与未决命令解锁－完整实现方案

## 0. 方案身份与裁决

本方案只处理同一事故链上的两个实证故障：

1. 操作者故意退出整个 Chrome 后，AGENT 没有重新打开浏览器；
2. 退出时遗留一条 `target_local + DISPATCHED` Browser WAL，重启后的新 Attempt 先执行 `attempt-replaced` 普通释放，被同一条未决 WAL 阻断 30 秒，随后两个任务以 `V6_DEADLINE_BUDGET_EXHAUSTED` 失败，形成业务停摆。

本方案是该 GAP 的唯一施工方案。它只替代《十小时连续运行事故分组根治－完整实现方案》第 6 节 G1 中“`WAIT_NEW_ATTEMPT` 释放成功后再恢复 Chrome”的旧设计；旧文档继续作为十小时事故历史记录，其余分组不受影响，不与本文并行施工。

本文状态为“施工中”，表示设计边界已冻结且正在对同一候选实施与验收；在 CI-FULL 出具唯一终局前，不表示 Chrome 生产实证、READY 或 RELEASE 已通过。

## 1. 需求、业务终点与范围

### 1.1 需求

在不放宽 Browser WAL 安全门、不删除事故记录、不增加守护服务、重试器、第二恢复链或兼容桥的前提下，实现：

- 已鉴权 Browser 通道因 Chrome 物理退出而终止后，系统立即调用现役宿主能力检查 Chrome 窗口；只有窗口数为零时才打开一个载入现役 Workbench URL 的 Chrome 窗口；
- Chrome 重新启动并沿现役自动配对恢复后，新 Attempt 能使用当前 Website grant 与新 writer fence，在唯一 Browser lane 内先原位结算同 job 的旧 `target_local` 未决 WAL，再继续正常 acquisition；
- 其它 job 在该旧 WAL 结算前仍不得越过，Provider effect 仍不得重放；
- 事故 WAL、`physical_input_count`、原 Target/Document/fence 和终态理由继续保留，禁止人工删除或降格为 `mutation_outcome=no`。

### 1.2 权威业务终点

本次修复的工程终点不是“Chrome 被打开”，而是：

```text
已鉴权 Browser 通道终止
  -> 宿主确认 Chrome 零窗口并打开一个 Workbench 窗口
  -> 固定扩展按现役路径重新配对
  -> Website 签发/维持合法执行授权
  -> 同 job 当前 production binding 在唯一 lane 原位终结旧 target_local WAL
  -> 当前 Attempt 正常执行
  -> Website admission + 领域对象持久化/readback
```

“打开 Chrome”和“旧 WAL 已结算”是恢复链的中间事实；最终业务完成仍以 Website 接受、持久领域对象及 readback 为准。

### 1.3 明确非目标

- 不修改 Website 仓库、Website 状态机、Attempt 签发规则或业务 admission；
- 不修改 Browser mutation 表结构，不迁移、删除、覆盖或手工终结事故行；
- 不放宽 `mayCrossUnresolved`，不允许普通 release、其它 job、fresh navigation、observation 或 mutation 越过未决 WAL；
- 不新增 Chrome watchdog、定时轮询、keeper tab、后台进程、第二 WebSocket、第二 lane、第二队列、第二 store、恢复 manager 或状态机；
- 不自动重放 Provider effect，不把 `DISPATCHED` 猜成未发生；
- 不处理 GPT 回答判停、Prompt、附件、重命名、业务结果入库等其它故障；
- 不在本方案设计阶段启动/关闭 Chrome、重启服务、重跑任务、写数据库、改法案、改代码或执行 CI。

## 3. 现役实现重建与第一直接断裂

本次采用深度但窄范围重建：故障同时命中宿主恢复、Browser authority 生命周期、唯一 lane、持久 WAL 和 Runtime Attempt 切换，必须闭合这条受影响图；不扩展到其它 Product/GPT/Website 业务。

### 3.1 现役宿主恢复能力已经存在

- `scripts/startup/lib/open-workbench-page.mjs::restoreWorkbenchWindowIfChromeHasNoWindow` 已通过 AppleScript 读取 Chrome 窗口：窗口存在时返回 `already_visible`，窗口为零或 Chrome 未运行时只打开一个载入 Workbench URL 的窗口；不创建额外 Tab；
- `src/app/server.ts` 已把该函数作为 `GrassEyeWorkbenchOptions.restoreBrowserHostVisibility` 注入；
- 固定扩展已有现役自动配对，不需要新增重连器。

结论：缺失的不是“如何打开 Chrome”，而是正确、可达的触发点。

### 3.2 旧触发点位于故障之后，形成循环依赖

当前路径是：

```text
Website WAIT_NEW_ATTEMPT
  -> Runtime releaseJobBoundTarget(wait-new-attempt)
  -> release 成功
  -> restoreBrowserHostVisibilityAfterRelease
```

但故障发生在 Browser command 已 `DISPATCHED`、Chrome 通道先退出的时刻。未决 WAL 会阻止普通 `wait-new-attempt` release，因此“release 成功后再打开 Chrome”依赖一个在浏览器退出现场无法先完成的动作。该路径没有观测 Chrome 物理退出，且触发点晚于恢复所需条件。

第一直接断裂一：`BrowserAuthorityWebSocket -> BrowserInfrastructureSupervisor.onRevoked` 已得到已鉴权通道的终止事实，却只撤销 workspace/target、拒绝 lane waiter 和记录失败，没有调用已存在的零窗口宿主恢复能力。

### 3.3 新 Attempt 被过时的预释放挡在现役恢复规则之前

当前 `runtime-claim.ts::executeClaim` 在 durable accept 新 Attempt 之前执行：

```text
prior failed attempt differs
  -> releaseJobBoundTarget(job, "attempt-replaced")
  -> acceptClaim
  -> Product 第一次 Browser acquire
```

而 `BrowserLaneCoordinator.nextWaiter` 在存在全局未决 WAL 时只允许：

- 同 job 的 current production acquire；
- 同 job 的 Website 永久撤权或管理员删除 release。

`attempt-replaced` 是普通 release，不能越过未决 WAL；其固定 30 秒预算先耗尽。于是新 Attempt 永远到不了 `pump()` 中已经存在的 `settleRetiredTargetLocal(waiter.binding)`。

第一直接断裂二：旧的 `attempt-replaced` 预释放位于 durable accept 和 current production acquire 之前，使现役合法 target-local 收尾入口不可达。

### 3.4 现役恢复规则本身正确，不应削弱

`LAW-LOCAL-BROWSER-SESSION-004-V43`、Browser Blueprint V49 和当前实现已经共同规定：

- 其它 job 与普通 release 不得越过任何未决 `DISPATCHED`；
- 只有 Website 当前有效 production grant、AGENT durable binding、同 job、全局唯一一条 `target_local`、旧 fence 已失效且当前 writer fence 不同，才能在任何新 acquisition 前把旧行原位结算为 `REJECTED + mutation_outcome=dispatched`；
- 原 `physical_input_count` 和 WAL 事实必须保留；
- provider effect 只能零输入读回，不能重放。

因此本方案不改 `mayCrossUnresolved`、`settleRetiredTargetLocal` 或数据库合同，只删除挡在它前面的旧 release。

## 5. Identity spine 与有限闭环分母

### 5.1 Identity spine

宿主恢复链只使用：

```text
authenticated Browser authority
  + connection generation
  + BROWSER_EXTENSION_CHANNEL_UNAVAILABLE
  + transportEvent(peer_close | tcp_close | tcp_error)
  -> OS Chrome window-count readback
```

WAL 收尾链只使用：

```text
job_id
  + old attempt_id / old execution_fence_hash
  + current Website grant
  + current durable attempt_id / writer_fence_hash
  + exact single unresolved target_local row
```

不得引入 recovery id、额外 ledger、窗口状态表、Attempt alias 或第二 effect identity。

### 5.2 有限分母

| 输入/分支 | 唯一 Owner | 决定与输出 | consumer/readback | 终态/回接 |
|---|---|---|---|---|
| 已鉴权 authority 因 transport close/error 终止，Chrome 零窗口 | Browser 检测；App Shell 执行宿主动作 | 调用一次现役 restore callback；打开一个 Workbench 窗口 | OS helper 返回；固定扩展现役配对事件 | authority 重新 PRESENT；正常主链继续 |
| 同上，但 Chrome 仍有窗口 | App Shell | helper 返回 `already_visible`，零动作 | 窗口数 readback | 保持 Browser absent/等待现役自动配对；不新增 Tab |
| 未鉴权/pending socket 关闭、认证帧非法、显式非 transport revoke | Browser | 不请求宿主恢复 | restore callback 调用增量为零 | 按原 typed failure 结束 |
| 宿主打开失败 | App Shell/Browser 日志 | 记录 `BROWSER_HOST_UNAVAILABLE`，不重试 | Browser authority 仍 absent，日志可读 | 人工处理后接回现役配对；任务不重放 |
| 新 Attempt，无未决 WAL | Runtime/Browser | durable accept 后按原路径执行；不再预释放 `attempt-replaced` | fresh Child/current Target typed readback | 正常 Website admission |
| 新 Attempt，唯一同 job 旧 `target_local`，旧/新 fence 不同 | Browser lane/WAL | acquire 获准穿过；先将旧行原位结算 `REJECTED + dispatched`，再 acquisition | SQLite 同 command_id 终态、原 physical count 保留；当前 precondition fresh readback | 当前 Attempt 继续 |
| 未决属于其它 job、多条/混合 scope、同 fence、非 production binding | Browser lane/WAL | 继续失败关闭 | 未决行不变、物理输入增量为零 | 等相应权威收尾；不得旁路 |
| 同 job `provider_effect + DISPATCHED/CONFIRMED` | Browser/GPT 现役 readback | 零 Provider 输入对账/读回；fresh 路径拒绝 | 同 effect WAL/结果 readback | 接回原 accepted effect；不 submit |
| Website 永久撤权或管理员删除 | Website + Browser | 保留现役两个精确 release 例外 | exact jobRefHash ack；WAL 审计保留 | 终止/删除闭环 |

## 6. 删除审判后的唯一目标链

```text
App Server 构造现役 restoreBrowserHostVisibility callback
  -> Workbench assembly 仅把同一 callback 注入 Browser supervisor
  -> 已鉴权 Browser authority 收到真实 transport terminal
  -> supervisor 先确认当时 authority=PRESENT、reason=CHANNEL_UNAVAILABLE、transportEvent 合法
  -> 撤销现役 Browser authority/workspace/target 并拒绝 waiter
  -> 异步调用一次 callback
  -> helper 读取 Chrome 窗口：有窗口零动作；零窗口打开一个 Workbench 窗口
  -> 固定扩展沿现役自动配对恢复

Website 新 Attempt
  -> Runtime fresh readback + durable accept
  -> 不再执行 attempt-replaced 预释放
  -> Product 第一次 current production acquire 进入唯一 Browser lane
  -> 现役 settleRetiredTargetLocal 原位终结旧 target_local WAL
  -> 现役 acquisition / fresh precondition / Product 流程
  -> Website admission + durable readback
```

这条链不增加持久状态、队列、定时器或公共恢复服务。

## 7. 原子施工工单

### IR-1：施工图纠偏并冻结唯一恢复时序

**Owner**：`local-browser-session` 与 `agent-production-runtime` 各自现役 Blueprint Owner。
**路径**：

- `docs/blueprints/local-browser-session/LOCAL-BROWSER-AUTO-PAIRING-AND-EXACT-CHATGPT-CLAIM-V2-BLUEPRINT.md`
- `docs/blueprints/xuanxue-ai-production/WEBSITE-AGENT-V6-BLUEPRINT.md`

**施工动作**：

1. Browser Blueprint 原位加入窄规则：只有当前已鉴权 authority 的 WebSocket 因 `BROWSER_EXTENSION_CHANNEL_UNAVAILABLE` 且来源为真实 transport terminal 时，才请求构造注入的宿主 callback；callback 必须先读 Chrome 窗口，有窗口零动作、零窗口只开一个 Workbench 窗口；它不进入 Browser lane、不读 WAL、不创建 Target、不重放任务。
2. Runtime Blueprint 物理删除“`WAIT_NEW_ATTEMPT` release 成功后恢复 Chrome”的段落，删除 Runtime 对该宿主动作的 Owner 表述。
3. Runtime/Browser Blueprint 删除把 `attempt-replaced` 作为新 Attempt 前置释放的表述；明确新 Attempt 先 durable accept，再由第一次 current production acquire 使用现役 target-local 收尾规则。
4. 保留普通 `wait-new-attempt` release、`business-admitted` release，以及 Website 永久撤权/管理员删除两个未决 WAL 例外；它们不承担 Chrome 退出恢复。
5. 不改法案版本，不手改 generated registry，不新增 Blueprint、dependency spec、合同版本或治理文件。

**完成门槛**：两个 Blueprint 对同一时序无冲突；全文搜索不再存在“release 后恢复 Chrome”或“新 Attempt 必须先 attempt-replaced release”的现役指令。

**失败停止**：若施工时发现 active law 明确要求 Runtime release 后才可恢复 Chrome，停止并回到设计；不得静默改法案。本次设计已核实当前法案没有该要求。

2. `BrowserInfrastructureSupervisor.onRevoked` 在撤销前读取 authority 是否为 `PRESENT`。只有同时满足以下条件才 fire-and-observe 一次 callback：
   - 撤销前是已鉴权 active authority；
   - `reasonCode === BROWSER_EXTENSION_CHANNEL_UNAVAILABLE`；
   - `refs.transportEvent` 精确属于 `peer_close | tcp_close | tcp_error`；
   - supervisor 仍处于 started 状态。
3. callback 自身继续以 OS 窗口 readback 作为最终动作门：窗口存在则零动作，窗口为零/Chrome 已退出才打开一个 Workbench 窗口。Browser 不猜测 Chrome 进程状态。
4. callback 失败只通过现役 Runtime Log 写入 typed `BROWSER_HOST_UNAVAILABLE`；不得 throw 回 transport close、不得改变 WAL、不得重试或排队。callback 成功不新增持久“恢复成功”状态；后续 `BROWSER_AUTH_PAIRING_COMPLETED/BROWSER_SOCKET_AUTHENTICATED` 是现役 readback。
5. 从 Runtime 物理删除：
   - `RuntimeState.restoreBrowserHostVisibility`；
   - `restoreBrowserHostVisibilityAfterRelease`；
   - `startProductionRuntime` 的对应输入和 `workbench.ts` 对 Runtime 的转发；
   - `runtime-claim.ts` 与 `runtime-business-admission.ts` 在 release 后调用恢复的分支；
   - 只为旧触发存在的 mock、断言和 import。
6. 不修改 `restoreWorkbenchWindowIfChromeHasNoWindow` 的零窗口语义，不新增定时重试；若现役 helper 测试已充分，只补调用链测试，不复制 helper。

**完成门槛**：全仓只有 App Shell 构造一个宿主 callback，只有 Browser 已鉴权 transport terminal 消费它；Runtime production 目录内 `restoreBrowserHostVisibility*` 引用为零；已有 Chrome 窗口时新增窗口/Tab 增量为零。

**失败停止/回接**：宿主动作失败后 Browser authority 保持 absent，任务保持现役 typed 失败；操作者修复 Chrome/扩展后由现役配对接回。绝不自动重放当前命令。

### IR-3：物理删除 `attempt-replaced` 预释放，恢复现役 WAL 收尾可达性

**Owner**：`agent-production-runtime` 决定本地执行顺序；`local-browser-session` 继续唯一拥有 WAL 收尾。
**允许修改路径**：

- `src/lib/local-runtime/production/runtime-claim.ts`
- `src/lib/browser/exact-target/browser-target-lease.ts`
- `scripts/acceptance/browser-lane-fifo.acceptance.ts`
- 对 `attempt-replaced` 的其它直接引用。

**施工动作**：

5. 保持新 Attempt 的 fresh/profile/model/menu/附件/Composer 等 target-local 准备由现役 Child 在 current Target/Document 重新验证和执行；删除预释放不允许继承旧 Attempt 的准备事实。

**完成门槛**：生产源码、类型、Blueprint 和测试中 `attempt-replaced` 为零；同 job 新 production acquire 能使唯一旧 target-local 行原位到达 `REJECTED + mutation_outcome=dispatched + BROWSER_TARGET_LOCAL_EXECUTION_RETIRED`，原 command_id、physical count 和审计事实不变；其它 job 仍被阻断。

**失败停止**：若未决是 provider effect、多条、跨 job、同 fence或身份不一致，现役 Browser 必须保持未决并 typed fail-close；禁止为了“继续运行”放宽门禁或删除记录。

## 8. 分层验收

### 8.1 静态与确定性验收

- 法案文件与 generated registry 零差异；
- 两份 Blueprint 与代码时序一致；
- Runtime production 目录不再拥有 Chrome 可见性恢复 callback 或调用；
- `attempt-replaced` 全仓零生产消费者、零类型字面量、零测试豁免；
- `BrowserLaneCoordinator` 仍只有一条 queue、一个 active owner、一个 WAL gate；普通 release 例外没有增加；
- 无新增表、列、迁移、持久状态、timer、service、manager、watchdog、keeper tab 或第二 Browser 路径。

### 8.2 本地动态故障注入验收

使用受控 fixture，而非真实 Provider 写入，证明：

1. authenticated socket terminal -> callback；
2. callback 已有窗口 no-op / 零窗口 single-open；
3. extension 重新认证后 Browser authority 恢复 PRESENT；
4. 同 job 当前 binding 原位结算旧 target-local 行；
5. 新 Attempt 的第一次 acquisition 和 fresh precondition 可达；
6. unrelated job 在 settlement 前不能穿越；
7. Provider physical input 增量为零。

### 8.3 用户重启后的真实 Chrome 验收

另获用户授权后，使用一个明确测试 job 执行一次受控物理故障：

1. 记录候选 commit、job/attempt/result revision、command_id、Target/Document、writer fence 和 Chrome 窗口数；
2. 用户完整退出 Chrome；
3. 日志必须先出现该 authority 的 `BROWSER_EXTENSION_CHANNEL_UNAVAILABLE`，随后 Chrome 只恢复一个 Workbench 窗口，扩展沿现役路径重新认证；
4. 不人工删除或修改 WAL；Website 合法授权到达后，同 command_id 原位读回 `REJECTED + dispatched + BROWSER_TARGET_LOCAL_EXECUTION_RETIRED`，原 physical count 保留；
5. 同 job 后续执行恢复，至少一个受事故阻断的任务抵达 Website admission 与领域对象 readback；
6. 其它 job 不再连续出现由该旧 WAL 导致的 30 秒 `V6_DEADLINE_BUDGET_EXHAUSTED`；
7. Provider submit count 没有因恢复增加。

仅“Chrome 打开了”不能判定完成；仅 quality PASS 也不能判定真实故障已闭环。

## 10. 删除反事实

| 候选结构 | 当前必要性与消费者 | 删除后的具体失败 | 裁决 |
|---|---|---|---|
| 现役 `restoreWorkbenchWindowIfChromeHasNoWindow` | App Shell 已有真实消费者；提供唯一 OS 零窗口 readback/action | 无法在确认零窗口后启动 Chrome | 保留并直接复用 |
| Supervisor 中一次性 callback 消费 | 唯一能同时知道“此前已鉴权”与“真实 transport terminal”的现役位置 | 浏览器退出仍无人触发已有宿主能力 | 在现有 Owner 原位增加调用，不建新层 |
| 现役 automatic pairing | Chrome 打开后唯一认证回接 | 只能开窗口，Browser authority 仍 absent | 保留，不修改 |
| 现役 WAL 与 `settleRetiredTargetLocal` | 保护现实动作 at-most-once并原位终结事故行 | 要么死锁，要么只能危险删除/重放 | 保留，不放宽 |
| Runtime release 后恢复链 | 无法处理 release 前的 Chrome 退出，且制造循环依赖 | 删除后目标链仍由通道终止触发完整闭合 | 物理删除 |
| `attempt-replaced` 预释放及 authority literal | 被未决 WAL 阻断；现役 fresh Child 与 current production acquire 已承担真实需要 | 删除后新 Attempt 反而可到达合法 settlement；无验收缺口 | 物理删除 |
| 新 watchdog/timer/retry/service | 无当前必要性；无独立消费者 | 删除后一次 transport trigger + 自动配对仍闭合 | 禁止新增 |
| 新恢复表/状态/ledger | WAL、authority 状态和 OS readback 已提供全部必要事实 | 删除后无身份或 readback 缺口 | 禁止新增 |
| 放宽 `mayCrossUnresolved` | 会允许普通 release/其它 job越过未知现实动作 | 不是修复而是破坏安全门 | 禁止修改 |
| 人工删除事故 WAL | 会销毁事故证据并掩盖 unknown effect | 现役 settlement 已能安全原位终结 | 禁止 |

删除上述三条旧/假设路径后，有限分母所有分支仍有 Owner、终态和 readback，因此它们不能进入方案。
