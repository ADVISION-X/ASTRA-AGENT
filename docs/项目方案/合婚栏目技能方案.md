## 5. 两份 Skill 的产品语义

### 5.1 `hehun-ai-analysis/SKILL.md`

要：

- 把命盘锁定事实、READY 古籍/规则、用户原问题、私人底稿先验、关系终稿推断分层；

- 清楚写不确定性、边界与安全说明；
- 私人底稿只是非约束内部先验，终稿必须重新核对双方锁定事实与完整 READY，可纠正或拒绝底稿；

不要：

- 合婚分数、百分比、“一定结婚/离婚/出轨”等确定性结论；
- 把命理推断写成事实，把任一底稿原文、内部 marker/artifact/ref/hash 泄露给用户；

- 写 Flow、actionOrdinal、DOM、schema、profile 或重试策略；
- 在 private-base turn 注入这份 Product Skill。

## 8. HH02 私人底稿 exact identity 与 singleflight

### 8.1 reusable identity

每一方 identity 精确闭包：

`owner_scope_hash + privacy_subject_ref + party_role + party_subject_ref + chart_ref/version/hash/candidate_set_hash + private_base_contract_version/hash + canonical_provider_identity/version + private_base_profile_hash + private_base_evaluator_hash + complete_READY_corpus_set/hash + purpose_scope`

### 8.2 唯一持久化方式

本 AUTHORITY-PENDING/NO-GO 方案不得把 private base、reservation、`product_internal` admission、artifact grant 或 Hehun branch 塞进现役 GPT continuation；也不得新建 `hehun_private_bases`、缓存表、base queue、base API、latest 查询、第二 store 或兼容路径。未来若要引入这些责任，必须先单独修改并升版法案、Blueprint、合同和验收。

## 10. 机械隐私与 source proof

当前模型输出类型注释声称系统会追加 privacy/source proof，但 canonical final report 实际没有该对象，这是 P0 GAP。证明必须先于 Website 领域接纳产生，完整链只有一条：

1. Product 在 A/B private semantic output 中扣除 `relationship_input` 已含的共享 locked facts/READY canonical spans，得到 private-only taint denominator；
2. canonical proof contract 固定 `hehun-private-span-denominator.v1`：文本先 NFC，CRLF/CR→LF，保留LF层级而将其余Unicode White_Space连续段折为一个U+0020；按空行切paragraph，再按保留分隔符的`。！？!?；;\n`切sentence；对扣除以同算法从relationship locked facts/READY生成的共享span后的每个private-only unit，枚举完整unit及每个8/16/32 Unicode scalar滑窗，纯空白/标点窗丢弃；base-only structural keys、internal refs/markers不受最短长度限制并作为exact unit进入；每项按`SHA256("hehun-private-span-v1\\0" + scalar_length + "\\0" + UTF8(bytes))`，小写hex字典序去重排序，并用项目现役 canonical-JSON serializer 编码为唯一字符串数组 bytes。完整set要求`1 <= count <= 16384`且`max_canonical_bytes=2097152`；set hash为该UTF-8 bytes的SHA-256；Merkle leaf=`SHA256(0x00 || raw32(span_hash))`，parent=`SHA256(0x01 || left || right)`，奇数层复制末叶，唯一根为root。空set或任一上限超出都在relationship/followup mutation前分别以`HEHUN_PRIVATE_TAINT_DENOMINATOR_EMPTY/OVERFLOW`失败关闭，严禁 truncate、sample、前N项或降粒度；原文只留AGENT observed-response artifact，不进transport；
3. Product 对 relationship 的 raw semantic text 与 normalized output 做同一 canonical span hashing，要求与 private-only set 交集为零；这只证明没有直接私有字节/片段泄漏，不冒充证明“没有语义影响”；
4. Product 生成 system-only `HehunPrivateExecutionProofV1` sidecar，绑定 A/B identity/artifact/admission commitment、role-isolation/READY receipt hash、canonical taint commitment set bytes/hash/root/count、scan algorithm/version/result、relationship raw/normalized hash、execution binding 与 proof hash；不含 Skill/Prompt/Profile/private raw bytes；
5. V6 现有结果 envelope 以产品中性的 `product_execution_proof` ref/hash/bytes 随同一 result/outbox 运输；共享 transport 只验 bytes/hash/type，不解析 Hehun；不新建 queue/store/result truth；
6. Website staging 只做 envelope 与 proof bytes/hash 可读性机械验收；
7. Website Hehun domain 先核 proof binding、zero-hit、current consent、canonical final contract，再生成 `HehunPrivateSourceProofV1` 与 domain admission receipt；两者同时绑定 final raw/normalized hash 和 Product proof hash；
8. canonical report 纳入 system-only privacy proof hash，用户 HTML/PDF/JSON 只从明确 allowlist 构造，禁止 spread canonical report/base 对象。

Forensics denominator receipt 必须绑定 A/B exact semantic artifact ref/hash、tokenizer/span 算法、完整 set bytes/hash/root/count 与上限裁决。因为它由两次独立 checkpoint 共同派生，必须以完全相同 canonical receipt bytes 分别追加到 A 与 B 两个 exact checkpoint call identity 的受控 derived-artifact suffix，读回两份 ref/hash/bytes 全等后才可继续；不得把双来源塞进一个虚构 call identity。检测到任一侧缺失/不等、marker/ref/structural key/taint span 任一命中、denominator 为零但存在 private output、删任一元素、超限、截断/采样、重复/重排、set-hash/root不等、私有子句部分复制、proof 缺失或绑定漂移，必须领域拒收，Delivery Manifest 不得签发。HH03 还须先证明继承 set 与 parent terminal receipt 全等，再扫描本轮全部新 raw/normalized spans。共同 chart/classical facts允许通过 final relationship output重新表达。

## 14. 失败、恢复与公开状态

### 14.1 二元状态

公开任务状态只允许 `failed | completed`：

- 初始：`failed + current_reason=AWAITING_FIRST_ATTEMPT`；
- `failed` 对用户只表示“尚未交付”，安全投影为“处理中/正在恢复/需要重新授权”，不显示技术终态；
- `completed` 必须绑定 §13 两层 receipt；不存在 `completed + delivery=verifying`；
- `queued/assembling_input/running/blocked/recovery_pending` 退出 public/domain truth，位置只进 `current_reason`、lease、artifact 或 consumer receipt。

`accepted_attempt_count` 只作遥测与有限退避。删除 HH02 `max_attempts=3`、`attempt_count < max_attempts` 放行和按错误字符串判永久失败。

### 14.2 恢复原则

- 第一次真实外部 Child failure 形成不可变 attempt_failure；typed code/cause/mutation/effect/Child/Browser outcome/evidence 原样跨仓；
- confirmed submit 由 exact WAL+Forensics receipt 决定，任何后续只读错误码/超时不得降格或重发；
- A/B complete base 跨 task 只读复用；incomplete reservation 只由原 creator/effect 收束；
- relationship complete continuation 使接收器/consumer 崩溃后零重复 final turn；
- HH03 acquire 后所有非 advance 出口必 release；format grant 返回后重新 acquire/focus/verify；advance 前已有 durable pending-result receipt，advance commit 后至 `context.complete` 之间的崩溃只从原 receipt 恢复，零二次 turn/advance；
- staged raw/result 已存在时，domain/commercial/UI 故障从原 artifact 继续，不重做 Provider；
- 只有 Website 明确撤销 consent/authorization/cancel 可停止新业务动作；旧证据、报告、receipt 不删除。

### 14.3 consent 撤销传播

Website consent Owner 撤销任一方 purpose consent 时，唯一 transaction 只协调四个单对象 typed writer：authorization epoch、job-control `requestPauseWithClient`、active private/review/parent grant set revoke、active-task `current_reason`；各自锁/写/readback后才签一张业务 revocation receipt。transaction 不复制任何 repository SQL，job-control operation不理解合婚/consent。已交付历史对象只撤 active access/grant，不删除 bytes/receipt。禁止虚构 `STOP_NEW_PROVIDER_ACTIONS` 或第二控制表。

经 A-012..A-015 的双仓 authority 闭合后，AGENT Runtime 独占 control consumption。authority transport 只有一条：Website `v6-contract.ts:ControlIntentV6/assertControlIntentV6` → canonical V6 manifest 内机器可读 current-control schema → 唯一 generator 把字段/类型/枚举/约束投进 AGENT dependency spec → `v6-manifest-projection.ts` 机械验证并供 `transport-protocol.ts:ControlIntentSchema` 构造或全字段等值校验；Website `project/readAiProductionDeviceJobStatusV6` 是 current control 只读 Owner，AGENT `parseDeviceControlAuthority/readProductionDeviceJobStatus` 把 `intent/control_epoch/job/lease/fence/reauthorization_receipt_ref` 注入 Runtime-only `readCurrentControl` closure，Product 永远看不到。只投影总 manifest hash 不足以证明字段 shape；heartbeat 只证明活性，绝不代替 current read。

`MutatingChildSiteDenominatorV1` 不手写固定个数，也不把动态 identity 伪装成可预枚举静态集合。它从六 route 的真实 Flow call-site template、GPT canonical mutation classification 与 Browser `committedMutation` fact 机械生成，覆盖 profile open/close、prepare、单次 batch attachment、write/submit、产生 navigate mutation 的 conversation focus，以及 persist/reserve/complete/acquire/advance/release 等 session mutation；format branch 以 `format_generation/call/actionOrdinal/inputHash` 参数化同一 site template。附件按真实一次 batch Child 计，不按材料名虚拆；未被六 route 调用的 capability 不进入 site 分母。

唯一门精确安装在 `ProductionGptChildTools.executeOne` 进入 `this.gpt.execute`/Browser 原子 dispatch 之前，并覆盖 session mutation dispatch。每次实时调用都先按 canonical mutation classification 与 Browser `committedMutation` 判定；只要该次调用是 mutation，就必须 fresh read current control，绝不以“动态 identity 是否出现在静态 set”作为放行条件。网络失败、epoch回退、job/lease/fence/reauthorization receipt不等或 intent 非`none`，新 Provider/Browser/session mutation均为零。唯一例外是已 acquire 同job/exact lane 的幂等 `release` 清理：它不得产生Provider/Browser effect，只按原lane/version/fence执行一次并readback release receipt；已 DISPATCHED/CONFIRMED effect 仍只允许 exact read-only reconcile。Product 只收到 typed abort；读取 private bytes 前另验 Website 业务 read grant。

双方重新授权时，Website 只可对同一原 task/job 做 `reauthorizeSameHehunJob` 事务：读回两份新 current consent 与原 pause receipt，重新调用唯一 authorization-epoch writer 生成新 epoch，调用单对象 writer 创建全新 private/review/parent grant set、调用 job-control 唯一 mechanical CAS 绑定该新 epoch、递增现役 `control_epoch`并把同一 row 恢复为 `none`、调用 task writer 恢复`current_reason`，最后签唯一receipt。没有该 authority、receipt 或 exact same-job binding 就保持暂停；禁止 replacement task/job、Product 自行复权或把旧 grant 重新启用。

## 15. 不可变纠错

现状缺合婚纠错主链，且现役共享 Commercial 合同与数据库同时有三道真实阻断：Manifest 的 `order_id/entitlement_id/fulfillment_intent_id` 唯一且整行禁止 UPDATE/DELETE；普通 entitlement 的 grant-basis 全局唯一；primary result link 按 order 全局唯一。因此“只新建 fulfillment”或“给 Manifest 加可变 status”都不可施工。必须先由 Commercial law Owner 接纳唯一方案，再在现有 Hehun domain/commercial family 内原子补齐，不新增 AGENT action，也不默认新增 correction service/ledger：

1. Web 与 internal service 使用同一 canonical pathname `POST /api/hehun/reports/:reportId/corrections`；security IDs 分别是 `web.hehun.reports.corrections.create` 与 `hehun.reports.corrections.create.internal`，`subject_kind=hehun_report`、`request_body_limit=4096`，Web=session+same-origin+CSRF，internal=workload+socket；现有 Hehun security denominator 从 12 精确增至 14。它们不属于六条 AGENT AI routes，也不新增 Product Skill；
2. Web route 只核 user-session report owner 后按原 body/idempotency key 调现役通用 `proxyHehunApi` 一次转发，禁止新增 `forwardHehunCorrection` helper；`hehun-runtime-handler.ts` 只新增 `HehunMutationKind=create_report_correction` 的 exact pathname match，`executeHehunRouteMutation` 仍只保留幂等 transaction wrapper，绝不拥有 correction 业务；
3. canonical `HehunCorrectionRecordV1` 固定 `correction_id/original_report_ref/original_manifest_hash/original_case_hash/actor_ref/reason_ref/reason_hash/idempotency_key/successor_task_ref/successor_subject_bundle_ref/successor_entitlement_ref/successor_fulfillment_ref/successor_manifest_ref/status/accepted_receipt_hash/completed_receipt_hash/created_at`；`status` 只允许 `pending | completed`，同原报告+幂等键唯一；

6. `packages/commercial-contracts/src/delivery-manifest.ts` 只保留一个 canonical 显式版本联合与两个 exact validator：历史/普通新交付由行级 `manifest_record_version=v1` 路由到原 shape validator，correction successor 由 `v2` 路由到要求 `manifest_schema_version='verified-delivery-manifest-v2'` 与 non-null predecessor ref 的 V2 validator；共享 row reader 先读行级版本再分派，禁止按 JSON 可选字段存在性猜版本。Manifest 行与 `record_json/hash/results` 永不更新，“当前交付”只由唯一 successor 链尾与 active result links 读回派生；`delivery-completion.ts` 的同一 Owner 新增 typed successor 入口，只接受新 subject bundle、新 inherited entitlement、inheritance receipt、新 fulfillment/outbox；

8. `executeCorrectionTransaction` 是唯一 accepted 事务协调者：锁 exact 原 case/chart/report/manifest/order、actor、reason 与 idempotency，依次调用上述 typed operations 并提交一张 `HehunCorrectionAcceptedReceiptV1`。合法中间态是“旧 grants 已撤、原 Manifest 字节不变、新 successor pending”；事务失败全部回滚；

10. successor 完成时，同一 Commercial SQL 事务先锁原链尾及 active result links，核 new bundle/entitlement/inheritance/fulfillment，写旧 links `active→superseded` 及 event，再插入不可变 V2 Manifest 与新 active links并完成 successor fulfillment，读回“原 Manifest 仍不可变历史、新 V2 是唯一链尾、新 links 唯一 active”；随后 correction repository 才以 accepted receipt+successor Manifest hash 单向 completed 并签 receipt。任何并发、唯一约束、event 或 readback 失败整笔 rollback；
11. canonical shared builder/reader、全部 product adapters、Manifest/result readers、下载/UI 授权和 Qimen 既存纠错消费者都必须进入 V1/V2 分母与回归；普通新交付仍产 V1，历史 V1 原字节可读，不能用 Hehun 测试替代全消费者证明；
12. UI 从同一 accepted/completed receipt chain 和 canonical current-chain-tail reader 展示原版本历史、successor pending/current、继承凭证与原因，不拼两套 active truth。

不要创建 `hehun_correction` Product/Skill/route、默认新增 `hehun-correction-service.ts` 或 `hehun-commercial-correction.ts`，除非施工时证明现有 mutation/commercial consumer 无法承载且先获得新增对象授权；不要把技术失败包装成业务纠错，不让 review 自动撤销商业交付。

### 18.3 迁移不变量

- 迁移前后原 task/job/result/artifact/continuation/receipt identity 不变；
- `legacy_persisted_count = migrated_persisted_count`，persisted identity/provider/checkpoint hash multiset完全相等；
- `pre_completed_reservation_count = post_completed_reservation_count`，其identity/artifact/admission/grant hash multiset完全相等；
- `pre_incomplete_reservation_count = post_incomplete_reservation_count`，creator/fence/effect/lane集合完全相等且全部有recovery-or-hold disposition；
- `pre_task_count = post_task_count`，captured result hash、domain receipt、Manifest 与 review plan 的已存在集合不减少；新增只允许 migration/cutover receipt；
- HH02与HH03分别满足`pre_legacy_status_count/hash = post_binary_status_disposition_count/hash`，每行都有effect bucket、current_reason与唯一recovery/consumer/hold去向，未裁决=0；
- 不删除已 captured Provider output，不把旧 strict receiver failure 当 Provider failure；
- 不为旧结果补造 private-base proof；`historically_admitted`按旧version receipt守恒，未接纳旧结果缺proof就不晋升vNext completed；
- 不用新 task 接替技术失败的旧 task；只有用户发起的业务纠错产生 successor；
- 不在 drain 时全局停机，只隔离 Hehun fault slice；
- migration/切换/rollback 都没有第二 active route：数据库 mismatch 在 rename 前整笔 rollback；代码切换后 rollback 只能回到 fail-closed，不回到旧 Provider Flow。
