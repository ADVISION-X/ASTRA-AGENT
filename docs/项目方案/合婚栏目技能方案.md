## 0. 最终设计裁决

### 0.1 唯一允许的产品结构

合婚栏目只保留现有三个产品、两个 Product Plugin、两份 Product Skill：

| 产品 | 类型 | 唯一 Owner | Provider 形态 |
|---|---|---|---|
| HH01 `hehun_case_preparation` | Website 确定性产品 | Website Hehun | 零 AGENT、零 Provider |
| HH02 `hehun_ai_analysis` | AI 产品 | AGENT `hehun-ai-analysis` | 一个 Website job 的一个 fresh Provider turn |
| HH03 `hehun_report_followup` | AI 产品 | AGENT `hehun-report-followup` | 每个续问是一个新 Website job、一个 fresh Provider turn |

每个 Plugin 继续拥有三条现役 route：primary、`accuracy_challenge`、`quality_reflection`。不新增合婚总 Plugin、甲方 Plugin、乙方 Plugin、review Plugin、共享合婚执行器或第二调度链。

第 14 个能力的名称、Owner 与失败语义全部冻结：当前合婚短名映射为 `hehun_ai_analysis → 合婚分析`、`hehun_report_followup → 合婚追问`，标题机械投影为 `MMDD·项目短名·aiprod_<job UUID前八位>`。它只使用 confirmed effect 的 `terminalAt`（`Asia/Dubai`）、当前 canonical conversation URL、job 与 product identity；返回 `already-exact|renamed`，物理输入只能是 `0|4`。invalid、missing、ambiguous、stale、timeout、transport unknown、预算不足或 proof/log failure 全部只能产生 `impact=CLEANUP` 并继续原 park；标题不得参与 Target 选择、提交、恢复、result revision、Product payload、Outbox、Website admission 或完成裁决。

因此合婚施工对第 14 个能力的唯一合法动作是只读核对：registry 总数恰好 14、Product facade 恰好排除它、两个 Hehun Plugin 调用数为 0、核心生产 caller 恰好一个、cleanup 任意结果不改变业务结果。禁止为合婚新增重命名 wrapper、显式调用、重试、回扫、queue、table、worker、ledger、fallback、第二 Browser lane 或标题驱动恢复。

### 0.4 为什么旧方案作废

旧方案的 305 个动作把以下不存在或被现役法案禁止的结构当成主干：private-base reservation、continuation store、lane/CAS、derived-artifact facade、Runtime dispatch control、跨 attempt 阶段恢复、Hehun proof projection。它既会侵入已经跑通 SEO 的共享链，也与当前候选 `LAW-AGENT-PRODUCTION-RUNTIME-001-V59`、`LAW-GPT-001-V51` 和 GPT V48 施工图冲突。

本版全部删除。删除后不损失当前合法能力：现有两个 Hehun Plugin 已能用现役能力完成单次 fresh turn，Website 已有输入构建、V6 job、结果 consumer、报告存储、HTML/PDF/JSON 与 Commercial Delivery Manifest 主链。

4. 冻结 HH02 为“一张 Website job、一个 fresh Provider turn、完整双方锁定材料、一份最终关系报告”；
5. 保留双身份、双命盘、双 consent、完整 READY corpus、完整问题覆盖、双层表达、引用、无打分、无宿命保证与隐私输出边界；

7. 保持 HH03 fresh job、exact active HH02父报告 locked-fact material与immutable successor correction；HH03递归续问没有本轮需求和现役代码消费者，明确不纳入本方案；

## 6. Product Skill 定稿

### 6.1 `hehun-ai-analysis/SKILL.md`

Skill 只保存专业语义，不保存执行步骤、Child 名称、action ordinal、重试、恢复、schema 字段清单或 DOM 规则。

必须写清：

1. 当前输入是一份 Website 已授权、身份与问题冻结的双人案卷；Skill 不复核购买资格。
2. 分别核对 Party A 与 Party B 的命盘事实、稳定倾向、需求、优势、压力和不确定性，再分析互动、互补、冲突、现实条件、时序、支持与反证。
3. 甲乙顺序是业务身份，不得互换；不得增加第三人、补造关系经历或把一方事实归到另一方。
4. 古籍引用必须来自当前 READY corpus，并与具体判断相连；冲突与候选差异必须保留。
5. 所有冻结问题单位必须被覆盖；专业层与白话层结论、条件、时序和不确定性一致。
6. 禁止关系打分、排名、固定等级、宿命保证、操控/监视/强迫建议，以及冒充医疗、心理、法律、财务专业判断。
7. 只输出最终关系报告；不得输出内部推理、A/B 私有底稿、执行身份或第二份结果。
8. review 动作只返回 finding，不改写报告、不替 Website 裁决。

必须删除现役 Skill 中“甲方私有分析／乙方私有分析／最终判断服从私有分析”等会重新引入 private-base 语义的句子；替换为“单次正式分析中先分别核对双方，再形成唯一关系结论”。

### 6.2 `hehun-report-followup/SKILL.md`

必须写清：

1. 只消费本轮 Website 下发的 exact parent report、parent hash、双人案卷身份和新问题。
2. 只回答新问题；可以解释、限定或纠正父报告，但不得静默覆盖父节点。
3. 人物、命盘、consent、父报告或关系对象变化时拒绝续问，交回 Website 创建新业务任务。
4. 不读取或引用不存在的 A/B 私有底稿，不续接 Provider conversation。
5. 不复述整份父报告、不生成第二份 HH02、不增加新人物。
6. 保留证据、反证、适用条件、时序、不确定性与现实安全边界。
7. review 动作只审当前 followup，不改父报告、当前结果或 Website 裁决。

### 6.4 Website 机械来源与最小隐私投影 proof

`LAW-HEHUN-004/008` 不因单-turn而删除。来源、批准材料、raw result 与执行身份继续由现役 `agent_execution + envelope + anchor_registry + coverage_proof + capacity_proof` 唯一证明，不复制第二套 source proof。唯一最小新对象只允许是 canonical Hehun report 内的投影 proof，不进入模型输出、AGENT、Runtime或用户正文：

```text
HehunPrivacyProjectionProofV1
- schema_version = hehun-privacy-projection-proof.v1
- canonical_body_hash                        # report_ref/envelope/report_hash写入前、通过唯一validator的body
- projection_policy_ref + projection_policy_hash
- proof_hash                                 # 只hash前三项，明确排除proof_hash自身
```

唯一 producer 是 Website Hehun canonical finalizer；唯一业务 consumer 是 Website Hehun delivery gate；审计 consumer 是现役 Hehun Exam。构造顺序固定为：canonical body hash → projection policy hash → proof hash → 把proof并入pre-final report → 按现役算法生成report hash/ref；proof不引用envelope、report hash/ref、artifact或自身，因此无环。renderer核canonical body与projection policy，只把白名单 `HehunUserReportProjection` 序列化到HTML/PDF/浏览器JSON。A/B中间artifact不存在由producer/consumer静态枚举证明，prompt/DOM/URL/raw bundle不外泄由projection allowlist与负向mutant证明。任一hash或policy不等时，报告可留作失败证据，但交付、Manifest与admission增量必须为0。不得改通用 `XuanxueAiReportTerminalProofV1`，不得新增表。

### 6.5 只借鉴本地化的工单法，不复制产品结构

本方案借鉴现役本地化施工的四点：canonical Website producer、Product只生产候选、Website admission才算完成、每张ACT都绑定EVD与负向后置。只复用这种handoff和工单表达。
