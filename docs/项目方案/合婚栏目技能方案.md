## 6. HH03祖先、冻结及恢复

新HH03仅从用户选择的exact direct-parent manifest定位父canonical报告。父可以HH02或HH03；每个节点验证persisted canonical report/hash、verified商业manifest、completed领域receipt及V6 job/result binding。沿direct-parent反向读取，visited检测循环；到达唯一HH02 root停止，再反向生成有序history。禁止吸入sibling、同case别根、最新任务或时间排序近邻；断parent、跨case、重复节点、多root、hash错在job签发前失败。

resolved contract v2包含：root完整报告正文恰好一次及ref/hash；ordered prior HH03 history每个节点question原文/hash+完整answer/ref/hash恰好一次；direct-parent仅ref/hash及accepted V6 parent triple，不重复正文（父为root时history为空，父为HH03时其正文仅在history末节点）、真实case/ref/hash、两方root绑定的BZ01/BZ05材料、原chart consent及owned_selection/external scope consent、current question及原始输入、history_hash、bundle_hash。root是唯一来源选择真相；每轮重验current资格但不替换root旧BZ05为较新报告。历史只读不代表新任务资格。root是旧协议缺双BZ05的报告不能开启本次新v2追问，提示重新完整准入生成root；不建旧/新material双reader。

subject_bundle identity与task record/input object须一致；task_id仍来自唯一fulfillment+parent身份。新任务先在现役`hehun_followup_tasks.record_json`固定input ref/hash及ordered immutable source locator身份（不存第二份完整resolved正文）；对象IO在长事务外按现役条件写与GET/hash验证；短事务精确CAS从同一冻结记录创建唯一V6 job/material并关联任务。崩溃后已有task必须读原input，而非重新读current问题或祖先组装新hash；输入存在但job未联结则同身份幂等补齐，不新造任务/状态/队列。queued locator已存而对象尚不存在时，只能从这些immutable locator和原SubjectBundle原始问题重建同一bytes/hash；assembled_at等身份字段由首次task固定，不能重取当前时钟。必须与task预期input hash相等，缺对象/来源则同需求typed可恢复失败；不重新选报告或永久丢弃paid demand。生产job创建和task linkage必须在同一数据库client事务，未知回复读回job/task而不重签。
