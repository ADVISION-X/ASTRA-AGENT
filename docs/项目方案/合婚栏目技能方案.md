## 5. 两份 Skill 的产品语义

### 5.1 `hehun-ai-analysis/SKILL.md`

要：

- 把命盘锁定事实、READY 古籍/规则、用户原问题、私人底稿先验、关系终稿推断分层；

- 清楚写不确定性、边界与安全说明；

不要：

- 合婚分数、百分比、“一定结婚/离婚/出轨”等确定性结论；
- 把命理推断写成事实，把任一底稿原文、内部 marker/artifact/ref/hash 泄露给用户；

## 10. 机械隐私与 source proof

当前模型输出类型注释声称系统会追加 privacy/source proof，但 canonical final report 实际没有该对象，这是 P0 GAP。Website domain 必须新增且只在系统侧生成 `hehun-private-source-proof.v1`，绑定：

- A/B base identity hash、artifact hash、semantic-admission receipt hash；
- A/B role-isolation material receipt 与完整 READY set hash；
- relationship input/result contract/prompt/raw output hash；
- Product profile/Skill/turn-contract hash；
- public projection allowlist version/hash；
- internal-only structural keys、artifact refs、sentinel/token 的 leak scan version、scan denominator、zero-hit receipt；
- proof hash。

## 14. 失败、恢复与公开状态

### 14.1 二元状态

公开任务状态只允许 `failed | completed`：

- 初始：`failed + current_reason=AWAITING_FIRST_ATTEMPT`；
- `failed` 对用户只表示“尚未交付”，安全投影为“处理中/正在恢复/需要重新授权”，不显示技术终态；
- `completed` 必须绑定 §13 两层 receipt；不存在 `completed + delivery=verifying`；
- `queued/assembling_input/running/blocked/recovery_pending` 退出 public/domain truth，位置只进 `current_reason`、lease、artifact 或 consumer receipt。

`accepted_attempt_count` 只作遥测与有限退避。删除 HH02 `max_attempts=3`、`attempt_count < max_attempts` 放行和按错误字符串判永久失败。

### 14.2 恢复原则

- 第一次真实外部 Child failure 形成不可变 attempt_failure；typed code/cause/mutation/effect/Child/Browser outcome/evidence 原样跨仓；
- confirmed submit 由 exact WAL+Forensics receipt 决定，任何后续只读错误码/超时不得降格或重发；
- A/B complete base 跨 task 只读复用；incomplete reservation 只由原 creator/effect 收束；
- relationship complete continuation 使接收器/consumer 崩溃后零重复 final turn；
- HH03 acquire 后所有非 advance 出口必 release，advance commit-before-return 幂等读回；
- staged raw/result 已存在时，domain/commercial/UI 故障从原 artifact 继续，不重做 Provider；
- 只有 Website 明确撤销 consent/authorization/cancel 可停止新业务动作；旧证据、报告、receipt 不删除。

## 15. 不可变纠错

现状缺合婚纠错主链，必须由 Website 原位补齐，不新增 AGENT action：

1. correction Owner 接受 exact 原 case/chart/report/manifest 与原因；
2. 创建新 chart/case/subject bundle/entitlement/fulfillment/task successor，原对象不改；
3. 原 active result/download grants 原子变 `superseded/revoked`，留下 correction receipt；
4. 新 HH02 仍走普通 `hehun_ai_analysis/produce`；未变化一方只有 exact base identity 全等才可零调用复用，变化一方必须新 base；
5. 旧 parent 上禁止新 HH03；历史报告仍可审计但不再 active delivery；
6. 新报告/Manifest 绑定 `successor_of`，不覆盖原 report、consent 或 parent node。

不要创建 `hehun_correction` Product/Skill/route，不把技术失败包装成业务纠错，不让 review 自动撤销商业交付。
