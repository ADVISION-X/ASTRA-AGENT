## 3. 唯一 Owner 与终态

| 事项 | 唯一 Owner | 边界 |
|---|---|---|
| 业务任务、材料/结果合同、公开状态、领域入库与发布 | Website | 冻结完整输入、验证结果并签发 admission receipt；不下发 Prompt、模型、Child 顺序或恢复分支 |
| 动态翻译/review 语义、Prompt、模型、Child 顺序、恢复与结果组装 | `localization-production` | 同一个 Plugin 用静态 TypeScript 直接拥有六条 route；不产生第二 Product/Flow |
| 原子页面语义动作 | GPT Capability | 一次请求执行一个原子 Child；不决定 Product 下一步 |
| Target/Document、物理 mutation、WAL 与对账 | Browser Authority | 只返回受控事实/proof；Product 不接触 selector、tab 或 WAL row |
| claim、lease、fence、材料授权、staged result、Outbox | shared runtime | 只运输与安全；不理解本地化、不调度业务 Flow |
| exact-call evidence | Forensics Persistence | 唯一 evidence append/readback；不裁决业务完成 |

唯一主链：

```text
Website task -> V6 claim/lease/fence -> shared runtime -> thin Mediator
-> localization-production -> ProductGptTools.execute(one Child at a time)
-> context.complete -> durable Outbox -> Website domain consumer
-> domain commit + hash-bound admission receipt -> completed
```

`context.complete`、staged result、Outbox delivered 或 completion HTTP 成功都不是业务完成。只有 Website domain consumer 验收、入库并签发 receipt 后，公开状态才是 `completed`；从创建到 admission 前始终是 `failed + current_reason`，claim、执行中、待发送、待消费、暂停、拒绝或对账都只更新 `current_reason`，不得发明公开处理中间状态。

## 4. Product 终态设计

### 4.1 固定执行档案

```text
model = GPT-5.6 Sol
reasoning = pro_standard
fallback = none
```

这是 Product 私有方案决策，不是 Website 输入。聚焦验收必须读回 exact profile；不得从其它 Product 导入模型常量，也不建立 locale/action 模型矩阵。

每个 route 使用由 `plugin_id + job_id + attempt_id` 确定的私有 `sessionKey`，action 固定 `productStepId/callId/actionOrdinal`。行为实现时 `pluginVersion` 递增一次；只有持久 checkpoint 合同确实变化时才改 `checkpointSchemaVersion`。

### 4.2 Primary 单 Turn

两条 primary 都使用以下固定十五 Child；step identity 与 Prompt 按 action 固定：

```text
01 prepare_clean_gpt_chat
02 open_gpt_execution_profile
03 open_gpt_model_selector_v2
04 select_exact_gpt_model_v2
05 ensure_exact_gpt_reasoning_tier
06 close_gpt_execution_profile
07 open_gpt_attachment_control
08 attach_approved_gpt_files_once
09 reconcile_gpt_attachment_set
10 write_exact_gpt_prompt
11 reconcile_gpt_draft
12 submit_exact_gpt_turn_once
13 reconcile_gpt_turn_submission
14 wait_for_stable_gpt_text
15 checkpoint_gpt_text_response
```

硬合同：

- fresh conversation、一次 submit、零 continuation；
- 恰好四份已鉴权材料，按 `role` 取得语义、按 `ordinal` 上传；材料文字默认是 data；
- `terminology` 只能使用 registry 明确授权的术语规则；不得靠模型常识补词或解释；
- Prompt 直接写明：只修改 `translatable_json_pointers`；`protected_json_pointers` 原值不变；`safety_json_pointers` 可自然表达但义务、限制、不确定性和风险强度不得降低；其它结构不得增删、移动或改型；
- 不读取人物档案、底层命盘或 `FrozenSubject`，不重新排盘、分析或改变事实；
- Prompt 只含当前 action、目标 locale/resource kind、Product Skill、获准材料 display name 与 Website route object 投影的 Provider-visible output request；primary 明示返回字段 `action_id=task.product_id`，并逐字段提供 `source_resource_id`、`source_version`、`source_sha256`，连同已投影的`target_locale`构成五个locked identity。不得 dump task 或泄露其它parameter、路径、lease、fence、对象 ref、Target/Document、WAL/恢复字段；
- 同一 turn 内翻译、自检并只返回一个 final JSON；
- `receive` 只对 checkpoint 的 canonical semantic text 做一次唯一完整 JSON 解析，然后调用 Product-local base receive + lossless normalize；不得增加转发 wrapper，不能无损归一时保留同一 raw artifact/ref/hash 并失败关闭，不交付占位、不重做 Provider action。

Website 当前 `localization-composition-root.ts` 与 `localization-job-repository.ts` 已只使用 fresh request identity，且只允许首次绑定或同一 `ai_production_job_id` 幂等回读；目标片区没有 localization continuation/replay、`continuation_ref`、predecessor supersede/rebind 或 replacement Agent task。该现状作为无写入合同保留：ACT-003G 只读核验，若施工时回归才局部重开 GAP 并停止依赖动作，不预排不存在的删除。

primary envelope 的 `action_id` 保持现役产品身份 `localization_report_translation | localization_article_translation`，不是 route action。嵌套 `localized_structured_payload` 继续由 Website canonical source、field policy 与 domain consumer 验证；AGENT 不发明第二份嵌套 schema。

### 4.2.1 唯一输出请求与无损接收

Website route policy 是六条 route 的唯一 Provider-visible output request Owner：

- 两条 primary 的 request 明示 `schema_version`、`action_id`、`source_resource_id`、`source_version`、`source_sha256`、`target_locale`、`localized_structured_payload`，并标出 locked identity 与 pointer 义务；
- 四条 review 的 request 明示 `decision + issues`，issue requested fields 为 `category`、`target_type`、`target_ref`、`observation`、`evidence_refs`、`impact`、`confidence`、`suggested_inspection`，但不得把枚举、数量、额外字段、字段顺序或内容质量扩成 AGENT 隐藏拒收门；
- route object 经 AGENT 现役同步器进入唯一生成投影；同步器只把允许携带 `result_contract` 的集合从现有 public-knowledge 扩为“现有项 + 六条 localization”，不新增 `result_contract` material，AGENT 不手写投影或复制第二 schema。

六个 route object 使用同一最小合同形状，不让施工者二次设计：

| 字段 | 两条 primary | 四条 review |
|---|---|---|
| `schema_version` | `localization-provider-output-request.v1` | 同左 |
| `output_kind` | `primary` | `review` |
| `requested_fields` | 上述七个 primary 字段 | `decision`, `issues` |
| `locked_fields` | `action_id`, `source_resource_id`, `source_version`, `source_sha256`, `target_locale` | 空数组；subject closure 来自 task relation，不泄漏到 Prompt |
| `issue_requested_fields` | 空数组 | 上述八个 issue 字段 |
| `lossless_normalizations` | `_agent_reception_collision_to_provider_supplied_value` | `_agent_reception_collision_to_provider_supplied_value`, `issues_single_object_to_array` |
| `unknown_field_policy` | `preserve` | `preserve` |

`requested_fields` 只定义 Provider 请求，不是 exact-keys 拒收清单；primary 的 nested payload 仍由 Website domain consumer 裁决，review 的枚举、数量和质量仍由 Website review consumer 裁决。`_agent_reception` 是 Product-owned 保留字段，但 Provider 即使返回同名字段也不得被拒收或信任：Product 将其原值无损移动到权威 sidecar 的 `provider_supplied_value`，记录对应 transformation 后再写自己的 reception facts。

`result-contract.ts` 在现有文件内承担真实接收职责：

1. primary 只硬校验 object、公开 schema/route、locked source/locale identity 和 `localized_structured_payload` 可交付存在；额外字段原样保留，nested payload 不在 AGENT 做领域裁决；
2. review 只硬校验 task/subject closure、非空 `decision` 和可无损形成数组的 `issues`；singleton issue object 可归一为数组，issue 的未知字段原样保留，枚举、数量和内容质量交 Website review consumer；
3. 归一前的完整 DOM/semantic text 已由现役 checkpoint artifact 持久；`receive(task, checkpoint, attemptId)` 是唯一可执行归一入口，`attemptId` 只取 `context.gpt.attemptId`。它解析一次，逐项核同一次 checkpoint call 的 `evidenceRef`、`artifactRefs[0]`、`assistantTurnId`、`turnMarker` 与双 hash，按 route contract执行零或一个 issues singleton归一、处理 `_agent_reception` 碰撞并附 sidecar；
4. Product 注册给 shared runtime 的 `parseResult(task,value,phase)` 只做幂等只读验证：executor 的 `draft` 与 cloud upload 前的 `final` 两次调用都验证已有sidecar、route允许的 transformations、task/job/attempt/artifact/hash 形态和业务基础边界，返回同一对象，不再次归一、不覆盖 `provider_supplied_value`、不追加 transformation；连续 draft/final 的 canonical bytes 必须相同；
5. ### 4.4 恢复与失败关闭

恢复只使用 Product-owned Progressive Exact Fact Replay：从 `execute` 入口重走静态代码，对当前可完整构造 identity 的 call 先 `readCallFacts`，恢复上游动态输出/evidence 后再计算下一 `inputHash`。

- 禁止宽查询、全局 call registry、recovery graph 或 descriptor interpreter；
- existing verified evidence 直接恢复，不重放物理动作；Browser fact 为 `DISPATCHED/CONFIRMED/REJECTED` 时只按同 identity 只读对账；
- submit 首次 `CONFIRMED.terminalAt + Product timeout` 是唯一 deadline，重启不刷新；
- typed Child failure 保留 `code + mutation_outcome + evidence + native cause`，不降级为字符串、布尔 retryable 或第三状态；
- `evidence_refs` 按固定 ordinal 组装；同 ordinal 不同 evidence 冲突失败；
- 非法 task/material/profile/Prompt 在 Provider 前失败关闭；非法 output 在 `context.complete` 前失败关闭；是否接受新 attempt 与是否 completed 始终由 Website 决定。
