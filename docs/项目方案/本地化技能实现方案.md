## 1. 需求、终点与范围

本轮要修复已证实的本地化生产链缺口，并把系统从 Website 打包、AGENT 运输与执行、结果 Outbox、Website 领域入库一直闭合到精确业务对象 readback。

权威完成终点按业务分开：

- 动态报告：同一 `job_id + result_payload_hash` 的译文被 Website localization consumer 验收，写入 `localization_artifacts`、三个格式 artifact 和唯一 current report edition；V6 回执绑定该 report edition ref；AGENT 校验回执后才本地 `completed`。

- 固定页面文案：五个 locale 各自完成领域接纳后，只形成候选集合；随后必须经仓库唯一 import、publish、READY、RELEASE、部署和线上页面 readback。五张 job `completed` 不等于页面已发布。

本方案不授权改代码、法案、施工图、数据库、服务、Browser 或生产数据；不执行历史失败任务重放。施工授权需另行重新绑定。

## 4. Identity spine 与有限分母

主身份链：

```text
canonical resource id/version/hash + target_locale + policy_version
-> localization_job_id -> ai job_id + request_hash
-> accepted attempt_id + result_revision
-> provider_effect_identity_hash
-> Product completion intent hash
-> Outbox request_id + payload_hash + Website write receipt
-> result_payload_hash
-> localization artifact_ref + report edition/publication business_object_ref
-> business_consumption_hash
-> AGENT local completed
```

文章 continuation 额外绑定：

```text
article/version/hash + target locale ordinal
-> parent_task_ref + parent_result_ref + parent_result_hash
-> exact parent CONFIRMED Browser WAL canonical URL
```

有限分母只含当前真实分支：

- source/term/policy/parent 缺失、篡改或不唯一：Website sender 在 task/Provider 前拒绝，增量为零。
- Provider effect `REJECTED + no + 0`：Website 可结束 attempt 并有限退避签发新 attempt。
- Provider effect `DISPATCHED/CONFIRMED`：保留原 accepted attempt；只允许 Browser WAL 同 effect readback，physical submit 增量为零。
- Product 已完成但 artifact/envelope/terminal response 成功、失败或未知：复用同一 completion intent 与 Outbox；先读 Website write receipts，再决定是否发送 exact intent；不得重跑 Product/Provider。
- Website 明确拒绝 result revision：只由 Website 生成下一 revision；旧 completion intent/outbox 不可跨 revision 复用。
- Website 领域消费暂时失败：保持 staged result 和原身份，由现有 consumer 重消费；不重跑 Provider。
- Website job 权威缺席/永久撤权：仅清理 exact local job 及其现有材料、Outbox、intent、Browser/Forensics 事实；不触及其它 job。
- 业务接纳成功：先从 Website 再读回精确 domain object/ref-bound receipt，之后 AGENT 才完成。

## 5. 相邻 handoff 合同

1. Website localization sender -> ai-acceptance task：四材料仍恰好为 `source_content/terminology/locale_policy/render_policy`。术语材料改为 canonical 最小投影；文章必须带 exact parent triple，报告不得带 continuation parent。
2. ai-acceptance -> Runtime：task-result 合同固定为 intended v11；V6 在 G5 后升为 v33。consumer dependency 只保留 contract id/version/provider repo，不能复制 provider body。
3. Runtime -> Product：只交 task、四份鉴权材料、route policy 与 GPT public facade。Runtime 不解释 locale/term/parent；Product 不读取 transport/store/fence。
4. Product -> Runtime：`context.complete(output)` 先在现有 SQLite task store 写一份 hash-bound `completion_intent_json`，再触发 Outbox。该 intent 是当前结果运输所必需的唯一本地事实，不是第二业务结果。
5. Runtime -> Website writes：artifact intent 的持久 headers 只保存稳定 content/idempotency headers，当前 lease/fence 在发送时注入；terminal body 仍绑定当前 lease/fence。每次恢复先读取 Website `write_receipts` 并严格核本地 intent，再决定 hydrate、重新授权 exact artifact write 或生成当前 lease 的新 terminal intent。
6. Website domain consumer -> ai-acceptance：同一事务返回 `business_object_ref`；`business_consumption_hash` 必须包含该 ref。device status 在返回 receipt 前从领域表 join readback，证明 ref 属于同一 ai job 的 artifact/edition/publication。
7. ai-acceptance -> Runtime：receipt 必含 `job_id/result_payload_hash/consumer_ref/business_object_ref/outcome/consumption_hash/consumed_at`；Runtime 重算 hash并验证 ref 非空且类型前缀与 localization route 相符，再本地完成。

- 动作：五语逐 locale admission齐备后运行唯一 `localization:review:import-admitted`，再运行唯一 `localization:review:publish`；提交生成差异，进入 Website 原生 READY/RELEASE，部署后逐 locale 读线上真实页面。
- 完成：同 source/policy/hash 的五 locale `production_approved`、catalog/ledger/manifest/runtime projection 一致、部署版本命中、线上五 locale 文案与发布 hash 对应。任一层缺失只能报告当前层，不得称完整入库或已发布。

## 8. 跨仓施工与 cutover 顺序

1. 先完成 W0；其余一律不得开始。
2. Website 依次完成 W1、W2、W3、W4 的 Website 半边、W6 provider/0139；AGENT 完成 W4 半边、W5、W6 consumer。每仓只在自己的目标路径写入，保留用户改动。
3. 运行两仓聚焦测试；生成物只由仓库 builder 重建。随后各自运行唯一 `quality:check`，不得创造跨仓总 verdict。
4. cutover 前关闭新 localization producer，并只读证明：无 localization accepted lease、无 staged result、无未决 local completion intent/outbox、无 Website terminal 待消费；固定 catalog ensure 同样暂停。历史 completed 数据必须通过 0139 预检。
5. 冻结 participant commits 与版本：task-result v11、V6 v33、route manifest 的同一 projection hash。先停止 AGENT worker，应用 Website 0139并部署 Website，再部署 AGENT consumer；版本不等期间 session open 必须失败关闭，禁止兼容读。
6. 重新打开 session，先做 contract/manifest/read-only preflight，再恢复 producer。先一条报告、再一组文章五 locale，最后固定 catalog 五 locale；不得用历史任务替代新 proof。
7. 回退：若尚无 v33 新写入，可保持 producer/worker 关闭并整体回退两仓代码，0139 的已重算 hash需用对应迁移前密封快照恢复；一旦已有 v33 receipt 或新领域对象提交，禁止降级兼容，只允许停流量并向前修复同一合同。

### READY / RELEASE / Dynamic Proof

- 两仓 clean participant commits，contract/projection exact，迁移 registry/hash readback，原生 READY 后再 RELEASE。
- 报告分母：五个 target locale 各一条新 primary；每条都要 Provider/Browser effect、completion intent 清除、全部 Outbox receipts、Website report edition/三格式 readback、ref-bound admission、AGENT local completed。
- 文章分母：同一新 zh-CN article 的五 locale 严格链；同 canonical URL、五个不同 userTurnId/submit effect、每 job一次 submit；交换 parent negative 为零输入；每 locale publication 为 `released` 并绑定自身 receipt。
- 恢复分母：W4 断网一次；W5 四个 transport fault point各一次。所有 confirmed/unknown effect恢复的 physical submit delta 均为零。
- review 分母：报告/文章 manual accuracy 与 scheduled reflection 各一条，能读取四材料快照且只审不改。
- 固定文案：五 locale admission之后完成 import、publish、Website RELEASE/部署与线上五页 readback。

任何一项只到 Provider、HTTP 2xx、Outbox sent、terminal、staging、job completed 或 DB 单行，都不得代替其后续业务终点。
