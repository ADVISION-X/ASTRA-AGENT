## 1. 最终结论

动态本地化只复用现役 `localization-production` Product Plugin，不新建 Plugin、共享执行器、工作流引擎、队列、台账或 Provider runner。

唯一动态执行分母为六条现役路由：

```text
localization_report_translation / report_translation
localization_report_translation / accuracy_challenge
localization_report_translation / quality_reflection

localization_article_translation / article_translation
localization_article_translation / accuracy_challenge
localization_article_translation / quality_reflection
```

两条 primary 各自一次 fresh-conversation translation turn，只返回一个 final；四条 review 各自一次 fresh-conversation review turn，只返回 `decision + issues`。动态报告/文章不使用 Candidate A/B、selector、修稿轮、continuation、第二 job 或第二队列。

Website 静态 UI/catalog 本地化仍按现役 authority 使用 Candidate A/B、静态审校与 blind selector，并继续只属于 `localization-production` 私有 Flow；它没有进入当前三十九条公开 AGENT route，本方案不新增入口、不施工该片区，也不删除其权威语义。

当前 NO-GO 由已证实的输入合同缺口造成，不代表 Product 架构失败。各缺口按 route 阻断，不建立 feature flag、兼容路径或双轨：Website 在任务创建边界 typed fail-close，AGENT 始终只有一套实现。

## 3. 唯一 Owner 与终态

| 事项 | 唯一 Owner | 边界 |
|---|---|---|
| 业务任务、材料/结果合同、公开状态、领域入库与发布 | Website | 冻结完整输入、验证结果并签发 admission receipt；不下发 Prompt、模型、Child 顺序或恢复分支 |
| 动态翻译/review 语义、Prompt、模型、Child 顺序、恢复与结果组装 | `localization-production` | 同一个 Plugin 用静态 TypeScript 直接拥有六条 route；不产生第二 Product/Flow |
| 原子页面语义动作 | GPT Capability | 一次请求执行一个原子 Child；不决定 Product 下一步 |
| Target/Document、物理 mutation、WAL 与对账 | Browser Authority | 只返回受控事实/proof；Product 不接触 selector、tab 或 WAL row |
| claim、lease、fence、材料授权、staged result、Outbox | shared runtime | 只运输与安全；不理解本地化、不调度业务 Flow |
| exact-call evidence | Forensics Persistence | 唯一 evidence append/readback；不裁决业务完成 |

唯一主链：

```text
Website task -> V6 claim/lease/fence -> shared runtime -> thin Mediator
-> localization-production -> ProductGptTools.execute(one Child at a time)
-> context.complete -> durable Outbox -> Website domain consumer
-> domain commit + hash-bound admission receipt -> completed
```

`context.complete`、staged result、Outbox delivered 或 completion HTTP 成功都不是业务完成。只有 Website domain consumer 验收、入库并签发 receipt 后，公开状态才是 `completed`；否则保持 `failed + current_reason`。

## 4. Product 终态设计

### 4.1 固定执行档案

```text
model = GPT-5.6 Sol
reasoning = pro_standard
fallback = none
```

这是 Product 私有方案决策，不是 Website 输入。聚焦验收必须读回 exact profile；不得从其它 Product 导入模型常量，也不建立 locale/action 模型矩阵。

每个 route 使用由 `plugin_id + job_id + attempt_id` 确定的私有 `sessionKey`，action 固定 `productStepId/callId/actionOrdinal`。行为实现时 `pluginVersion` 递增一次；只有持久 checkpoint 合同确实变化时才改 `checkpointSchemaVersion`。

### 4.2 Primary 单 Turn

两条 primary 都使用以下固定十五 Child；step identity 与 Prompt 按 action 固定：

```text
01 prepare_clean_gpt_chat
02 open_gpt_execution_profile
03 open_gpt_model_selector_v2
04 select_exact_gpt_model_v2
05 ensure_exact_gpt_reasoning_tier
06 close_gpt_execution_profile
07 open_gpt_attachment_control
08 attach_approved_gpt_files_once
09 reconcile_gpt_attachment_set
10 write_exact_gpt_prompt
11 reconcile_gpt_draft
12 submit_exact_gpt_turn_once
13 reconcile_gpt_turn_submission
14 wait_for_stable_gpt_text
15 checkpoint_gpt_text_response
```

硬合同：

- fresh conversation、一次 submit、零 continuation；
- 恰好四份已鉴权材料，按 `role` 取得语义、按 `ordinal` 上传；材料文字默认是 data；
- `terminology` 只能使用 registry 明确授权的术语规则；不得靠模型常识补词或解释；
- Prompt 直接写明：只修改 `translatable_json_pointers`；`protected_json_pointers` 原值不变；`safety_json_pointers` 可自然表达但义务、限制、不确定性和风险强度不得降低；其它结构不得增删、移动或改型；
- 不读取人物档案、底层命盘或 `FrozenSubject`，不重新排盘、分析或改变事实；
- Prompt 只含当前 action、目标 locale/resource kind、Product Skill、获准材料 display name 与 exact output contract；不得 dump task 或泄露路径、lease、fence、对象 ref、Target/Document、WAL/恢复字段；
- 同一 turn 内翻译、自检并只返回一个 final JSON；
- checkpoint 只执行 `parseRouteResult(task, rawText)`，然后把 payload 与 ordered `evidence_refs` 交给 `context.complete`；解析失败不得交付占位结果。

primary envelope 的 `action_id` 保持现役产品身份 `localization_report_translation | localization_article_translation`，不是 route action。嵌套 `localized_structured_payload` 继续由 Website canonical source、field policy 与 domain consumer 验证；AGENT 不发明第二份嵌套 schema。

### 4.3 Review 单 Turn

四条 review 各自使用独立 fresh conversation 和同一十五 Child，恰好挂载：

```text
subject_result
review_context
```

localization `review_context` 内嵌 subject task 四份 primary material 的冻结快照，分母恰好为：

```text
{ role, sha256, value }
role = source_content | terminology | locale_policy | render_policy
```

subject task/result/authorization identity 继续使用现役 review 字段，不在 snapshot 复制第二套 identity。snapshot 内容寻址、owner-scoped、locked；AGENT 不回查 Website object store。

`accuracy_challenge` 只检查事实、遗漏、术语、保护字段、风险强度和 locale 偏差；`quality_reflection` 只检查自然度、一致性、清晰度与合同摩擦。两者只返回 `website-agent-review-output.v1` 的 `decision + issues`，不改稿、不审批、不保存 ledger。

### 4.4 恢复与失败关闭

恢复只使用 Product-owned Progressive Exact Fact Replay：从 `execute` 入口重走静态代码，对当前可完整构造 identity 的 call 先 `readCallFacts`，恢复上游动态输出/evidence 后再计算下一 `inputHash`。

- 禁止宽查询、全局 call registry、recovery graph 或 descriptor interpreter；
- existing verified evidence 直接恢复，不重放物理动作；Browser fact 为 `DISPATCHED/CONFIRMED/REJECTED` 时只按同 identity 只读对账；
- submit 首次 `CONFIRMED.terminalAt + Product timeout` 是唯一 deadline，重启不刷新；
- typed Child failure 保留 `code + mutation_outcome + evidence + native cause`，不降级为字符串、布尔 retryable 或第三状态；
- `evidence_refs` 按固定 ordinal 组装；同 ordinal 不同 evidence 冲突失败；
- 非法 task/material/profile/Prompt/output 在 Provider 或 `context.complete` 前失败关闭；是否接受新 attempt 与是否 completed 始终由 Website 决定。

## 7. 验收与施工顺序

聚焦验收必须至少证明：

- 两条 primary 与四条 review 各自 exact 15 Child、ordinal 1..15、一个 session、一次 submit、零 continuation；

- replay 逐前缀恢复 exact facts；upload/submit existing evidence 或 `DISPATCHED` 时物理重放为零；
