# GrassEye Agent 故事情节：视觉裁判、解码器与机器臂

## 0. 这一篇写给谁

这一篇不是给普通用户看的说明书。

这一篇是写给 GrassEye 自己看的。

也是写给后续每一个 AI 助手、每一个开发者、每一次迭代看的。

它要讲清楚一件事：

**GrassEye 到底是什么？**

过去，我们以为 GrassEye 是一个自动化程序。

后来，我们发现它不是。

它不是一个按钮脚本。

不是一个网页爬虫。

不是一个简单的浏览器自动化工具。

它也不是一个只会截图、问 AI、再点鼠标的小程序。

GrassEye 更像一个电脑里的电子工人。

它看屏幕。

它理解任务。

它根据 AI 的判断选择动作。

它执行动作。

它留下证据。

它继续下一步。

但是现在，我们又看到了更深的一层。

GrassEye 不应该把所有判断都拆碎。

不应该每一个小动作都问一次 AI。

不应该一会儿问“是不是页面准备好了”，一会儿问“是不是产品视频”，一会儿问“是不是下一条视频”，一会儿又问“按钮在哪里”。

这样会让系统越来越复杂。

能力组越来越多。

交接包越来越多。

执法脚本越来越多。

每一层都像有道理。

合在一起却像一团绳子。

真正简单的方向应该是：

> **AI 做完整思考。  
> 系统负责解码。  
> 肌肉记忆负责执行。  
> Forensics 负责记录。**

这就是这一篇故事情节要讲的核心。

---

## 1. 过去：我来想，它来做

最早的时候，我们想要一个东西：

**我来想，它来做。**

我不想每天重复点网页。

不想每次都手动打开平台。

不想每条视频都自己看。

不想看到疑似产品视频还要手动截图、手动保存、手动记录。

我真正想要的是：

我提出目标。

GrassEye 去执行。

比如：

> 去 Facebook / TikTok 里找种草视频。

它应该打开平台。

它应该看屏幕。

它应该判断当前视频是不是产品视频。

如果是，就保存线索。

如果不是，就下一条。

这就是最初的 V1：

```txt
打开平台
→ 截图
→ AI 判断 product_yes / product_no
→ YES 保存截图、URL、标题、AI 摘要
→ 尝试点赞
→ 下一条
→ NO 直接下一条
```

这已经比普通脚本强很多。

因为它不是固定点某个按钮。

它是看见屏幕后，根据视觉判断做选择。

但调试中我们发现，系统越做越复杂。

因为每一个环节都被拆成了一个小关口。

---

## 2. 中途：能力组开始穿插

为了让系统稳，我们建立了很多能力组。

打开页面是一组能力。

截图是一组能力。

AI 判断是一组能力。

页面状态是一组能力。

视觉目标定位是一组能力。

坐标归一是一组能力。

鼠标点击是一组能力。

键盘输入是一组能力。

动作后验证是一组能力。

证据保存是一组能力。

这些能力组本身没有错。

它们就是 GrassEye 的身体。

身体必须存在。

身体必须稳定。

身体必须能被调用。

但是问题出现在：

**我们让身体里的每一块肌肉都参与思考了。**

于是，一个很简单的任务，变成了很多关口：

```txt
页面准备 AI 判断
→ 当前页面状态证明
→ 截图证明
→ 产品判断 AI
→ 下一条验证 AI
→ URL 是否一致
→ pageStateProof 是否一致
→ targetUrl 是否还在
→ 是否能保存 Forensics
```

结果是：

系统每往前走一步，都可能被一个证明挡住。

不是这个 ref 丢了。

就是那个 proof 不一致。

不是 URL 变化被误杀。

就是下一条验证浪费 10 秒。

不是截图太重。

就是 AI 判断分散。

我们开始意识到：

如果继续这样修，GrassEye 会越来越像一个被证明链绑住的机器人。

它有身体。

但身体太紧。

它有大脑。

但大脑被拆碎。

它有手。

但每动一下都要先写十张通行证。

这不是我们要的最终形态。

---

## 3. 新发现：AI 不应该只回答一个小问题

过去，我们总是这样问 AI：

> 这是不是产品视频？

或者：

> 页面准备好了吗？

或者：

> 下一条视频切换成功了吗？

或者：

> 评论按钮在哪里？

每次问一个小问题。

AI 回答一个小结果。

系统再用这个小结果走下一步。

这样看起来清晰。

但它有一个大问题：

**AI 的思考能力被浪费了。**

AI 明明可以看完整个屏幕。

AI 明明可以同时判断：

```txt
这是 Facebook 还是 TikTok？
当前是不是推荐视频流？
有没有跑到主页、用户页、搜索页、登录页？
这是不是产品视频？
如果是产品，应该保存吗？
要不要点赞？
下一步应该下滑还是回入口页？
如果有弹窗，应该点哪里？
```

可是我们只让它回答：

```txt
是不是产品？
```

这就像让一个人看完整个战场，却只问他：

> 你看到红色了吗？

然后其他判断全部交给代码硬凑。

这不合理。

真正应该做的是：

> **每一轮只截图一次。  
> 把完整画面交给 AI。  
> 让 AI 一次性给出完整判断和动作计划。**

---

## 4. 坐标图：解锁鼠标能力的钥匙

过去，鼠标点击很难。

因为 AI 说：

```txt
点右边的评论按钮。
```

系统不知道右边到底是哪。

AI 如果说：

```txt
x=1040, y=520
```

又会遇到很多问题：

```txt
截图尺寸是多少？
浏览器窗口在哪里？
Mac Retina 缩放是多少？
页面滚动了吗？
坐标是图片坐标还是屏幕坐标？
视频区域有没有偏移？
```

于是我们做了视觉目标定位、几何校准、鼠标点击、动作后验证。

这些能力都对。

但它们让系统很复杂。

后来，一个更简单的想法出现了：

> **给 AI 一张原图，再给 AI 一张带坐标网格的图。**

不是让 AI 自由报 x/y。

而是让 AI 在我们给定的坐标语言里回答：

```json
{
  "action": "CLICK_GRID_CELL",
  "gridCell": "D6",
  "targetName": "close_popup"
}
```

这样系统就不需要猜 AI 的坐标。

系统知道 D6 在图片中的位置。

系统知道 D6 对应屏幕哪个区域。

系统只要把格子反算成鼠标点击位置。

坐标图不是为了让 AI 乱点。

坐标图是为了建立一门共同语言。

AI 看图。

AI 选格子。

系统解码格子。

机器臂执行动作。

这一下，鼠标能力就被解锁了。

过去，鼠标点击是一堆复杂证明链。

未来，它可以变成：

```txt
原图 + 坐标图
→ AI 选择动作和格子
→ 系统执行白名单动作
```

这不是削弱肌肉记忆。

这是更深地挖掘肌肉记忆。

因为肌肉记忆本来就会点击。

只是以前 AI 不知道怎么精确调用它。

坐标图让 AI 能够调用鼠标肌肉。

## 5. 新角色：AI 是视觉裁判

于是，GrassEye 里出现一个新角色：

# Visual Mission Judge  
# 视觉任务裁判

它不是普通 AI prompt。

它不是只判断产品视频。

它是每一轮任务的视觉裁判。

它看到：

```txt
一张原始截图
一张坐标网格截图
当前目标平台
当前任务目标
动作手册
输出 JSON Schema
```

然后一次性回答：

```txt
当前是不是目标平台？
当前是不是推荐视频流？
当前有没有跑偏？
当前是不是产品视频？
如果是产品，要不要保存？
要不要点赞？
下一步是下一个视频，还是回入口页？
有没有弹窗？
如果需要点击，点哪个格子？
```

AI 的职责不再是回答一个小问题。

AI 的职责变成：

> **看完整屏幕，理解任务，输出下一步动作计划。**

这才叫 AI 回到思考的位置。

---

## 6. 系统的新身份：解码器 + 机器臂

如果 AI 是视觉裁判，那 GrassEye 系统是什么？

系统不是裁判。

系统不应该在代码里到处猜：

```txt
这是不是 TikTok 推荐页？
这个 URL 变了是不是正常？
这是不是产品？
下一条有没有切换成功？
```

这些应该尽量交给 AI 视觉裁判。

系统的新身份应该是：

# 解码器 + 机器臂

什么叫解码器？

AI 返回标准 JSON。

系统解析 JSON。

系统检查动作是不是在白名单里。

系统把动作码翻译成已有肌肉记忆。

比如：

```json
{
  "actions": [
    { "type": "SAVE_LEAD" },
    { "type": "PRESS_KEY", "key": "L" },
    { "type": "PRESS_KEY", "key": "ArrowDown" }
  ]
}
```

系统解码成：

```txt
调用 Forensics 保存线索
调用 text-input 按 L
调用 text-input 按 ArrowDown
```

什么叫机器臂？

机器臂不思考人生。

机器臂只执行允许动作。

AI 说保存，系统保存。

AI 说按 L，系统按 L。

AI 说下一个，系统下一个。

AI 说点 D6，系统把 D6 转成坐标并点击。

AI 说回入口页，系统打开入口页。

AI 说停止审查，系统停止并记录。

机器臂不自由发挥。

也不问为什么。

它只做动作手册允许的动作。

---

## 7. 动作手册：AI 能说什么，系统就能做什么

为了防止 AI 乱说，必须有动作手册。

AI 不能随便输出：

```txt
帮我点一下那里。
把账号密码输入进去。
打开一个陌生网站。
发送一条评论。
购买这个产品。
```

AI 只能从动作手册里选择：

```txt
SAVE_LEAD
PRESS_LIKE_KEY
PRESS_NEXT_VIDEO
REOPEN_ENTRY_PAGE
WAIT_SHORT
CLICK_GRID_CELL
STOP_REVIEW_REQUIRED
```

这就是边界。

AI 不是皇帝。

AI 是视觉裁判。

它可以判断。

它可以建议动作。

但它只能说系统听得懂、允许执行的动作码。

系统也不是傻子。

系统只执行白名单动作。

如果 AI 输出未知动作：

```txt
拒绝执行
记录 Forensics
停止或要求 review
```

这就是安全。

这也是大道至简。

不是让 AI 完全失控。

而是让 AI 的思考能力集中起来。

让系统的执行能力单纯起来。

---

## 8. 种草视频：一次截图就够了

对种草视频来说，新架构会非常简单。

每一条视频只需要一次截图。

系统准备：

```txt
原图
坐标图
平台：Facebook 或 TikTok
任务：寻找产品种草视频
动作手册
JSON Schema
```

AI 返回：

### 如果是产品视频：

```json
{
  "platform": "facebook",
  "surface": "reels_video",
  "isTargetPlatform": true,
  "isTargetFeed": true,
  "isProductVideo": true,
  "productDecision": "product_yes",
  "confidence": 0.88,
  "visibleProductTypes": ["portable blender"],
  "reason": "A portable blender is clearly being demonstrated.",
  "actions": [
    { "type": "SAVE_LEAD", "required": true },
    { "type": "PRESS_LIKE_KEY", "required": false },
    { "type": "PRESS_NEXT_VIDEO", "required": true }
  ]
}
```

系统执行：

```txt
保存线索
按 L
按 ArrowDown
进入下一轮
```

### 如果不是产品视频：

```json
{
  "platform": "facebook",
  "surface": "reels_video",
  "isTargetPlatform": true,
  "isTargetFeed": true,
  "isProductVideo": false,
  "productDecision": "product_no",
  "confidence": 0.82,
  "reason": "No clear product is visible.",
  "actions": [
    { "type": "PRESS_NEXT_VIDEO", "required": true }
  ]
}
```

系统执行：

```txt
按 ArrowDown
进入下一轮
```

### 如果跑偏了：

```json
{
  "platform": "tiktok",
  "surface": "profile_page",
  "isTargetPlatform": true,
  "isTargetFeed": false,
  "pageStateDecision": "recover_to_entry",
  "reason": "The screen is a TikTok profile page, not the recommendation feed.",
  "actions": [
    { "type": "REOPEN_ENTRY_PAGE", "required": true }
  ]
}
```

系统执行：

```txt
重新打开 TikTok 入口页
进入下一轮
```

这样一来，很多原来的复杂判断都会消失。

不用单独问是不是下一条。

不用单独问 URL 是否一致。

不用单独问页面准备好了没有。

不用单独问是不是产品。

AI 一次看图，一次回答。

系统照动作手册执行。

## 9. 不仅是种草，而是电脑上的一切操作

真正有意思的地方在这里：

**这个方法不只适用于种草视频。**

它适用于电脑上绝大多数需要视觉操作的事情。

因为电脑操作，本质上就是：

```txt
看见屏幕
理解当前状态
决定下一步
点击 / 输入 / 滚动 / 等待 / 保存
再次截图
继续判断
```

种草视频只是最简单的一种。

一条视频，一次截图，一次判断，一组动作。

如果是操作一个电脑程序，无非是多几轮：

```txt
截图
→ AI 判断当前界面
→ 返回动作计划
→ 系统执行
→ 再截图
→ AI 再判断
→ 再执行
```

比如操作一个网站后台：

```txt
截图 1：AI 判断当前在登录页
→ 动作：STOP_REVIEW_REQUIRED 或等待人工登录

截图 2：AI 判断当前在 dashboard
→ 动作：CLICK_GRID_CELL 打开 Orders

截图 3：AI 判断当前在订单列表
→ 动作：CLICK_GRID_CELL 打开筛选器

截图 4：AI 判断筛选完成
→ 动作：SAVE_SCREEN_REPORT
```

比如操作一个桌面软件：

```txt
截图 1：AI 判断软件已打开但弹窗遮挡
→ 动作：CLICK_GRID_CELL 关闭弹窗

截图 2：AI 判断主界面出现
→ 动作：CLICK_GRID_CELL 打开菜单

截图 3：AI 判断设置项出现
→ 动作：CLICK_GRID_CELL 选择选项
```

比如整理邮件：

```txt
截图 1：AI 判断 Gmail 收件箱
→ 动作：CLICK_GRID_CELL 打开第一封重要邮件

截图 2：AI 判断邮件内容
→ 动作：SAVE_SUMMARY 或 PRESS_NEXT_ITEM

截图 3：AI 判断下一封邮件
→ 动作：SAVE_SUMMARY
```

它的通用形态都是一样的：

```txt
截图
→ AI 视觉裁判
→ 标准动作 JSON
→ 系统解码
→ 肌肉记忆执行
→ Forensics 记录
→ 下一轮
```

这就太有意思了。

因为 GrassEye 不再只是一个种草视频工具。

它开始变成：

# 一套视觉驱动的电脑操作系统

不是替代 macOS。

而是在 macOS 上长出一个会看、会想、会操作的数字工人。

## 10. 地图的意义也变了

过去，地图像一条详细路线。

它要写：

```txt
第一步打开页面
第二步截图
第三步问页面准备 AI
第四步问产品 AI
第五步下一条验证 AI
第六步保存
```

以后，地图会更简单。

地图只需要说：

```txt
这个任务使用 Visual Mission Judge。
这是入口页面。
这是目标平台。
这是任务目标。
这是动作手册。
这是允许动作。
这是停止边界。
这是保存规则。
```

也就是说，地图不再负责拆碎每一个判断。

地图负责定义任务框架。

真正每一轮的判断，由 AI 视觉裁判完成。

这会让地图更像“任务说明书”，而不是“机械流程脚本”。

---

## 11. Prompt Contract 的意义更强了

在这个新架构里，Prompt Contract 更重要。

因为 AI 视觉裁判能不能稳，取决于提示词是否足够严谨。

Prompt Contract 要定义：

```txt
AI 的身份
输入内容
任务目标
平台规则
页面状态规则
产品判断规则
动作手册
禁止动作
输出 JSON Schema
示例输出
错误处理
置信度要求
```

也就是说，未来真正迭代最多的，不一定是代码。

而是 Prompt Contract。

比如今天发现：

Facebook Reels 的 URL 每条都变，但这是正常。

那就写进 Prompt Contract：

```txt
Facebook URL 变化不是跑偏，视觉上仍在 Reels/feed 视频即可继续。
```

明天发现：

TikTok 跑到 profile 页面就不适合继续刷。

那就写进 Prompt Contract：

```txt
TikTok profile page is not target feed. Return REOPEN_ENTRY_PAGE.
```

后天发现：

有弹窗挡住画面。

那就写进 Prompt Contract：

```txt
If popup blocks the target screen, return CLICK_GRID_CELL for close button if visible.
```

这就是把复杂性放回 AI 应该处理的地方：

**思考层。**

而不是让代码到处打补丁。

---

## 12. 肌肉记忆没有消失，反而更强

有人可能会问：

如果 AI 一次判断所有事情，那肌肉记忆是不是没用了？

恰恰相反。

肌肉记忆更重要了。

因为 AI 只负责说：

```txt
PRESS_NEXT_VIDEO
PRESS_LIKE_KEY
CLICK_GRID_CELL D6
REOPEN_ENTRY_PAGE
SAVE_LEAD
```

真正执行这些动作的，还是肌肉记忆。

没有肌肉记忆，AI 只能说话。

有了肌肉记忆，AI 的判断才能变成动作。

以前的肌肉记忆像一堆孤立按钮。

现在，坐标图和动作手册把它们组织起来。

AI 可以调用它们。

系统可以约束它们。

Forensics 可以记录它们。

这才是肌肉记忆的真正释放。

---

## 13. Forensics：每一次思考和动作都要留下脚印

新架构不是黑箱。

每一轮都必须记录：

```txt
原图 ref
坐标图 ref
Prompt Contract ID
AI 输出 JSON
动作计划
实际执行动作
保存结果
失败原因
下一轮状态
```

如果 AI 判断错了，可以复盘。

如果动作失败了，可以复盘。

如果某个平台规则不对，可以改 Prompt Contract。

如果某个动作手册不够，可以新增动作。

这才叫可成长。

没有 Forensics，这个系统会变成“AI说什么就做什么”的黑箱。

有了 Forensics，它就是一个可训练、可审计、可改进的数字工人。

---

## 14. 未来的 GrassEye

未来，GrassEye 的每一轮可能都很简单：

```txt
截一张屏幕
生成一张坐标图

```

```txt
多轮截图

一步步执行
```

桌面软件：

```txt

```

邮件整理：

```txt
多轮截图或读取

```

## 15. 新故事的核心

过去的故事是：

# 我来想，它来做

现在可以补上一句：

# AI 来判断，系统来执行

更完整地说：

```txt
人类提出目标。
地图定义任务。
AI 看图思考。
系统解码动作。
肌肉记忆执行。
Forensics 留下证据。
```

这就是新的 GrassEye。

AI 不再只是回答一个小问题。

AI 回到真正的思考位置。

系统不再在代码里到处猜。

系统回到解码器和机器臂的位置。

肌肉记忆不再被复杂 proof 拖住。

肌肉记忆被坐标图和动作手册彻底解锁。

而人类终于可以回到最应该的位置：

**提出目标。**
