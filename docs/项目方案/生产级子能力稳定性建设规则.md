## 一、最终结论

我们要建设的不是一个万能 Child 引擎，而是一组所有 Child 都不能违反的原子不变量。

> **统一的是契约形状、安全不变量、结果语义、证据语义和验收方法。**
>
> **不统一的是各 Child 的 DOM 身份、局部状态谓词、可等待条件、直接后置和 CAS 语义。**

最终目标是：

> **每个 Child 都只在自己的权威表面内，用与自身能力画像匹配的最小结构，把一个可独立验证的语义意图做到底。**

总原则仍然是：

> **内部极强，外部极窄。**

对 21 个页面 Child，这句话现在有了完整的生产含义：

> **强壮页面 Child = Browser 提供可信、同瞬间的机械事实 + GPT Child 作出唯一局部语义裁决 + Browser/WAL 守住至多一次动作 + GPT Child 用新鲜直接后置结算。**

对 6 个 continuation Child，则把 Browser/WAL 换成唯一 Session transaction/version/CAS；二者不得混成一个通用引擎。

这套规则的价值不是保证 Provider 永远不改变，而是保证：

1. 已支持状态确定成功，不靠 selector 运气。
2. 已完成目标零动作返回。
3. 需要动作时至多一次，结果未知绝不盲目重做。
4. 短暂状态只在明确证据和有界期限内重新观察。
5. 未知、多义和漂移在动作前零动作失败。
6. 真变化只影响一个 Child 的局部合同，不扩散成整条生产链反复迭代。

三审一致要求保留的内容包括：

- “内部极强，外部极窄”。
- 同一裁决不得拼接不同瞬间的事实。
- 已满足时零动作；需要动作时至多一次。
- dispatch 后只读对账。
- 动作前冻结完整正、反后置。
- 未知、多义、漂移动作前零动作失败。
- 局部合同唯一，禁止 fallback、打分和默认取第一个。
- typed failure、安全证据和摧毁式验收。
- 先用四类原型验证，再扩展到 26 个 Child。

### 2.2 V4 的 fork 权威裁决

真实页面已经证明 fork 的可见主链是两个独立状态变化：先打开 exact source checkpoint 的“更多操作”菜单，再点击唯一“打开新分支”叶子。授权人已明确批准修改法案、施工图和 Child 边界，因此终态不再等待假设中的一动作接口，也不允许一个 Child 隐藏两次物理动作：

1. 新增 `open_gpt_checkpoint_actions_menu`，画像为 `TARGET_LOCAL_MUTATION`，只打开或确认 source-bound 菜单，mutation budget 为 0 或 1，直接后置是唯一 active menu 与唯一 fork 叶子。
2. `fork_exact_gpt_conversation_at_checkpoint` 保持 `PROVIDER_EFFECT_ONCE`，只点击已重新证明的唯一 fork 叶子一次并读回唯一 child relation，不得再次打开菜单。
3. Product Plugin 以两个独立 callId/actionOrdinal 显式排列；Facade、GPT shared runtime 与 Browser 不得合并两步或决定是否调用下一步。
4. 目标分母由 20 个页面 Child + 6 个 continuation 调整为 21 + 6 = 27；画像数量固定为 6 / 12 / 3 / 6。

### 3.3 历史故障说明了什么

2026-08-31 的真实附件故障曾出现：

- file-input 物理动作约 200ms 完成，并已有 Browser CONFIRMED。
- Provider 附件 ready 对账约 60.1s 后仍失败。
- 后续才补入更长 Product timeout、stale fresh retry 和 no-layout 与真实 DOM payload invalid 的分类。

本段时长来自 `.grasseye-local/runtime-logs/agent/24647bca-b7c4-421a-925d-34aa90c0f6b7-0001.jsonl:219-229,1521`；SQLite `production_attempt_failures.failure_json` 同时保留了 `GPT_ATTACHMENT_UPLOAD_TIMEOUT` 的 typed failure。它们只作为历史故障样本，不构成目标 27 个 Child 的生产验收。

这证明物理动作完成不等于 Provider 语义完成，也证明继续按事故逐个补特例无法得到强壮 Child。统一规则必须提前覆盖：动作与语义分层、可等待资格、typed cause、deadline 和 dispatch 后读回。

## 四、唯一共同原子内核

所有 Child 共同的运行形状只有五步：

    精确输入与唯一权威
            ↓
    一份完整、可验证的局部事实
            ↓
    Child 局部纯裁决
            ↓
    零动作，或经 Browser/CAS 原子门至多一次动作
            ↓
    新鲜直接后置
            ↓
    success(value, evidence)
    或 failed(typed_reason, evidence)

以下内容不属于这个运行形状：

- Product 的下一步、分支、跳过、恢复和业务终态。
- Browser 的 Target/Document 选择、WAL 解释和物理恢复裁决。
- Website 的 retry、claim、撤权和业务完成。
- 中央状态机、共享 executor、统一 wait engine、统一 replay engine、registry 或 DSL。

### 4.1 八项共同合同

每个 Child 的现役唯一合同必须机械表达以下八项内容：

1. **身份与版本**：childId、contractVersion。
2. **原子语义意图**：它独立证明什么，或者独立改变什么。
3. **权威表面与边界**：唯一 Owner、读集、写集、允许的 Document transition、禁止副作用。
4. **精确输入身份**：输入类型、exact call identity、必要的 subject/authorization 或 Target kind。
5. **能力画像**：四种画像之一，以及是否具有 bounded-wait 特征。
6. **局部事实与裁决合同**：前置、完成谓词、动作资格、可等待资格、typed fail-close 原因。
7. **动作与结算合同**：mutation budget、正/反后置、重放和 readback 规则。
8. **安全证据合同**：允许投影的稳定字段、hash、typed cause 和隐私边界。

verification cases 属于验收，不进入生产运行合同。以上八项必须优先由现有唯一 Child/DOM 合同承载，不授权新建第二 registry、DSL 或契约真相。

## 五、四种能力画像

### 5.1 画像定义

| 画像 | 局部语义 Owner | 所需权威事实 | mutation budget | 可等待 | 恢复依据 | 必要动态证明 |
| --- | --- | --- | ---: | --- | --- | --- |
| DOM_OBSERVATION | GPT Child 合同 | 当前 Browser Target/Document 的 typed facts | 0 | 可附加 bounded-wait | 丢弃旧观察后 fresh read | deterministic mutant；页面类加真实 Chrome |
| TARGET_LOCAL_MUTATION | GPT Child 合同 | Browser exact Target/Document + WAL | 0 或 1 | 可附加 bounded-wait | exact call evidence + WAL；新 generation 不产生重做资格 | Chrome、TOCTOU、跨 generation 禁重做 |
| PROVIDER_EFFECT_ONCE | GPT Child 合同 | Browser/WAL 物理事实 + Forensics evidence + Provider 直接读回 | 0 或 1 | dispatch 后只读等待 | confirmed receipt、submission locator 或 exact readback | 中断、重启、Target 丢失、再次 mutation 为零 |
| CONTINUATION_TRANSACTION | GPT Session Child 合同 | 唯一 Session Controller/store 的 transaction/version/CAS 事实 | 0 或 1 次 CAS | 不使用 DOM wait | identical readback、version conflict、commit-before-return | 真实 storage/CAS、并发、崩溃点和授权错配 |

bounded-wait 是画像上的附加特征，不是第五个 Owner 或第五个公共执行器。

- reconcile attachment/submission 等可在 DOM_OBSERVATION 上附加 bounded-wait。
- wait text/image 因依法可能至多一次关闭精确遮挡，属于 TARGET_LOCAL_MUTATION + bounded-wait。
- CONTINUATION_TRANSACTION 不使用 DOM variant、Browser Target/Document 或真实 Chrome 证明。

## 六、Browser DOM 与 Child 的联合生产合同

### 6.1 联合裁决

《Browser DOM 生产级方案.md》的核心方向成立：如果 Browser 不能稳定证明 exact Target/current Document、候选基数、节点物理状态和动作边界，Child 再严密也只能在不可信事实上作判断。

但 Browser DOM 不是第二套 Child 规则，更不能成为中央语义 classifier。联合终态固定为：

1. Browser 只拥有产品中性的物理事实、Target/Document 生命周期、物理动作和 WAL。
2. GPT Child 只拥有自己那一小块页面的语义身份、DONE/ACT/WAIT/FAIL_CLOSED 裁决和直接后置。
3. Product 只拥有 Child 顺序、总等待策略、跳过、恢复和业务终态。
4. Session continuation 不经过 Browser，继续由唯一 transaction/version/CAS Owner 结算。

因此，“一套统一模式”不是让每个 Child 调同一个万能 `isActionable()`，而是让所有页面 Child 都通过同一个 Browser 物理事实合同，再由各自唯一局部合同解释这些事实。

### 6.2 唯一 Owner 与允许的信息流

| 层 | 唯一拥有 | 明确不得拥有 |
| --- | --- | --- |
| Product Plugin | Child 顺序、Provider 总 timeout、readCallFacts 后的流程选择 | selector、DOM 候选、WAL row、Child 内部状态机 |
| GPT Child | 源码冻结的私有 scope/selector 或等价语义身份、最小事实、局部裁决、正反后置 | Target 选择、物理点击、WAL 恢复、下一个 Child |
| Browser Authority | exact Target/current Document、同瞬间机械观察、节点物理事实、typed mutation 命令、FIFO、WAL 和 terminal fact | ChatGPT 业务语义、DONE/WAIT/FAIL 命名、Product Flow |
| Session Controller/store | continuation identity、version、authorization、CAS、identical readback | 页面 DOM、Browser generation、Provider 页面恢复 |

scope/selector 只能是 GPT Child 源码冻结的私有合同，经认证的 typed Browser 命令传递；Website、Product、public Facade 或任意调用方不得在运行时提供 selector，也不得获得通用 selector/JavaScript 执行能力。

### 6.3 对 Browser DOM 方案的吸收与校正

| Browser DOM 方案主张 | V3 裁决 | 最终规则 |
| --- | --- | --- |
| 一个 Browser DOM engine | 保留方向，收窄含义 | 只允许一个 Browser Owner 和一条 canonical DOM reader/action path；不新建中央 Child 语义引擎 |
| exact Target/current Document | 完整保留 | 所有 Browser 事实和动作都绑定 exact call、Target、current Document；Document 失效即原包作废 |
| 一份 observation snapshot | 完整保留，但禁止持久化 | 一次裁决只消费一份调用期 coherent packet；不得建立 snapshot registry 或第二事实库 |
| 用 Document epoch/hash 保证一致 | 不充分 | Document identity 相同不能证明 React 未重绘；必须由单条 typed observation 原子采集，或由 Browser 证明调用期 revision 未改变 |
| READABLE/ACTIONABLE/FILE_INPUT_TARGET 三种统一 strategy | 不原样采用 | 保留底层机械维度和 file-input 特例；不得形成取得 Child 语义的公共 strategy DSL |
| 新增 NOT_FOUND/NOT_RENDERED/OUTCOME_UNKNOWN 等状态和错误 | 拒绝直接引入 | 使用现役 Browser typed cause 和 DISPATCHED/CONFIRMED/REJECTED；任何新枚举都需单独法案/Blueprint 授权 |
| Child 向 Browser 提供 selector | 有条件保留 | 只能是 Child 私有、源码冻结、typed permit 内的 selector/scope；绝不能变成 public caller 参数 |
| 固定跑全产品组合和连续 50 单 | 拒绝作为统一配额 | 使用共同硬门、画像附加门和真实消费者旅程；并发/连续运行规模由实际容量与风险决定，不造数字型 PASS |

### 6.4 调用期 coherent observation packet

页面 Child 所需的统一 Browser 返回形状是“稀疏而完整”的调用期事实包，不是每个 Child 都填满一份大而全的表：

    BrowserDomObservationPacket<TFacts>
      exact_call_identity_hash
      target_ref_hash
      document_ref_hash
      observation_revision_hash
      observed_at
      facts: TFacts
      native_cause_code | null

硬约束：

- `observation_revision_hash` 只证明本次调用期事实的一致性，不是持久状态、恢复凭据或新 registry。
- 若 Browser 无法证明多个 CDP 读取处于同一 revision，就必须改成一条 typed observation 在扩展侧一次采集；不能由 Child 拼接。
- `TFacts` 只返回该 Child 合同实际需要的机械事实；不存在“字段越多越稳定”的要求。
- 事实包过期、节点断开、Document/revision 改变时整包失效，Child 只能 fresh observe。
- proof 只投影稳定 hash、基数、typed cause 和结果引用；不把整个事实包或 DOM 快照持久化。

Browser 可按真实消费者提供的机械事实维度包括：

- scope 与 candidate 的 raw count/eligible count。
- `connected` 的真实值，而不是常量。
- layout box 是否存在及坐标是否合法。
- computed display/visibility/opacity、HTML hidden、aria-hidden、inert。
- HTML disabled、aria-disabled。
- viewport 与命中测试事实，仅在真实物理指针动作需要时采集。
- 该 typed 命令必需的 role/name/testId/label/value/checked/type 等精确属性。
- CDP/协议原生 cause 和发生阶段。

Browser 可以机械判定“这次物理动作是否安全可执行”，但不能把机械事实升级为“模型面板已正确打开”之类 GPT 语义。隐藏 file input 是独立 typed mutation：它必须证明 exact input、`type=file`、connected、授权文件集合和 Document 绑定，不要求像可点击按钮一样可见或命中测试。

### 6.5 现役 typed cause 的统一映射

本方案不创建第二套 Browser 错误词典：

| 观察事实 | 现役唯一表达 |
| --- | --- |
| exact Target 不合法 | `BROWSER_TARGET_INVALID` |
| current Document 不合法或已更换 | `BROWSER_DOCUMENT_INVALID` |
| 合法 scope 内候选为 0 | `BROWSER_DOM_CANDIDATE_MISSING` |
| 合法 scope 内候选大于 1 | `BROWSER_DOM_CANDIDATE_AMBIGUOUS` |
| 节点断开、旧 node/revision 失效 | `BROWSER_DOM_NODE_STALE` |
| CDP record、数值、坐标或协议 payload 真的畸形 | `BROWSER_DOM_READ_INVALID`，并保留安全的 native cause/stage |
| 节点 connected 但没有 layout box | 正常机械事实，不冒充 payload invalid，也不自动等于 Child failure |

`UNKNOWN` 可以是 Child 对未知页面语义的失败关闭原因，但不得成为新的 Browser terminal。mutation 命令跨越不可逆边界后收不到终局证据时，Browser 继续诚实保持 `DISPATCHED`，而不是另造 `OUTCOME_UNKNOWN`。

### 6.6 跨进程 mutation 原子边界

当前 Browser 服务端与扩展之间存在真实进程边界。生产模型必须按实际顺序定义：

1. GPT Child 用 coherent packet 裁决 ACT，并提交绑定 exact call、Target/Document、最小机械谓词、zero-action predicate、动作身份及正反后置的 typed permit。
2. Browser 服务端验证认证、authority、exact call 和 permit 形状，在唯一 WAL row 写入 PREPARED。
3. 在把 mutation-capable 命令发送到扩展这个不可逆边界前，将同一 WAL row 推进为 DISPATCHED；此后无论是否收到扩展回复，同一 exact call 都不得再次发送物理动作。
4. 扩展在同一条 typed 命令内重新绑定 exact Target/current Document，并原子重验冻结的候选基数和机械谓词；它不解释 GPT 语义。
5. 扩展只允许四种物理结局：
   - zero-action predicate 成立：物理输入为 0，返回 fresh facts；Browser 可结算 `CONFIRMED + mutation_outcome=no`，GPT Child 再裁决 DONE。
   - 动作机械资格不成立：物理输入为 0，返回 fresh facts/cause；Browser 结算 `REJECTED + mutation_outcome=no`，GPT Child 再裁决 WAIT 或 FAIL_CLOSED。
   - 动作机械资格成立：只执行一次物理输入，并按冻结的直接读回结算 `CONFIRMED` 或 `REJECTED`；物理输入事实与语义后置分别保留。
   - 回复或终局证据缺失：保持 `DISPATCHED + mutation_outcome=dispatched`，只允许原 attempt 对账。
6. GPT Child 只消费 Browser 安全投影和新鲜后置，不读取 raw WAL、Target 或 Document，也不获得重新发送资格。

这套顺序承认“命令已 dispatch”不等于“物理输入已发生”，同时保证最坏情况下也不会因为网络、扩展崩溃或结果未知而重复点击。现役实现尚未完整表达上述 `DISPATCHED + physical mutation 0/1 + terminal` 的正交结算，因此这是实施 GAP，不是已完成事实。

### 6.7 21 个页面 Child 如何消费 Browser

| Child 画像 | Browser 必须提供 | Browser 不得替 Child 决定 |
| --- | --- | --- |
| DOM_OBSERVATION（6） | coherent packet、exact Target/Document、typed cause | 业务事实是否足以 success |
| TARGET_LOCAL_MUTATION（12） | coherent packet、typed permit、WAL、物理 0/1、fresh readback | DONE/WAIT/FAIL 和 Product 下一步 |
| PROVIDER_EFFECT_ONCE（3） | 上述全部 + exact effect identity、不可重放事实、Forensics 安全投影 | Provider 业务是否最终完成 |
| CONTINUATION_TRANSACTION（6） | 不消费 Browser | 任何 session/CAS 语义 |

这张表与 5.2 的 27 个 Child 映射共同构成唯一分母；不得在 Browser DOM 方案内再维护第二份 Child 清单或第二种分类。

### 6.8 当前必须先关闭的 Browser/Child 联合阻塞

1. **物理事实不可信。** `connected=true` 常量、box model 近似 visible、disabled 事实不完整，必须先修到能支持真实 Child 的最小机械判断。
2. **观察不相干。** 模型 topology 和附件状态仍由多次读取拼接，必须先提供至少一个真实消费者所需的 coherent typed observation。
3. **cause 不稳定。** no-layout 不能继续依赖有限英文 message 文本，协议错误必须保留稳定分类和安全 root cause。
4. **上传 scope 过宽。** “Upload from computer” 等入口必须绑定已证明的当前菜单/面板 scope，不得全页面文本猜选。
5. **fork 代码尚未追上已裁决权威。** V4 已依据明确授权把真实两步拆为 `open_gpt_checkpoint_actions_menu` 与 `fork_exact_gpt_conversation_at_checkpoint`；当前实现仍是旧单 Child selector。代码阶段必须删除旧路径并按两份独立合同重建，禁止循环点击、fallback 或把两 action 合回一个 handler。
6. **结算模型尚未落地。** 当前服务端 DISPATCHED、扩展实际 mutation 和 terminal projection 还没有完整表达第 6.6 节四种结局，不能宣称 Browser DOM 已生产级。

以上结构 GAP 关闭前，Browser DOM 和依赖它的 21 个页面 Child 都不得依据本方案声称“生产级稳定”；6 个 continuation Child 则按自己的 transaction/CAS 证据独立验收。

## 七、十二条生产级强制规则

### SC-01：一个 Child 只拥有一个可独立验证的原子语义意图

- observation Child 只拥有一个直接事实证明，不拥有 Provider 状态变化。
- mutation Child 只拥有一个状态变化和至多一次动作。
- transaction Child 只拥有一次精确 CAS 或相同内容读回。
- 一个 Child 不得同时拥有两个独立状态变化，不得理解 Product 下一步或业务终态。

判断标准不是“做了几个 find/click”，而是“能否独立给出完整直接后置”。

### SC-02：共同合同一份，局部语义各自唯一

所有 Child 使用第四章的八项合同形状；每个 Child 的具体 DOM 身份、状态谓词、可等待条件、直接后置和 typed reason 只由该 Child 的局部合同拥有。

禁止为了“统一”建立：

- 中央 classifier、executor、planner 或 workflow。
- 公共 wait/replay 状态机。
- variant registry、snapshot 表或第二 proof store。
- 让 public Facade 在 handler 前后偷偷追加观察、重试或后置。

公共原语只有在至少两个现役 Child 已证明需要同一产品中性机械能力，并且消费者、Owner 和验收均明确时才可增加；否则留在局部 Child。

### SC-03：一次裁决必须来自一份完整的权威事实包

页面 Child 的动作许可或成功判定必须来自：

1. 当前 exact Target/current Document 内的一次 Browser 原子 observation；或者
2. Browser 可验证地证明多次读取期间同一 revision 未改变。

仅仅前后 DocumentRef 相同，不能证明 React 没有在中间重绘。

具体要求：

- 多对象事实不得由多次 findCount 无证明拼接。
- stale、Document/revision 变化或节点断开后，整份事实包作废，从头 fresh read。
- 事实包是一次调用期返回值，不持久化，不形成 snapshot registry。
- session Child 必须在一个 transaction/version readback 中形成完整事实。
- 如果当前 Browser 接口不能表达某个 Child 的完整多对象事实包，这是一项明确的最小跨 Owner 接口 GAP；不得由 Child 用旧事实模拟。

### SC-04：使用最小充分事实，不设“越多越强”的配额

事实仍分为：

- 身份事实：证明对象是谁。
- 状态事实：证明对象现在怎样。
- 诊断事实：解释为何不能继续，不能单独授权动作。

动作或成功只需要当前真实环境中能唯一证明语义身份的**最小充分事实集合**：

- 一个完整机器事实足够时，不得人为再绑脆弱属性。
- 一个事实不足时，必须用确定合取补足。
- 禁止打分、最像、模糊 fallback、selector A/B/C 或默认取第一个。

variant 只用于真实存在两种或以上、且被现役权威允许的合法 DOM 结构：

- 单一结构直接使用 canonical local contract，不创建形式化 variant。
- variantId 归属 childContractVersion，不增加第二版本轴。
- 新 selector 加上 variantId 不会自动合法；必须先有真实证据并依法更新对应权威。
- CONTINUATION_TRANSACTION 不使用 DOM variant。

### SC-05：内部裁决只有四个瞬时分支，公开结果始终只有两种

Child 可在一次调用内部使用以下非持久标签：

    DONE         整个直接目标已成立，零动作成功
    ACT          当前完整动作资格成立
    WAIT         有正面证据证明处于受支持的短暂收敛过程
    FAIL_CLOSED  未知、多义、冲突、终止负例或合同漂移

这些只是局部实现标签：

- 不进入 Product 状态。
- 不成为 proof verdict、数据库状态、恢复 phase 或第三种公开结果。
- 不适用的分支不需要伪造 N/A 字段。

公开 Child terminal 永远只有：

    success(value, evidence)
    failed(typed_reason, evidence)

Browser 的 DISPATCHED/CONFIRMED/REJECTED 是独立权威事实，不是 Child 第三种结果。

### SC-06：等待资格和 deadline 分属不同 Owner

“找不到”本身不是 WAIT。只有 loading、generating、uploading、Provider 已接受但尚未 ready 等合同明确的正面事实，才能 fresh probe。

责任固定为：

- Product：冻结 Provider 总等待策略并传入 timeoutMs/absoluteDeadline 所需输入。
- GPT wait/reconcile Child：在本次调用内拥有短 probe、fresh observation、瞬时退避、取消检查和直接收敛。
- Browser：拥有原子 observation、物理 FIFO、park/reacquire 和 submit 首次 CONFIRMED 的 immutable terminalAt；不裁决等待成功。
- Website：拥有跨 attempt 的 retry_not_before、claim、业务撤权和任务继续资格。

local hydration/direct postcondition timeout 可由 Child 局部合同有界声明；它不能覆盖 Product 的 Provider 总期限。deadline 到期只结束本次 Child/probe，不能改变已 CONFIRMED Provider effect，也不能授权重新提交。

### SC-07：目标已完成时零动作；动作资格必须在 dispatch 原子边界再验证

DONE 判断针对整个 Child 的直接后置，而不是一个局部属性。

进入 ACT 后，Child 只提交固定、局部、typed 的动作合同。GPT Child 的局部合同唯一定义并裁决 ACT 谓词；Browser 不解释 DONE/ACT/WAIT/FAIL_CLOSED，也不取得 Provider 语义。

Browser 必须按第 6.6 节的真实跨进程边界执行：服务端先验证 authority/permit 并写 PREPARED，在 mutation-capable 命令离开 Browser Authority 前写 DISPATCHED；扩展随后在同一条 typed 命令内重新绑定 exact Target/current Document、机械重验候选和冻结谓词，并只允许物理输入 0 或 1。zero-action satisfied、资格不成立、一次物理输入和回复缺失分别按现役 Browser outcome 与 `mutation_outcome` 正交结算。

这关闭“先观察、页面重绘、仍凭旧事实点击”的 TOCTOU 窗口，也避免虚构跨进程不存在的“扩展先重验、服务端后写 DISPATCHED”原子性。Child 不读取 raw Target、Document 或 WAL row，也不自行决定跨 attempt 恢复。

如果现有 Browser 命令无法携带完成某一 Child 所需的最小动作资格，后续实施只能增加该真实消费者所需的最小 typed permit；不得建立通用脚本、任意 selector/JavaScript 或中央动作引擎。

### SC-08：dispatch 是单向门，generation 不是重做许可证

对同一 exact call：

- 一旦已有 verified evidence，或 Browser 已有 DISPATCHED、CONFIRMED、REJECTED 任一事实，换 Document 或 Target generation 都不得重做物理动作。
- 新 generation 只有在 Browser Owner 能证明该 exact call 从未 dispatch、没有 verified evidence、没有任何 WAL 事实时，才可能承载它的首次动作。
- DISPATCHED 或结果不明只允许原 attempt 在原合法现场只读/幂等对账。
- Provider submit 已有唯一 CONFIRMED + passed receipt 且原 Target 权威不存在时，只允许同一 accepted attempt 在新合法 system Target 上按 submission locator 只读重证，所有 Provider mutation 增量为零。

Product 通过现役 readCallFacts 的安全事实投影决定跳过或继续自己的静态 Flow；Browser/WAL 拒绝重复物理 dispatch；GPT Child 只处理当前一次合法调用的局部前置、动作和直接后置。三者不得互相取得恢复裁决权。

### SC-09：动作前冻结完整正、反后置，动作后只用新鲜权威读回

正后置说明什么事实证明成功；反后置说明什么事实证明没有错误、多余或越界结果。

- mutation Child 在 dispatch 前冻结完整正、反后置并绑定 exact action identity/hash。
- observation Child 使用直接成功谓词与 typed 失败谓词，不伪造 mutation postcondition。
- transaction Child 冻结 CAS identity/version、期望写集和 identical readback。
- 动作命令没报错不等于语义成功。
- 动作前节点、旧 snapshot、旧 receipt 或旧 Document 不能冒充当前直接后置。

dispatch 后只能新鲜 readback/settle，不能返回动作门再次尝试。

### SC-10：Child 证据、Browser 事实和恢复决策必须正交

最小安全 proof envelope 应表达：

    child_capability_id
    child_contract_version
    child_status = success | failed
    child_reason_code
    exact_call_identity_hash
    internal_decision_code  # 可选诊断，不是状态权威
    authority_ref_hashes
    fact_result_ids
    candidate_cardinality
    mutation_outcome = no | dispatched | confirmed
    postcondition_result = passed | failed | pending
    browser_fact = null | {
      exact_call_identity_hash
      child_capability_id
      effect_scope = target_local | provider_effect
      browser_outcome = DISPATCHED | CONFIRMED | REJECTED
      mutation_outcome = no | dispatched | confirmed
      terminal_at = null | immutable_timestamp
      evidence_ref
      evidence_hash
    }
    native_failure_code

硬规则：

- mutation_outcome 不包含 rejected。
- browser_fact 为 DISPATCHED 时 terminal_at 必须为 null；只有 CONFIRMED/REJECTED 的 terminal_at 是不可变非空时间。
- 外层 mutation_outcome 只描述当前 Child；嵌套 browser_fact 只描述它自己的 exact effect，二者不得按邻近关系合并。
- Browser outcome 不得由 mutation_outcome 或错误码推断。
- 原 confirmed submit 与后续只读 Child failure 必须同时保留，不能互相覆盖；两者必须保留各自的 exact_call_identity_hash。
- Target/Document 只进入不可逆 hash 或 Browser 安全投影，不泄漏 raw identity/WAL row。
- Browser proof、日志、wire envelope 不得持久化原始 DOM/HTML、Prompt、用户输入、cookie/token、资源 URL 或可变本地路径；现役法案明确允许的 task-owned 精确响应 artifact 仍由其唯一 Owner 按专门合同保存，不得被本 proof envelope 复制。
- proof 不决定 Product 下一步，不成为第二 quality verdict。

### SC-11：未知状态失败关闭，修复只落在最小合法 Owner

动作前出现 missing、ambiguous、stale 后不能闭合、UNKNOWN、合同漂移或事实冲突时，必须零动作失败。

动作后未知必须保存真实 DISPATCHED/CONFIRMED/REJECTED 和 postcondition 事实，只读对账，不得声称动作未发生。

事故修复先判定：

| 故障性质 | 唯一修复位置 |
| --- | --- |
| 无关 wrapper/class/顺序变化 | 若不属于最小充分事实，Child 不应修改 |
| 已知 transient 变慢但仍在 Product timeout 内 | 不增加 selector 或特例；继续同一 fresh probe 合同 |
| 新的真实合法 DOM 结构 | 只修改该 Child 局部合同；有真实证据且对应权威允许后才加入 |
| Browser typed cause 或原子 observation/dispatch 缺口 | 只修 Browser Owner 的最小机械表面 |
| continuation CAS、授权或 commit readback 缺口 | 只修唯一 Session Controller/store |
| Child 顺序、跳过、重试或业务恢复变化 | 只修 Product Plugin |
| 任务 retry、撤权或最终入库 | 只修 Website |

不得在相邻 Child 复制兼容分支，不得改变 Product Flow 绕过故障 Child。

### SC-12：稳定性必须由“共同硬门 + 画像附加门”证明

正常路径跑通只是一例，不是稳定性证明。测试分母由合同声明的全部状态分区和该画像适用的破坏算子组成，不要求不存在的无限状态。

#### 全体共同硬门

- 精确输入与 Owner/boundary。
- 直接成功和 typed fail-close。
- 公开结果只有 success/failed。
- mutation budget 为 0 或 1。
- 无跨 Child/跨 Owner 副作用。
- 无 fallback、模糊猜选和默认第一个。
- 证据 hash/字段闭合且不泄漏敏感数据。
- 相同输入和相同权威事实产生相同裁决。

#### DOM_OBSERVATION 附加门

- 候选 0/1/多义。
- stale、no-layout、payload invalid 和真正 Target/Document failure 分开。
- connected、layout、computed style、hidden/inert、HTML/ARIA disabled 等机械事实逐项可造假验证，不能再用常量或单一 box model 代替。
- 多对象事实包中途重绘时整包作废。
- bounded-wait 只对明确 WAIT 事实继续。
- mutation 增量始终为零。

#### TARGET_LOCAL_MUTATION 附加门

- DONE 零动作，ACT 恰好一次。
- 观察后、dispatch 前重绘不能授权错误动作。
- mutation command 已 DISPATCHED 但扩展重验后物理输入为 0，以及扩展回复丢失的场景，都不得产生第二次发送。
- 正/反后置分别缺失的负例。
- dispatch 前/后中断。
- 新 Document/Target generation 不产生重复动作资格。
- wait text/image 的精确频繁提示同次调用至多确认一次。

#### PROVIDER_EFFECT_ONCE 附加门

- PREPARED、DISPATCHED、CONFIRMED、REJECTED 和 return 前崩溃。
- submit/upload/fork 已 confirmed 后再次 mutation 为零。
- Target 丢失、进程重启和 readback timeout 不重做 effect。
- Provider 直接后置和 Browser WAL/Forensics identity 闭合。

#### CONTINUATION_TRANSACTION 附加门

- exact identity、authorization、owner/subject 和 version mismatch。
- 并发 CAS 冲突。
- commit 后 return 前崩溃。
- identical readback 幂等返回。
- reserve/complete/acquire/advance/release 各自只拥有一个 CAS，不互相顺带执行。

#### bounded-wait 附加门

- 明确 WAIT 与普通 missing 的差异。
- deadline 边界、取消和进程重启。
- fresh probe 不累积旧事实。
- immutable terminalAt/absoluteDeadline 不因重启刷新。
- 到期零额外 mutation。

## 八、生产级稳定性的验收硬门

### 8.1 单个 Child

任一项不成立，该 Child 只能称为“能跑”：

- [ ] 八项共同合同完整且机器可检查。
- [ ] 画像唯一，bounded-wait 特征明确。
- [ ] 一个可独立验证的语义意图，无 Product Flow。
- [ ] 完整事实包不拼接不同瞬间。
- [ ] 页面 Child 只消费 Browser coherent packet；DocumentRef 相同不冒充 React revision 相同。
- [ ] 最小充分身份事实，无多余脆弱依赖。
- [ ] 内部四分支覆盖本合同全部可达状态，公开只返回 success/failed。
- [ ] DONE 为零动作，ACT 至多一次。
- [ ] dispatch 前在 Browser/CAS 原子边界重新验证。
- [ ] 页面 mutation 的 PREPARED/DISPATCHED/扩展重验顺序与第 6.6 节真实进程边界一致。
- [ ] dispatch 后只读，generation 不产生重做资格。
- [ ] 正、反后置或 transaction readback 完整。
- [ ] Child、Browser 和恢复事实正交投影。
- [ ] 共同硬门和本画像附加门全部通过。
- [ ] 取得与权威表面对应的当前动态证据。

### 8.2 全体 27 个 Child

## 九、最小施工顺序

本文档不授权施工。获得单独实施授权后，按以下顺序执行：

1. **先修 Browser 最小可信事实底座，只覆盖已有真实消费者。**
   - 删除 `connected=true` 等伪事实。
   - 把 connected、layout、style/hidden/inert、disabled/aria-disabled 和 payload validity 分开。
   - no-layout 使用结构化 CDP 分类，不继续依赖两个英文 message。
   - 保留现役 typed cause，不创建第二错误词典。
2. **为两个真实消费者建立 coherent observation。**
   - `open_gpt_model_selector_v2` 的完整 topology。
   - `reconcile_gpt_attachment_set` 的 region/labels/ready/spinner。
   - 优先扩展现有 canonical Browser intent/runtime，不新建 snapshot service 或 registry。
3. **打通真实跨进程 mutation 结算。**
   - 用 `open_gpt_model_selector_v2` 验证 PREPARED、DISPATCHED、扩展重验、物理 0/1 和 terminal projection。
   - 覆盖 TOCTOU、扩展崩溃、回复丢失和新 generation 禁重做。
4. **同步校正现有 Child contract 的画像和真实 mutation budget。**
   - wait text/image 不能继续被泛化为绝对零动作 observation。
   - 6 个 continuation transaction 不能继续套 target-local-per-generation。
   - 不新增第二 registry，只重建现有唯一 contract 表达。
5. **再验证三种其它画像。**
   - DOM_OBSERVATION：reconcile_gpt_attachment_set。
   - PROVIDER_EFFECT_ONCE：submit_exact_gpt_turn_once + reconcile_gpt_turn_submission。
   - CONTINUATION_TRANSACTION：一个 reservation/lane CAS Child。
6. **关闭上传与 fork 的专门阻塞。**
   - 上传入口收窄到已证明的局部 scope，file input 使用专门 typed mutation。
   - fork 按已授权权威先实现 `open_gpt_checkpoint_actions_menu`，再实现只点击唯一叶子一次的 `fork_exact_gpt_conversation_at_checkpoint`；Product 显式排列，旧单 Child 双动作路径物理删除。
7. **只补四个原型共同证明需要的最小机械原语。**
   - 至少两个现役消费者。
   - 产品中性。
   - 唯一 Owner。
   - 有确定性和动态验证。
   - 不取得局部语义或流程裁决权。
8. **按画像逐个转换 27 个 Child。**
   - 每次一个可验证语义切片。
   - 新路径成立即物理删除旧粗分类或自写旁路。
   - 不留 wrapper、fallback、双轨或兼容桥。
9. **最后重建完整验收。**
   - common matrix。
   - profile-specific matrix。
   - 当前版本真实 Chrome/Provider 或 storage/CAS。
   - 连续/并发规模来自真实容量和风险，不用任意固定次数替代合同覆盖率。
   - 当前版本完整 CI 和唯一 quality verdict。

## 十、完成后必须达到的内部架构

    Product Plugin
      拥有 Child 顺序、timeout 策略、readCallFacts 后的跳过/恢复决策
            ↓ execute one Child
    GPT Child
      拥有八项合同、局部事实、局部裁决、至多一次动作意图、直接后置
            ↓ typed observation / typed mutation permit
    Browser Authority
      拥有 exact Target/Document、coherent mechanical observation、dispatch、WAL、terminal fact、FIFO/park
            ↓ mutation-capable command after WAL DISPATCHED
    Browser Extension
      同命令重绑 current Document、机械重验、物理输入 0/1、fresh fact/readback

    GPT Session Child
      ↓
    唯一 Session Controller / continuation store
      拥有 exact transaction/version/CAS/readback

    Runtime
      只运输、绑定 attempt/lease/fence、保留 typed facts、交付 staged result
            ↓
    Website
      拥有 retry/claim/撤权、领域接收、入库与业务 completed

任何层都不能因为“稳定性统一”而取得相邻层的决策权。

## 十一、最终准则

以后评价一个 Child，不再问：

> “这个 selector 现在能不能点？”

而是问：

> **“它是否只拥有一个原子语义意图；是否从同一权威事实包作出确定裁决；是否只在 Browser/CAS 原子门内执行至多一次动作；是否在 dispatch 后只读收敛；是否用与自身画像相匹配的破坏证据和真实权威读回证明直接后置？”**

只有答案是“能，而且当前版本已被对应画像的摧毁式验收与真实权威证明”，它才是生产级强壮子能力。
