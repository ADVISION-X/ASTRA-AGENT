## 2. 新合同：起始值、候选顺序与停止线

### 2.1 Product 提供的唯一策略输入

Product profile 保留既有 profileRef、executorIdentityRef、acceptanceRef/version 与完整性 hash；本题的两个策略输入改名为 `startModelDisplayName`、`startReasoningTier`，以“起始”而非“全局期望/默认”防误解。当前 `accountCapabilityRef/modelFamily` 在生产侧除 profile 声明及 hash/parse 外尚未找到行为消费者；目标合同先作逐字段删除反事实，确认无真实消费者即从 v3 物理删除，**不**另建 GPT 模型映射。移除 Product 侧的 `selectionPolicy=exact/exact-or-observed-maximum` 作为降级裁决字段。目标 profile 合同在实施时原位升版，严禁运行时双读 v2/v3 或把 v2 偷偷解释成新语义。Skill/Plugin 不给候选列表、额度判断、重试次数或实际模型。

当前获准目标域只有两种模型标签 `最新`、`GPT-5.6 Sol`，三种推理档 `pro_standard/extra_high/high`；低于 High 不是本方案的自动降级出口。若将来出现新模型或档位，先走拓扑/合同变更，不以“通用算法”推断字符串或能力。现役 schema 中 Fast/Medium 的其它潜在调用，不得被本方案隐式升级或降级；本候选生产 profile 分母没有这种调用。

### 2.2 从每个技能起点取后缀的唯一降序规则

共用规则只有两个**有序轴**：模型 `[最新, GPT-5.6 Sol]`，推理 `[Pro, 极高, 高]`。一张工单的候选只能从 Skill/Plugin 实际声明的 `(startModelDisplayName, startReasoningTier)` 两个起点分别向右取后缀，不得重置到序列首项。比如固定 catalog 的 `Sol/Pro` 只能尝试 Sol 下 Pro→极高→高，绝不先切“最新”；文章的 `最新/极高` 只从极高开始，绝不先试 Pro。后续任何新技能即使复用这份共用规则，也必须显式给出自己的起始 pair。

上述两个轴是**授权人确认的业务优先级**，不是按账号永久固定的页面布局。两种已证 UI：A 在 `最新` 及随后选中的 Sol 下均以 slider `0..4` 的第五档显示 Pro，且没有单独 Pro radio；B 在 `最新` 和随后选中的 Sol 下 slider 都只有 `0..3`，Pro 另以禁用 radio 显示。故不能再断言“Pro 永远是独立 radio”或“账号徽标为 Pro 就必有第五档”。G16 选择实际模型之后，G17 必须在当前 Target/Document **重新观察该模型下的强度形态**，不能沿用选择前的刻度。未知组合、可用的独立 Pro radio、或无明确禁用事实的 Pro 缺席均不得编造动作映射。AGENT Child 的动态正反验收只在修复 G03 后进行，不能要求现役 G03 穿过已知的 `0..3` HARD_FAIL。

上表 A 的 Sol/Pro 与 B 的 Sol/极高均已有人工同页 UI 证据，但都不是 AGENT 自动流程验收。仅有 G16 旧 proof 与同一 Target/Document **不够**，因为同 Document 内模型可能变化。G17 必须把已选模型 exact 文本/`aria-checked=true`、已选 radio 总数、当前 slider、Pro 禁用事实放进**同一 fresh coherent packet**，并与 G16 的实际模型及后置 Target/Document 核对；任何一项缺失或相反即失败。现役 Browser 只让普通 eligible 节点进入 `matches`，所以需在唯一 Browser observation 原位增加窄口径的只读 `non-actionable-inert-state`：只允许 `observe`，仅绕过 `INERT` 对指定模型/Pro radio 的**读取过滤**，必须仍返回 `inert=true`、真实 connected/layout/hidden/ARIA disabled，物理动作及其候选资格仍完整拒绝 inert；不建第二 DOM 读取链。该模式及精确字段已由本次授权覆盖，并须在 Browser 施工图与代码中保持一致；不得用 rawCount 或 Document 身份冒充选中模型。

G17 的选中模型 query 固定为 `selector='[role="menuitemradio"][aria-checked="true"]'`、`textEquals=G16.value.modelDisplayName`、`readEligibility='non-actionable-inert-state'`、`fields=['ariaChecked','inert']`；同包必须 `rawCount=1,eligibleCount=1,ariaChecked=true,inert=true`。现役 Browser 对 selector 得到的原始节点先计 `rawCount`，再对 `textEquals` 判资格，因此另一个模型同页被选中会使 raw 基数或 eligible 基数不符，不能漏判；证明是受信任的查询规格加返回基数，不伪称 Browser 返回了原始文本字段。B 的 Pro query 固定为 `selector='[role="menuitemradio"][aria-label="Pro"][aria-disabled="true"]'`、同一 readEligibility、`fields=['ariaDisabled','inert']`；必须唯一且两个字段为 true。该只读模式不放宽 `connected/layout/hidden/ariaHidden/display/visibility/opacity`，不适用于 mutation、postClickMatch、点击或键盘资格；若页面改为无 layout、aria-hidden 或属性漂移就先失败并回到拓扑补事实，不添加隐蔽 DOM 兜底。

顺序是先解析一个起始模型，再在该模型下从起始推理档向下解析；若起始模型在**G16 模型选择点击前**同一 fresh packet 唯一且 `aria-disabled=true`，才看模型后缀下一项，并在新模型下仍从**该技能原始起始推理档**开始。起始模型已唯一选中则零输入成功，并从该次 fresh observation 取得实际模型与后置 Target/Document 双哈希；否则至多点击一次，再从同次 mutation 后置包取得双哈希。**模型可选但无 High 及以上档位时，失败关闭；不得为碰运气切换到另一模型。** 任何实际 pair 都必须逐项在当前账号、当前 Target、当前 Document 的 fresh coherent observation 中被证明可选；Pro 订阅徽标不是推理档可用性，slider `max=3` 单独也不证明 Pro 为什么不可选。B 型的 `Pro[aria-disabled=true] + slider 0..3` 是已证的动作前不可选组合；若选中 Sol 后仍成立，G17 才按起点后缀取极高。灰置、缺席、显式拒绝与普通 transient DOM 必须区分。

**普通缺席不是不可选证明。** G15 的唯一“选择模型”入口点击可以先终结为 `CONFIRMED`；点击前仍用现役 `[aria-expanded='false']` exact selector 约束收起入口，点击后用现役 Browser `postClickMatch` 对独立的 exact base selector 加 `[aria-expanded='true']` 作唯一匹配，并核 Target/Document 连续性。这是点击后 fresh 入口状态证明，**不是**保留原 nodeId 的同节点证明，也不查询“起点或后缀至少一个”的 OR 候选。A/B 已证明主页菜单入口存在，未证明该模型子入口的生产 Target 点击后状态。G15 不决定实际模型，G16 才在自己的 fresh 当前菜单观察中解析起始模型及后缀。现役 `TRANSIENT_DOM` 依 Browser 唯一 1.5 秒、3 秒整包只读复核；第三次仍 transient 必须按原生事实失败，不能改名为 `MODEL_UNAVAILABLE` 或额度耗尽。仅 G16/G17 **选择点击前**同一 fresh 页面事实能精确证明相应起点 disabled/不可选时，才允许该 Child 取下一候选；`absent` 没有菜单完整性实证，当前不作为降级条件。一个 Child 仍至多一次 Browser 物理输入；G15 开门若 REJECTED/未决、G16/G17 选择点击若 REJECTED/未决或泛化拒绝，都保留首个 typed failure/唯一 WAL，交 Website 裁决旧 attempt，不能在同 attempt 再点下一档。多个同名候选、文案冲突、Target/Document 漂移、限流弹窗或菜单关闭也不得解释为“该档不可用”；已知“请求过于频繁”只走现役 Browser 中央冷却门。

### 2.3 关键结果与证据

成功事实只在**当前 Product/GPT 调用内存**中传递：起始 pair、实际 pair、动作前跳过原因、现役 observation revision、exact 目标的直接后置证明。Browser 的物理终态仍由唯一 WAL 保存；普通 Child proof 不进入 Forensics、Outbox、Website wire、数据库或第二 ledger。现役 Website 只接收原有业务结果及失败/effect 事实；它不接收实际 pair 或逐候选列表。若未来要求按已入库工单查询“实际模型/档”，必须先找出该业务域持久 execution evidence 的真实 producer/consumer 与合法字段，再单独授权合同变化；本方案不凭一句“可复盘”新增成功证据持久化。

**G15→G16→现役第二次 G03→G17 的原子 handoff**：在必要解冻和合同升版后，G15 仍至多点击一次唯一的收起态菜单入口，已展开则零点击；其直接后置用独立展开态 selector 的 `postClickMatch` 证明当前入口唯一展开，**不**宣称 retained-node 同一性，也不证明任何模型候选的数量或可用性。G15 不决定实际模型。G16 接收 Product 原始、hash 已验的起始 profile，在自己的 fresh coherent observation 中按该模型起点后缀解析最高合法可选项；纯缺席不降级。G16 对自己解析的唯一 exact 选项已选中时零输入，否则至多点击一次，并由同次 Browser mutation 对被点击节点证明 `aria-checked=true`、该选项退出当前**可操作**集合；其现役 `value.modelDisplayName` 改为**实际已选模型**，另从**同次后置 observation packet**提取 `targetRefHash/documentRefHash` 写入本轮 GPT typed 成功值。现役 `GptChildBrowserFact` 与 Child proof 均没有这两个显式字段，不能声称“原样传 proof 即可”。Product 继续执行现役 `profile-open-after-model`，由第二次 G03 重新展开当前 profile；B 的 Sol 选择后 radio 仍在 DOM、但位于 `inert` 子视图。Product 只把 G16 的已确认实际模型、该后置双哈希及原始起始推理档原样传 G17，不构造候选。G17 用同一 fresh coherent packet 读取：当前恰好一个 `aria-checked=true` 模型 radio，按 exact `textEquals` 匹配 G16 模型且该节点 `inert=true`；当前 slider/档位；B 分支 exact `aria-label=Pro,aria-disabled=true` 的 Pro radio（读到 `ariaDisabled=true,inert=true`）。G17 同时核 packet 的 Target/Document 等于 G16 后置双哈希；若模型已变，即使 Document 未变也失败，不拼接旧模型与新强度。所有 `inert` 节点只进入获准的非操作性 `observe`，不进入任何点击、按键或后置动作资格。随后 G17 至多点击一次推理档；整个链无 GPT 隐藏编排、无 Product 候选循环、无第二 decision hash/store。

失败保留**第一个原生 typed failure**及 cause 链；确切 code 命名须与现役 Child 合同统一，不另造 Runtime 通用失败。无法证明动作前不可选、纯缺席三次仍 transient、同名多义、点击后拒绝/未决、Target 丢失都不能偷偷变成下一候选。准备失败保持原 `target_local` Browser outcome/mutation outcome，沿 Runtime 既有 first-failure/effect 链交 Website；`target_local + REJECTED` 由 Website 结束旧 accepted attempt 并决定是否签发新 attempt，AGENT 不在旧 attempt 续点。若物理动作结果未明，先沿唯一 Browser WAL 原身份结算，**绝不继续点击下一候选**。Provider submit 已发生后，模型/推理不再重新配型；进程恢复先查同 effect WAL，CONFIRMED 只做零输入回答读回。

## 3. Owner 与端到端链

```text
Product Plugin：给各自起始 pair，保留本轮 Prompt、Child 顺序、业务结果组装
  → GPT G15：经 Browser 唯一 lane 打开菜单，证明当前唯一入口展开
  → GPT G16：经 Browser fresh 观察自行解析模型后缀，已选中零输入，否则精确点击至多一次，返回实际模型
  → Product：执行现役第二次 G03 重新展开 profile，只将 G16 实际模型与新增的后置双哈希原样传 G17
  → GPT G17：同一 fresh packet 核 G16 后置双哈希、当前唯一已选模型与强度，再从起始档解析并至多点击一次
  → Product：只在本轮内存使用 G16/G17 已证明的实际 pair，继续附件/Composer/唯一 submit
  → Runtime：成功按现役业务结果/Outbox 交付；失败保留 first typed failure/effect
  → Website ai-acceptance：只裁决 attempt、result revision、admission/rejection

```

模型/推理匹配只影响 submit 前准备。既有 provider_effect 身份 `[job_id,result_revision,product_step_id,call_id,child_id,request_hash,payload_hash]`、Website task/request identity、父 conversation continuation、附件/Prompt、安全门、限流门、70–90 秒轮询和动态本地化/固定 catalog 的业务路径均不改。任何跨仓合同或数据库迁移都需要先证明现有 Website consumer 读不到必要 typed fact；本方案目前**没有证明**新增 Website 字段、表或迁移的必要性，因此默认零 Website 代码/DB 修改。

| 限流/额度 | 已知“请求过于频繁”弹窗；同 Target 的 Pro 明确 disabled；Pro 仅缺席；点击后才拒绝；仅泛化 popup invalid | 依次走现役冷却门、在 B 型 UI 经选择后再次闭合时降至极高、缺席不降级、保留 first failure 交 Website、失败并要求现场取证；用户报告“Pro 不显示”不能替代菜单完整性证明 |
| 跨 attempt/恢复 | target-local REJECTED 后 Website 新 attempt；同 effect CONFIRMED 恢复 | 前者重做准备且重新配型；后者零准备、零 submit，只读回原 effect |
| 端到端 | 至少一个固定 catalog、一个动态翻译、一个最新版文章/图片相关路径；成功和失败各一 | 调用期 G16/G17 值由 Product 消费；现役业务结果或 first failure/effect→Runtime/Outbox→Website admission/rejection→领域对象 readback；不声称 Website 接收普通 Child proof |

验收不能用 mock 证明真实账号 Pro 额度、页面可选项或图片模型能力；动态证明必须绑定当时账号、Target/Document、DOM 事实与工单/effect 身份。现场取证若发现 UI 没有可证明的“不可选”语义，必须停止自动降级该分支，回到拓扑/方案补充已证事实，不能用点击失败次数拟合额度。

## 7. 防膨胀与删除裁决

## 8. 放行与停止条件

方案本身给出每技能起点、共用后缀业务优先级、Owner、失败语义和有限验收分母；**当前仍不能宣称拓扑新版已冻结或现场问题已解决**。入代码门前须同时满足：① A/B 两种账号样本分别记录：A 在默认账号的同一空白聊天选中 Sol 后 slider `0..4,now=4` 且第五档 Pro，B 选中 Sol 后 slider `0..3,now=3`、Pro exact radio `aria-disabled=true`；两次均已恢复原模型、零 Provider submit，但都不是 AGENT Child 动态验收。现役 G03 已知拒绝 B 的 `0..3`，不得以修复前 AGENT Child 正向运行作为入代码门；② selector 已明确解冻、双仓适用法案经直接条文核对无须升版，GPT/Browser/Runtime 与 Website SYSTEM 施工图须精确对齐并由主 Codex 两轮自审，随后在同一母表冻结拓扑新 hash；v2 G04–G06 已退休、v3 G15–G17 已分配；③ 静态核验 Browser 后置 packet 双哈希可由 G16 **新增 typed 字段**保留（现役 proof 没有显式字段），以及同一 coherent packet 可用受信任的 exact `textEquals` 查询规格、raw/eligible 基数、`aria-checked`、inert/disabled 与 slider 证明当前选中模型，不伪称原始文本已随 packet 返回；普通 Pro 缺席分支不自动降级；④ 双仓目标路径 dirty set 无重叠且当前候选可绑定。代码完成后的动态放行另须在 AGENT 当前生产 Target 上证明 G15 展开后置、G16 实际模型/后置双哈希、第二次 G03/G17 同 Target/Document 同包模型及强度读回、同页模型改变的负例，以及文章/图片实际降级模型的业务输出合同、正反工单 admission/领域 readback。部署切换前另核在途 v2 target-local profile 与未决 submit WAL，不能安全 drain 或按原身份零 submit 结算就不部署。若现场只在点击后拒绝、出现未证的新 UI 形态或无法区分普通 DOM 瞬态与全局限流，停止自动降级该分支，回到拓扑/方案补事实，不在同 attempt 试探。任一入代码条件缺失则失败关闭，不进代码；代码后动态条件缺失则不宣称验收或恢复工单。现有固定文案暂停状态不因本方案建立而自动解除；必须待正式施工、原生 CI 和业务 readback 证明后再由现役 Website Owner 依法恢复。
