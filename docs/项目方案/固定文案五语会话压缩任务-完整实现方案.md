## 第一部分：固定文案 Product 投产闭环

### 1. 最终裁决

当前生产拓扑在现役安全与质量合同下不属于过度设计：

```text
五个 target locale
× C 个 ContextBundle cohort
× Candidate A / Candidate B / blind Selector
= 3C 条 GPT conversation
= 15C 个 Provider turn
```

当前 `C=37`，因此是：

```text
111 条 conversation
555 个 Provider turn
5 个 Website locale task/result/admission
1 个五语 candidate set
```

每条 conversation 只属于一个 `cohort + role`，按固定顺序承载五个独立语言 turn：

```text
zh-HK -> zh-TW -> en-US -> ja-JP -> ko-KR
```

111 是 Provider conversation 分母，不是 Website 工单数，不是翻译消息数，也不是入库或发布证明。代码必须继续按动态 `C` 计算，不得硬编码 37。

最终方案不是继续改架构，而是沿现役唯一链完成真实投产：

```text
Website canonical zh-CN + ContextBundle v2 + public_value_binding
-> zh-HK root task
-> AGENT 领取一次当前授权并执行 3C 个隔离 role turn
-> Browser WAL 保证每个现实 submit 至多一次
-> Website 接纳 zh-HK result 并同事务签发唯一后继
-> 依次完成 zh-TW / en-US / ja-JP / ko-KR
-> 五次 Website admission 与持久结果 readback
-> 现有 import-admitted
-> 现有 publish
-> Website CHANGE / READY / RELEASE
-> 部署版本与线上五语页面 readback
```

任一层没有证据，只能报告最后已证明层级。
