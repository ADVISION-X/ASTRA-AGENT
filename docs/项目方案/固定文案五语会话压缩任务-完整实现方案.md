## 1. 唯一目标与不变终点

当前固定文案生产分母为五个目标 locale、每 locale 37 个 ContextBundle、每 bundle 三个隔离角色：

```text
当前 conversation = 5 locale × 37 cohort × 3 role = 555
当前 Provider turn = 5 locale × 37 cohort × 3 role = 555
```

目标不是减少翻译语言、消息分母或质量角色，而是只改变 conversation 拓扑：

```text
目标 conversation = 37 locale-neutral cohort × 3 role = 111
目标 Provider turn = 111 conversation × 5 locale turn = 555
```

代码不得硬编码 `37`。令当前 ContextBundle 分母为 `C`，机械不变量必须始终是：

```text
conversation_count = C × 3
provider_turn_count = C × 3 × 5
```

每个 cohort 的 Candidate A、Candidate B、Selector 各拥有一条独立 conversation；同一 role 的 conversation 内按 `zh-HK -> zh-TW -> en-US -> ja-JP -> ko-KR` 追加五个独立 turn。A/B/Selector 之间不得共享 conversation、回答或身份。

五语业务终点保持不变：五张 Website locale task、五个 result、五次独立 admission、一个五语 candidate set，之后仍经唯一 import、publish、READY、RELEASE、部署和线上 readback。111 个 conversation 不是入库，更不是发布。

核心法 010 与 UVI-V4 已通过当前 ContextBundle v2 `public_value_binding` 进入既有 Skill/实践链；本任务不再复制一套初心字段或第二裁决。任何会话压缩都不得弱化：

```text
返本溯源，古为今用
-> 来源角色不丢失
-> 确定事实不被增强
-> 当代用途不被替换
-> 工具不得升格为公开价值主体
```

## 2. 与既有闭环总案的边界

本任务只拥有：

- 固定文案 A/B/Selector 的 conversation 数量与隔离维度；
- 五个 locale task 的严格签发顺序；
- exact cohort-role 对应的 Browser locator 读取；
- `localize-user-surfaces` 与 AGENT Product Skill 对该拓扑的准确说明；
- 对应 route contract、实践代码和聚焦质检。

本任务不拥有，也不得在本文件重写：

- confirmed Provider effect 的恢复裁决；
- completion intent、Outbox 或 Website write receipt；
- admission receipt 与 business object readback；
- 术语投影、动态报告/文章翻译、review 材料；
- catalog import/publish/部署；
- 限流冷却、第二 scheduler 或历史任务清理。

施工时必须把原总案视为相邻约束。尤其其 W0、confirmed-effect 与 Outbox 闭环尚未形成可验收 candidate 时，本任务不得进入真实 Provider 执行；不能用“111 比 555 少”替代副作用恢复证明。


```text
source identity + policy_version + ordered cohort message_ids + role
-> locale-neutral product_step_id
-> exact parent job + same product_step_id + call_id=turn-submit
```

## 6. 为什么不修改本地化入库合同

不修改的对象：

- 数据库表、列、索引与迁移；
- `localization-static-catalog-result.v2`；
- 每 locale `selected_messages/selected_catalog_hash/decision`；
- Website static catalog consumer 的候选验收语义；
- 五语 candidate set、ledger、manifest、import 与 publish；
- admission receipt 的最终含义。

必须修改的只是“执行前合同”：

- Website 五任务由一次预建改为严格前缀逐个签发；
- task-result/route policy 从 v11 单次切到 v12；
- 同一现有 route 的 relation 改为新封闭值 `provider_sequence`；
- root 无 parent triple，后四项必须带完整 direct parent triple；
- AGENT/Browser 按当前 step 精确选择 continuation URL。

为什么不选择“一张任务一次返回五语”：它会修改 result schema、consumer 原子事务、失败粒度、五次 admission 和控制室分母，把最难调试的入库合同一起重做。为什么不保留五任务并增加 URL 表：它会建立 Website/Runtime 的第二 conversation 真相。两者都比复用现有 parent triple + Browser WAL 更复杂。

## 9. 有限失败分母

| 分支 | 唯一裁决 |
|---|---|
| root source/policy/五语 partitions 不闭合 | Website 零 task |
| root 重复/并发 ensure | 读回同一 root，不新增 task |
| successor 父 locale 未 admission | 零 successor task |
| source/policy 在序列中漂移 | 旧链停止；新 identity 另建 root，不混链 |
| parent job 同 step WAL URL 缺失/多义/未 CONFIRMED | 零 navigate、零 submit、typed failure |
| current submit 明确未发生 | Website 依现役恢复法决定以后是否新 attempt |
| current submit 已发生或未知 | 只收敛同 effect，physical submit 增量为零 |
| A/B/S conversation 相同或 role/profile 证据不闭合 | 当前 locale result blocked |
| Provider 限流或上下文上限 | 停止，不 fresh fallback、不自动冷却 |
| locale result 业务拒收 | 不签发后继；由 Website 决定新 revision/新 source |
| 五 locale admission 完成 | 只进入候选发布链，不直接宣称 RELEASE |

## 10. 不可删除证明

| 结构 | 删除后的直接失败 |
|---|---|
| 五张 locale task 与五次 admission | 失败粒度和 Website 领域真相被合并，必须重做入库合同 |
| A/B/Selector 三角色 | 单 producer 自审或 selector 改稿，失去现役质量合同 |
| 五语 message-id partition 全等门 | successor 可能续到不同消息 cohort，形成串线 |
| Website direct parent triple | AGENT/Browser 必须自行猜业务前序 |
| `provider_sequence` relation | `primary` 无权续聊，`provider_continuation` 又无法表达无 parent 的 root |
| locale-neutral product step | Browser 无法把 successor role/cohort 对应到父 job 的 exact URL |
| step-scoped 原子 Child | job-level唯一 URL 对 `3C` 个父 conversation 必然多义 |
| Browser 唯一 WAL | 重启或失联后无法证明现实 submit 与 locator，可能重复副作用 |
| current result/admission consumer | Provider/Outbox 成功会被误称为业务入库 |
| Skill 原位更新 | 后续执行者会继续按每 locale fresh 或错误合并角色 |

除 step-scoped Child 和 relation enum 外，不新增任何生产结构。二者都有当前真实消费者、删除后的可复现失败和现有主链验收；其余拟新增对象若不能指出本表中的具体断点，一律禁止。


READY 必须是双仓 clean participant commits、v12 provider/projection exact、两仓各自原生唯一 quality verdict 通过。READY 不等于生产完成。

> 不重做本地化入库合同，不把五语合成一张大任务；保留五张 Website 任务与五次 admission，只把 conversation 隔离轴从“locale × cohort × role”改为“cohort × role”，由 Website 严格逐 locale 签发、Browser 按 exact parent step 续写。这个变化必须先解冻并同步修订双仓现役法案，再同时更新 Skill 与实践代码；否则宁可保留当前 555-chat 合法实现，也不得暗中旁路。
