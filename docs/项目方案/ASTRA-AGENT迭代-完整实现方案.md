## 9. 方案审计、准入与完成汇报

方案先由主Codex独立审计三轮：第一轮核四份源头与每S漏项；第二轮核现役法案、闭环Skill、删除前保留裁决及全部消费者；第三轮由最终研究成果反查入口、身份、分支、证据取得时点、收益、风险与停止位置。发现即修订同一方案，不以轮数证明无问题。

主审三轮已无可操作问题后，才分派未参与方案建设的子智能体，只能做只读审计/审查/第三方质检；禁止并发写代码、改方案、运行生产或拓展通讯范围。分派前完整读取subagent-review；独立审查者按源头→法案→本方案核对，实际取原文和当前候选，不读取主审自评来凑结论。主Codex核原件处理每条发现，实质修改交原审查者定向复核。未放行不得结束方案建设；不得用百分比或全系统PASS代具体事实。

状态仅使用设计中、设计阻断、可施工。可施工表示设计已明确，不表示生产写入权限、工程质量、模型能力或交付成立；本次生产写入只来自随后明确授予的第7节工单实施权限。若必须改变源头、active law、冻结语义或通讯合同，本专项不擅改，先报告具体冲突并停依赖部分。

执行时以重新绑定的权限和目标文件状态施工。单片区根因、保留、旧对象、输入输出、consumer、收益、风险及验证必须在删除前具备；缺任一项不动成熟结构。新消费者、来源漂移或职责遗漏先回补此方案，不能把问题留给施工后决定。无自动回退授权，禁止reset/clean/stash及恢复旧骨架；既有产物、原件、未知输入与收据不因失败清除。
