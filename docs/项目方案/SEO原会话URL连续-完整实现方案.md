## 4. 唯一目标链与必要性裁决

```text
原 CONFIRMED WAL locator + 合法当前授权
→ 原 checkpoint 从 live / cache / signed source 取得已完成回答
→ 同 execution 内保留这一 sessionKey 对应的原 URL
→ Product 原顺序请求下一步；原全历史/授权门仍先成立
→ 尚需取得 Browser 时选择原 confirmed-readback，不导航首页
→ 在当前 Child 原 runAtomicStep(identity) 内选择该精确 URL
→ 当前 URL 相同零导航；不同仅一次原 Browser 导航并 fresh readback
→ 原 Child 正常准备/发送/读回 → 原结果交付
```

只允许一份 execution 内的瞬时 `{sessionKey, canonicalConversationUrl}`，由现有 lifecycle 持有；不是跨任务会话身份、恢复位置、授权或持久存储。它只使用 Session 已从原 WAL 验真的 URL；不另读父 URL，不记录 stepIndex、已执行步骤、旧回答、Target、Document 或另一个 effect 身份。进程重建时不恢复该字段；先沿原 Website grant/WAL/checkpoint 重建，才有新的瞬时 URL。

具体交接固定如下：

1. `captureCheckpointHash` 是 live、同 attempt cache、signed source 的共同结算入口。在现有 `recordSettledResult` 调用中同时交付 `call.sessionKey` 与该已结算 submit 的原 canonical URL。先核本次 hash，再调用 lifecycle 完成 URL 交接一致性校验，成功后才向 `submittedByStep` 登记本次 settled hash；不得沿用“先登记 hash、再核 URL”的旧调用顺序。URL 校验失败时保留当前 confirmed effect，但没有本次 settled hash，使原 typed mismatch 不被 `decorateSettledResultFailure` 升格为 `RESULT_SETTLED_UNUSABLE`。未取得合法 locator、checkpoint 失败或完整性失败时不建立该值。
2. `recordSettledResult` 不再因 active Browser 缺席而丢掉这个 URL；仅由 Session 共同结算入口交付的 sessionKey/URL 建立该瞬时值。既有 active effect 的独立 hash 结算仍成立，只在已有该值时核对其当前 URL。同 session 已有原 URL 时不得被后续不同 locator 静默替换，不等沿原 `GPT_CONFIRMED_SUBMIT_IDENTITY_MISMATCH` 保全事实并失败关闭。校验必须先于该方法的 URL 或 settled hash 写入；失败不改原 URL。这是本次 URL 交接一致性，不增加 submit 前置或回答内容门。原 settled hash 只更新匹配的现役 active effect。URL 不携旧 effect 的失败分类，不能把下一 turn 的准备错误误标成上一 turn 的 `RESULT_SETTLED_UNUSABLE`。
3. `browserFor` 先处理显式 fresh 的 URL 退休，再对同 session 的 active lease 提前返回；这一 live 分支不得传入新的 confirmed-readback 模式，以免 `browserForMode` 把尚在使用的 confirmed effect 当成另一份 readback 清除。只有确实需要 acquisition、同 sessionKey 已有上述 URL且 Product 未明确请求新聊天时，才由 fresh 收窄为现有 confirmed-readback。无此值保留原 fresh 或授权父模式；不同 session 不复用该值。live 分支不增加 acquisition/导航。
4. `acquireProductionBrowserCall` 将 `call.child === prepare_clean_gpt_chat` 作为内部 fresh 请求传入 `browserFor`。该请求先退休瞬时 URL，保留 Product 的 fresh 主权；不是依据 callId 文案、产品名或错误码猜测。
5. 对因该 URL 取得的新 lease，复用现有 `recoverySelectionRequired`，不新增第二选择标志。lifecycle 内一个窄方法只在该标志待完成且无当前 confirmed effect 时，消费同 session URL、调用原 `selectExactGptConversation`；成功才清原标志。缺 URL/身份不等或选择失败沿原 typed error 退出，不能 fresh fallback。
6. `executeProductionGptAtomicCall` 仅在现有 `!priorOutcome → browser.runAtomicStep(identity)` 的闭包内，先完成上述选择，再执行原 `input.gpt.execute`。内部 `acknowledge_known_gpt_rate_limit` 必须跳过该选择：它只确认当前精确弹窗，不能被未完成的 URL 选择前置，不能因该选择再次命中弹窗而递归或错过原紧急期限；原普通 Child 的选择标志仍待其后合法执行处理。保留一份 identity、一次原 runAtomicStep 入口及原 WAL 查询/readPriorAtomicOutcome 分支。既有 CONFIRMED submit 仅读原收据；普通 target-local 旧 outcome 仍按原规则拒绝，不能因 URL 连续重放旧动作。known-rate-limit、异常与 finally 仍由原 ChildTools/Executor 收尾。
7. `settle` 无论 park 成功失败都清除该瞬时 URL；显式 fresh 和 session 转换同样退休。正常 Provider pending 轮询不清除、不另加等待；原 40 秒静默、至少 70 秒资格、唯一 FIFO 和 active lane 保护完全保留。

存在性裁决：

- 保留 WAL/locator reader：唯一可信 URL 来源；删除会丢失恢复定位。保留原 Forensics cache/source：它们已保护旧答案和零重复输入；不能为了拿到页面而重做研究。
- 保留 `submittedByStep` 原退休时机和失败分类：删除会把前一步成果误算为后一步失败。不得通过延迟清整个 Map 来保留 URL。
- 保留 Browser 的 fresh 强制复位和精确 URL 导航：其它 Product 真实消费隔离与恢复能力。不得把所有 fresh 改成不导航，也不得修改扩展条件掩盖错误调用。
- 唯一增加的瞬时 URL 值有真实消费者：原 Browser acquisition/原子调用。删除它会复现 cache/source 后无 activeBrowser、下一步 fresh；保留旧回答或整份旧 submit 均比该值更宽，并会污染失败分类，故拒绝。
- 不新增 URL 表/Map、continuation controller、resolver、Child、协议字段、第二恢复链、第二队列/定时器、重试、兼容桥、feature flag、日志载荷或测试入口。没有独立必要性的对象不进入方案。
