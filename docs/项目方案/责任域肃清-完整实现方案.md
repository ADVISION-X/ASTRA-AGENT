# 责任域肃清方案

## 1. 本方案只肃清法案系统

本轮先固定生产侧，只设计法案侧。先得到一套职责清楚、没有重复立法和越权立法的规范，再冻结这套规范，随后才能另行讨论生产代码如何服从它。不得同时修改规范和生产实现来相互解释、相互迁就。

当前 13 个 domain、39 条 active law 是待审样本，数量、名称、分组和既有条文均不享有默认保留资格。允许合并、删除、拆分、新增；每个动作必须说明保护的实际风险、唯一责任、承接位置和验证方法。既有代码没有实现某项合理职责，不能成为删除该职责的理由；代码已经实现某种做法，也不能成为把它写成法案的理由。

本方案不是新 active law，不对生产路径发布新命令。本轮 CHANGE 的唯一写入对象是本文；不修改现役法案、母本、Manifest、检查器或生产代码。

**明确冻结的另一侧：**生产源码、Product Skill/Prompt、运行控制流、Browser 协议及生成物、启动行为、依赖、业务合同、Website、持久化数据和运行服务。本轮不设计生产修复工单，不新增调度器、队列、状态、回执、接口或超时机制，不启动、重启、停止或执行工单。

这里的“冻结”是本任务的范围约束及字节核验，不创建 freeze 文件、台账或新运行状态。其他会话若改变相关基线，停止依赖该基线的结论并重新绑定，不覆盖其修改。

## 3. 当前法案系统的问题

### 3.1 第一处可直接证明的断裂

母本 §14.3 要求一条 law-record 只治理一个可独立修订或退役的风险，§14.6 要求一项 forbidden 只表达一个违法条件。现役条文却把多个 Owner、多个风险、多个证据等级及多次修补塞入同一法条或同一禁止项。结果是：独立问题不能独立修法、取证和裁决，下游容易继承一整包并不属于自己的义务。

例如 `LAW-LOCAL-BROWSER-SESSION-004-V58` 的 24 项 forbidden 同时包含 WAL、风险 grant、交互就绪、GPT 长短提示词结构、DOM 可见性、原生错误、动作读回节拍及限流弹窗；`006-V46` 的封闭载荷与末项又包含完整传输、终局回执和清理协议。这不是一个不可分割风险。

这证明需要先整理立法边界；**尚不能据此断言生产中的每个超时都由法条混杂造成。**生产因果调查留给法案冻结后的下一阶段。

## 4. 目标：一个责任域，一部逻辑法案

“一部法案”是一个责任集合的唯一规范正文，不等于一条 lawId，也不要求每域新增物理文件。一部法案可以含多个独立风险法条；每个法条仍只有一个 Owner、一个主题和一个最终裁决。

保留母本规定的两份物理 active law source。基础法案只容纳共通根治理；功能法案按责任域设置唯一导航章。章标题不增加义务。每项义务只存在于一个 law-record，其他位置用 lawId 或正式合同引用。这样满足“一域一法、多条各管一事”，同时不为整理文件另建 parser、目录发现机制或第二法案源。

经下列义务归位，目标为九个法案责任集合；**九不是固定数量约束，不写入编译器或验收断言。**这是一套法案归属设计，不是本轮对生产部门、模块或运行架构的改造决定。

| 法案集合／逻辑 Owner | 必须管的事 | 明确不管的事 | 本次组织裁决 |
|---|---|---|---|
| 共通根治理／code-purity | 项目确需的结构红线、唯一职责、模块调用方向、存在必要性、原子能力边界、机械验证与专业语义的分界 | 不决定某产品 Prompt、浏览器操作、业务重试；不重复母本的 parser/registry/report 规则 | 吸收 capability-governance 中确有项目风险的共通规范；治理程序不另立元法 |
| 产品职责与边界／architecture-boundary | Product 的专业 Skill、静态 Flow、输入输出责任；Catalog/Mediator 仅路由；产品间隔离 | 不签业务 attempt/revision，不掌握 Browser 物理队列，不以路径主权取得产品业务决策权 | 保留现有标识，收窄正文；通用模块纪律退出，外部授权正文退出 |

| 浏览器现实事实／local-browser-session | 扩展鉴权、当前 Target/Document、物理输入与只读观察事实、唯一物理 FIFO、WAL、终局事实传输及物理收尾 | 不决定产品内容、任务优先级、业务重试、attempt/revision、内容好坏和业务完成 | 将当前综合大条拆成独立主题；不把 Chrome 扩展写成业务主管 |

| 诊断事实／runtime-log-spine | 受控事件、因果、写入顺序、诊断完整性与安全投影 | 不从日志生成当前任务状态，不指挥恢复，不代替 WAL、Outbox 或领域入库事实 | 保留诊断法，敏感信息共通禁令引用安全法，日志特有实施约束独立 |

capability-governance 不因“名称像治理部门”而自动保留独立 domain；其有效规范被根治理完整接收后退出 active 分母。以上合并只发生在法案归属及治理登记，不能据此移动、删除、改名或重写生产文件。

### 4.1 三种 Owner 必须分别表达

1. law-record 的逻辑 Owner：负责这项规范主题，不能借一条法律决定别人的全部工作。
2. Manifest 的 primary Owner：负责登记路径的维护与变更边界；`observedPaths` 只读，不授予写权。
3. 业务／动作决策 Owner：具体授权与事实由谁产生，只能由该主题法条和正式合同规定。

不新增三个 Owner 字段或第二权属表。继续使用既有 schema，在法条正文中准确规定决策边界，在 Manifest 中登记路径，在 Blueprint/spec 中表达正式交接。不得把三种权力压成“我维护文件，所以我决定业务”。

## 5. 两部容易混淆的法案必须这样写

### 5.1 “拓展”先拆清含义

本项目语境中，Chrome 扩展属于 Browser 的执行端；GPT Child 属于 GPT 的原子能力；Product Plugin 属于产品静态业务。三者不能因为都具有“扩展能力”而受同一部模糊的拓展法案统治。

浏览器现实事实法案只治理以下独立主题：

| 主题 | 它必须做 | 它不得做 | 证据对象 |
|---|---|---|---|
| 身份与通道 | 证明当前固定扩展、已鉴权通道及构建身份 | 把连接存在当成任务可执行或业务成功 | 配对、鉴权与发布身份事实 |
| 当前位置 | 证明当前 Target/Document 与当前授权动作匹配 | 把旧 Tab 或派生 hash 变成业务恢复身份 | 当前绑定、失效与精确读回事实 |
| 物理占用 | 维护唯一物理 FIFO 与真实操作生命周期 | 制定产品优先级、替 Website 派工 | 入队、取得、释放与真实 native 退出事实 |
| 输入副作用 | 记录并证明同 effect 输入事实，执行当前精确 permit | 从未知推导零输入或自行获得重放资格 | 原 WAL、原 effect 与 typed terminal |
| 机械观察 | 证明观察来自同一当前文档及一致事实包 | 决定回答专业质量或把等待时间当成功 | 原生观察、直接后置与稳定错误 |
| 终局传输与收尾 | 保全、送达和结算真实终局事实，区分回执与物理退出 | cleanup 撤销有效结果、日志替代终局事实 | 终局事实、持久接收及真实收尾读回 |

GPT 页面“这是什么控件、当前 Child 完成意味着什么”归 GPT 法；“我确实在当前文档做过一次输入、读到这些事实”归 Browser 法。已冻结的时钟、两门规则和载荷限制不在本轮擅改；其跨域职责通过单一正文及精确引用表达，不通过复制条文分配。

### 5.2 不建立一个包办所有事情的“调度法案”

必须分别写清三种权力，不能合并成一个中央主管：

- **业务派工与恢复授权**：Website.ai-acceptance 的外部主权。AGENT 法案只规定如何验证、消费、拒绝不合格授权，不复制一份 Website 授权算法。
- **产品内部业务顺序**：Product 负责其专业静态 Flow。Runtime、GPT、Browser、Mediator 都不得接管。
- **共享浏览器物理排队**：Browser 负责唯一物理 FIFO。它决定物理资源何时可用，不决定业务应否重做。

Runtime 的法案是运输与交付法，不是全系统调度法。出现 Browser 超时，只能由 Browser 产生其事实、GPT/Product 传播其 typed 失败、Runtime 按正式合同运输；任何一层都不能因此新增业务授权。这里只规定法律边界，不设计相应生产修复。

## 7. 法案系统各层的责任边界

| 层 | 可以规定／产生 | 不得接管 |
|---|---|---|
| 冻结母本 | 法案系统结构、准入、证据类别、编译、唯一质量裁决和授权规则 | 项目产品 Prompt、页面控件或运行补丁 |
| active law | 一个责任域的必须／禁止、独立风险、Owner、适用面及证据等级 | 文件盘点、当前事故故事、机器字段副本、一次施工过程 |
| Blueprint | 已获法案授权的复杂拓扑、时序与交接，指向正式合同 | 创设新义务或覆盖上位禁止；把旧方案变成第二法律 |
| spec／typed contract | 必需的机器字段、版本、身份、输入输出及安全合同 | 新增业务权限、重写法案或复制另一仓 provider 正文 |
| Manifest | 域、active lawIds、ownedPaths、observedPaths | 法条正文、检查器名单、PASS 条件或额外授权 |
| registry／builder | 从唯一源头派生当前索引并校验完整性 | 通过生成物倒推法律、人工维护第二事实源 |
| inspector／Exam／proof | 按当前法条实际取证，返回实际覆盖的 clauses、refs、findings | 固定历史数量、用通用总 PASS 遮盖漏项、因实现现状改写法律 |
| quality report | 对当前候选逐法裁决，明确等级和缺口 | 立法、授权下一步、替业务系统宣称完成 |
| 项目方案／Skill | 按现役权威组织任务与施工，记录本次边界 | 成为隐藏 active law，或用 Skill 的步骤覆盖项目 law |

需要调整机器字段细节时，先判断既有 typed contract 是否已足够；足够就直接引用，不为每个法条新建 spec。母本已有规则直接执行，不再创建一部“法案如何写法案”的元法。

| GAP | 法案动作 | Blueprint／合同动作 | 生产侧 | 质检动作 |

调查在 AGENT 法案系统边界停止。Website 的授权、领域入库和 provider 合同作为已存在的外部主权引用，不重新定义；对其生产实现不作本轮结论。AGENT 生产代码与动态故障不进入本轮修复分母；以后必须对照冻结后的法案另立授权范围，不能复用本方案的法案授权自动改代码。

## 9. 法案侧原子工单

以下是拟批准后的法案系统工单，当前不执行。共同施工纪律：先检查目标路径 Git 状态；保留用户修改；先完成有效义务的逐项承接再删除旧 active block；旧新版本一次切换，不双 active，不造兼容法案。每项动作的证据沿用当前任务实际操作记录和原生 quality 输出，不新增台账或第二报告。

### LA-1　固定生产侧并绑定法案候选

- Owner：主 Codex；对象：第 2 节的候选、两份 law source、母本、13 份 Manifest、现役 Blueprint/spec 和唯一质量入口。
- 做：重算冻结分母；将本轮法案系统实际差异与生产冻结分母分开核对；确认用户修改没有被归入待删对象。
- 不做：更换分支、reset、stash、回退其他会话提交、操作服务或数据库。
- 验证：生产路径集、内容、模式与基线一致；相关法案 overlay 全部解释。漂移时只重绑受影响对象；未经授权不回滚。

### LA-2　批准唯一职责正文及冻结片段处置

- Owner：授权人批准，主 Codex 制作精确 law-amendment 差异。
- 对象：两份 active law；第 6 节全部 39 个旧记录；母本 §14/17/39/66/70—72。
- 做：先把有效义务按第 4—6 节归位，列清新增、修订、合并、退役及依赖变化；冻结片段只按准确标识单独呈现，不使用“整体批准即可默认为解冻”。
- 不做：修改生产以证明新法可行；改母本降低准入；更改 Website 授权算法或业务合同。
- 验证：每项旧义务有唯一承接或具体删除理由；每项新义务有独立现实风险和证据对象；每项改变冻结片段的动作有对应明确授权。
- 失败：缺少冻结授权就停止该迁移，本文保持设计阻断；不能保留重复副本来制造完成。

### LA-3　重建两份 active law 的唯一正文

- Owner：各法案逻辑 Owner，主 Codex 负责同一 law-amendment 落盘。
- 对象：`.github/instructions/agent-rules/基础法案.md`、`功能法案.md` 的 law-record 与导航标题。
- 做：删除批准退役的完整旧 block，立即核验旧 block 缺席，再按已批准的新主题正文建设；经裁决保持的冻结 block 直接保留，不删除后恢复旧骨架。删除规范副本，不重写为同义副本。
- 不做：整文件清空导致未获授权条款丢失；把当前字段清单换一个文件名继续当法律；创建第三 active law 或永久迁移映射。
- 功能验证：一主题一法条、一个违法条件一项 forbidden；summary/forbidden 同一风险；版本与 supersedes 合法；依赖只指向新 active 集合且无环。
- 纪律验证：旧新 block 的切换、删除即时缺席、保留边界均有实际过程记录。最终 diff 不能单独证明中间纪律。

### LA-4　法案登记原子归位

- Owner：Manifest 当前 primary Owner；接收侧为 code-purity、local-app-shell 及其他保留域。
- 对象：13 份现有 `scripts/audit/domains/*/manifest.json`；唯一 registry。
- 做：按批准正文归并 lawIds；工作台三域与 capability-governance 退出；其既有路径登记一次性转入接收域，接收与退出同一事务性差异完成。
- 不做：借登记归位移动或重写 `src/**`、启动器、Product Skill；因目录名相似接管额外路径；新增 scope、Owner 数据库或影子 Manifest。
- 验证：每个存续生产路径仍唯一 primary-own；observed 不取得写权；法案、Manifest、registry 的 active lawId 集合精确相等；退役域不再有 active 身份，不能靠保留空 Manifest 假装退出。
- 失败：出现无主、重叠、未承接规范或 frozen 记录迁移未授权，停止本次归位，不提交半成品登记。

### LA-5　从承接对象中删除隐藏法案

- Owner：各现役 Blueprint/spec 的逻辑 Owner；范围限 `docs/blueprints/**`、`docs/specs/**` 和精确关联规范引用。
- 做：对七份现役 Blueprint、五份现役 spec 核对引用；删除无授权的新义务、重复正文和退役 lawId；机器字段只用原合同，复杂边界只用原 Blueprint。Website provider 不在写入范围。
- 不做：重排生产流程、改协议或业务合同含义、全面改写历史方案、增设每法一图／一 spec。历史方案保留为历史，不再充当现役依据。
- 验证：从任何承接对象均能回到唯一法条；删除任一副本不改变权利义务；移走的字段在原正式合同有唯一完整来源。
- 失败：发现必须改变外部合同或生产行为才能成立的规范，记录准确冲突并停止该依赖，不顺手扩展本阶段。

### LA-6　先审判检查，再调整治理实现

- Owner：code-purity 的共享 quality core 与各存续法案 Owner。
- 对象：`scripts/audit/domains/**`、`scripts/audit/shared/quality-routes.ts`、现役治理反例及直接承接退役规则的测试。
- 做：逐项确认检查所保护的新法条和具体违法实现；删除只保护旧数量、旧域名、旧法号或重复义务的检查；把有效断言转给新法条。退役域检查中仍保护有效风险的实现可由接收域直接接收，不能整目录盲删。
- 不做：为了全绿放松生产安全、不把结果固定为 PASS、不用另一 proof 的 verdict 充当本次证据；不修改生产测试来改变被冻结行为；不新增第二 quality 命令或报告。
- 验证：缺 Owner、缺条款、空 refs、错误 evidenceMode、候选漂移、新旧法同时 active、已退役规则复活均精确失败；共享执行仍逐 lawId 返回实际 assertions。母本已有反例复用，不机械每条新增测试。
- 失败：新法使冻结生产暴露真实不符，保留 finding；它是下一阶段的输入，禁止偷偷改法或生产消掉 finding。

### LA-7　冻结法案侧并交接，停止本阶段

- Owner：主 Codex；适用母本 §79 时，在实际治理迁移完成后安排其规定的独立审查，不在本设计阶段冒称已完成审查。
- 做：复用原生 `quality:check` 的实际等级与报告；完整列明法案系统自身缺陷和被冻结生产的不符，核对生产冻结分母，固定经批准法案正文的 Git 候选及内容身份。
- 不做：把“规范已经冻结”命名为 READY/RELEASE；把生产不符当作法律无效；为了使全量质量变绿同步修生产。
- 验证：第 10 节分母全部有事实结果；法案侧自身缺口全部消除，生产侧差距仍如实可见。只有另一次明确生产建设授权后，才以此冻结法案为输入讨论实现。
- 失败：法案侧仍有未决主权、冻结授权缺口或隐藏义务，不能宣称肃清完成；生产侧变化则先重绑，未经授权不恢复旧代码。

这组验收是本方案的交付核对，不是新的 active law 或质量裁判系统。真实 quality 结果仍只由原生入口出具。设计文档检查不证明未来迁移通过，治理检查也不证明生产完成。

删除反事实必须逐类成立：

- **两份源头、唯一 registry、唯一质量入口保留**：删除会失去现役权威和统一裁决；已有实现足够，不新增替代系统。
- **Runtime 007/008 的独立法条退出**：其通用治理义务已有母本；本域风险的证据等级回到实际风险条，独特安全义务不能随旧编号消失。不存在为维持这两条而必须保留的独立生产消费者。
- **通用两判据／双消费者配额退出**：配额不能证明权限、安全或原子性；现役职责、存在证明和具体风险判据可直接约束错误，特定冻结门不受影响。
- **四个工作台域合一**：保留所有独立风险和证据，只删除重复的规范主权；不删除工作台功能，不把四组裁决合成一个粗粒度 PASS。
- **Forensics 与 Browser WAL 不合并**：分别保护已完成原始产物与真实输入副作用；任意删除一方都会失去另一方不能代替的事实证明。
- **不新建域法文件、配套台账或治理 Agent**：两份现役源和已有 schema 可以表达目标；新增结构没有本次独立消费者与必要验证收益。
