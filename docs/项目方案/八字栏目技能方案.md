# 八字栏目 Product Skill 终态方案

> 状态：与当前法案、施工图和生产代码对齐
>
> 更新日期：2026-09-11（Asia/Dubai）

## 一句话结论

八字 AI 只保留三个独立 Product：`bazi-chart-interpretation`、`bazi-ai-full-analysis`、`bazi-report-followup`。每次 Website 新签发的 attempt 都从 Product 第一入口完整执行一次；失败 attempt 永久结束，不读取旧会话、旧回答或旧执行位置。

## 产品边界

| 商品 | Owner | 处理方式 |
|---|---|---|
| BZ01 基础排盘 | Website | 确定性计算，不创建 AGENT 任务 |
| BZ02 PDF 导出 | Website | 确定性导出，不创建 AGENT 任务 |
| BZ03 专项分析 | `bazi-ai-full-analysis` | 当前 attempt 内完成一次 GPT 生产流程 |
| BZ04 报告追问 | `bazi-report-followup` | 读取 Website 下发的已批准父报告材料，开启一次全新 GPT 执行 |
| BZ05 全盘解读 | `bazi-chart-interpretation` | 当前 attempt 内完成一次 GPT 生产流程 |

三个 Product 互不调用、互不共享业务 Flow。Naming 可消费 Website 已冻结的八字材料，但不属于八字 Product。

## 唯一生产主链

```text
Website 保存不可变 Job 并签发新 Attempt
-> Runtime 持久接收 Attempt、lease 与 fence
-> Mediator 精确路由到唯一 Product
-> Product 按静态 Flow 调用 GPT
-> Browser 以 Attempt 动作身份保证物理副作用不重复
-> GPT checkpoint Child 等待并稳定读回本次回答
-> Forensics 只保存一份不可变 raw answer artifact
-> Product 解析并组装唯一结果
-> Runtime 写唯一 Outbox 并发送 Website
-> Website 领域事务入库并签发 admission receipt
-> Runtime 校验 receipt 后完成本地任务
```

## 六份不能删除的真相

1. Website Job：证明用户要什么。
2. 当前 Attempt、lease、fence：证明谁被授权执行这一次，并拒绝旧请求。
3. Browser WAL：证明当前 attempt 的同一物理动作是否已经发出，避免重复点击。
4. raw answer artifact：保存 Provider 页面稳定读回的唯一原文，供 Product 解析。
5. Runtime Outbox：保证结果跨进程送到 Website，且同一写入身份不重复。
6. Website domain admission receipt：证明结果已真正进入业务数据库，而不是只到达接口。

任何结构若不能证明“删除后上述主链会在哪一步立即失真”，就不得保留。

## 一次性 Attempt

- 一个 attempt 只从 Product 第一入口开始一次。
- Browser mutation identity 必须包含 `attempt_id`；同一 attempt 的同一动作最多 dispatch 一次。
- 完整回答或明确失败后，这个 attempt 立即终结。
- 崩溃、超时、lease 失效、结果不明或 Website 拒绝，都不得在 AGENT 恢复旧 attempt。
- Website 若仍需要同一 Job 的结果，可在自己的有限退避后签发新的 `attempt_id`。
- 新 attempt 不读取旧 conversation、checkpoint、DOM、raw answer、staged result、Outbox 或失败记录。

因此删除 continuation、session controller、fork、跨 attempt checkpoint、重复等待 Child、重复 readback、reservation、execution context 和逐 Child 证据账本；不保留 alias、fallback、兼容桥或第二链路。

## GPT 与 Browser 分工

Product 决定 Prompt、模型、Child 顺序和结果组装。GPT Child 只做一个页面原子动作。Browser 只执行物理动作并保存自己的 WAL。

提交 Child 只负责一次提交；文本或图片 checkpoint Child 在同一次调用内完成有界等待、稳定判断和读回。不得再增加独立 wait Child、会话恢复 Child、旧结果查找器或跨调用 checkpoint。

Browser WAL 的结算直接使用 Browser 自己的动作后置事实。Forensics artifact 只承载回答原文，不承载 Browser 权威，也不形成逐 Child 生命周期账本。

## 三个 Product 的输入和结果

### BZ05 全盘解读

- 输入：Website 冻结的命盘、订单授权、语义分母和输出合同。
- 执行：当前 attempt 内独立生成一次正式分析。
- 完成：Website Bazi domain admission 和 exact Delivery Manifest 均成功入库。

### BZ03 专项分析

- 输入：Website 冻结的命盘、用户问题、订单授权、语义分母和输出合同。
- 执行：当前 attempt 内独立生成一次专项分析。
- 完成：Website Bazi domain admission 和 exact Delivery Manifest 均成功入库。

### BZ04 报告追问

- 父报告只允许 Website 已批准的 BZ03 或 BZ05 结果。
- Website 把父报告作为当前新任务的不可变材料下发。
- Product 不定位旧 GPT 会话，不续接旧对话，不复用旧 attempt。
- BZ04 不能成为新的 BZ04 父报告。
- 完成标准由当前 BZ04 领域 consumer 的 admission receipt 决定。

## 失败主链

```text
任一 Owner 发现当前步骤失败
-> 生成一个结构化 typed failure
-> Runtime 持久保存当前 attempt 失败并结束 lease
-> Website 接收明确失败
-> Website 决定停止，或以后签发一个全新 attempt
```

页面上曾出现答案但没有形成 raw answer artifact，属于本次 attempt 明确失败；不得回头查旧页面。Outbox 回复不明时，Website 以自己的领域入库事实为准：已入库就返回同一 receipt，未入库则以后新建 attempt。

## 完成边界

- GPT 页面显示答案：不是完成。
- raw answer artifact 落盘：不是完成。
- Product 解析成功：不是完成。
- Runtime Outbox 已发送：不是完成。
- Website 接口返回普通成功：不是完成。
- Website 领域事务入库并返回匹配当前 `job_id + result_payload_hash` 的 admission receipt：才是完成。

BZ03/BZ05 还必须同时返回 Bazi domain admission receipt 与 Delivery Manifest。review 类结果只允许 review receipt，不得混入正式报告完成字段。

## 数据库边界

AGENT Runtime 只保留 `production_tasks`、`production_leases`、`production_outbox` 三张表。Website 保存 Job、Attempt 授权、领域结果和业务 receipt。

不得建立 continuation、checkpoint、reservation、execution context、旧会话映射或 evidence-record 表。历史迁移文件永不修改；结构删除只能通过新的前向迁移完成。

## 验收

静态验收必须证明：

- 三个 Product 的 route、输入、材料和结果合同与 Website 当前 projection 完全一致；
- GPT 只有当前 13 个 Child，且不存在 continuation、fork、独立 wait 或恢复 Child；
- Forensics 只有 artifact append/read，没有 record lifecycle；
- Runtime 只有三表，没有第二队列、第二恢复器或第二完成裁决；
- Website 不再生产或消费 reservation、execution context、continuation；
- 历史 migration bytes 与登记 hash 未改变；
- 两仓只有一份 native quality verdict。

动态验收必须使用真实 Website Job、真实 Product、真实 GPT 页面、真实数据库和真实 admission receipt。READY 只证明候选满足静态和本地验收，不能冒充 RELEASE 或生产成功。

## 防止过度设计

新增字段、表、接口、Child、状态、账本或 Owner 前，必须同时回答：当前哪一步没有它会立刻失真；谁真实读取；用什么验收。只因“以后可能用”“方便排查”“更完整”不能新增。

默认处置是删除无消费者结构。代码总量原则上只能持平或减少；确有不可分割的新增时，必须由删除量抵消，并在施工前说明当前必要性。
