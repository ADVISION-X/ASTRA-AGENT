三个Product互不调用，不共享业务Flow。人物命名及合婚只通过Website冻结、已交付且合法可复用的BZ05及同源事实接力，不接管八字研究。商业命名独立，不使用经营者命盘代替商业对象。

Website唯一拥有出生资料、历法、L0/L1事实、授权、材料recipe、业务输入及输出合同；Product不得重排、补算未提供机械项或改变事实。完整事实应直接可读，保留归属、位置、时间、状态及原因、真实条件、候选和关联。用户原话及完整上游/父报告不以摘要替代；命盘PDF可以补充验真，不能反推替代现有事实。

各Product沿本轮route取得原有材料集合，先核目录和冻结来源，再实际读取所需完整事实、索引与原文；索引仅导航，引用以实际回读的原文及上下文为据。合法局部未知只限制受影响结论，资料漏失须如实报告，不冒充事实不存在。具体文件、schema及字段由Website唯一合同定义，不在本文复制。

## 一条执行与交付链

Website冻结需求并签当前精确grant → Runtime durable accept → Mediator路由一个Product → Product自有静态Flow/Prompt/模型调用GPT公共能力 → Browser唯一lane/WAL守住现实输入 → Forensics封存并读回已完成回答 → Product基础接收及本产品获准无损归一 → Runtime原子stage与唯一terminal Outbox → Website领域接纳、PDF及权益交付 → admission receipt读回 → Runtime本地completed。

Skill只拥有专业解释目标、方法和材料使用义务；实际步骤、模型及分支只在所属Product代码中存在。AI自主解释旺衰、格局、用神、支持反证和岁运，专业与通俗表达等义，不反写机械事实。程序不以关键词、字数、评分等代理指标裁决内容质量，不在AGENT重复领域内层验收。

原始回答先封存，后由原唯一JSON object提取器接收；必要schema/route/锁定身份仍失败关闭，合法未知内容字段保留。一次无损归一仅限唯一对接方案明确命名的字段表现，不补内容、不改原名、不添加模型修稿回合。

## 授权、effect与未知结果

Website.ai-acceptance是唯一业务恢复决策Owner。attempt/lease/fence只证明当前执行权，不能替代稳定业务需求或Provider effect。effect身份按现役Browser合同，**不含attempt、进程、Target或Document**；更换Prompt/hash也不证明旧输入为零。

任何页面准备前先核全历史effect。全部可信零输入才可按当前授权fresh准备；同一已输入或未知effect先按原身份零提交读回。普通新attempt、原答案有界不可得后的精确新revision风险grant、已拒结果的新revision及两种精确零提交来源，全部沿现役Website裁决、Runtime来源seal及Browser/WAL原链处理，本文不另立资格。BZ03/BZ04的业务父正文始终来自本轮Website材料，不以历史Provider聊天接续。

已有机械有效结果优先沿原身份交付。Outbox回复未知先读回同job/attempt/payload及Website staging/admission，不重做研究；cleanup、日志或旧first failure不能撤销结果。失败不自行终止未撤权需求，也不创建replacement job、第二恢复器、队列、状态或存储。历史未决不能连坐其它合法工单。

## 存储与完成证据

Runtime唯一持久结构为production_tasks、production_outbox、production_attempt_handoffs；第三表只保存原来源seal及交接证据，不取得恢复裁决权。已有库普通启动只读校验，Website lease/fence镜像、Product执行位置、continuation store和第二Outbox不存在。Browser WAL与Forensics仍分别保存原现实输入事实和完成回答，不新建逐Child生命周期账本。

模型回答、artifact封存、解析、上传、terminal或普通HTTP成功均不等于业务完成。三个正式八字报告及译本对外只交付同身份、语言、版本、内容完整可读且有权用户可读取下载的PDF；必要领域receipt及Delivery Manifest沿Website原Owner闭合。Runtime只在完整校验同job/result的business admission receipt后completed，不能以自身状态替代交付。

## 验证与结构预算

原Product自有验收覆盖实际Skill/Prompt消费、材料及父身份、一次submit和已授权零输入读回、raw保真及必要接收边界；原Runtime/GPT/Browser验收分别守各自权威，不复制Product流程。Child数量及路由集合从当前唯一合同与目录发现，不保存旧固定名单。旧strict校验方案已退役，不能再据其增加重复领域考官。

各仓只使用自己的原生quality:check，CHANGE、READY与RELEASE分别报告；真实Website材料、模型实际读取及用户PDF交付须有对应动态证据，fixture和READY不能替代。新增或继续保留的结构须证明当前用途、真实消费者、唯一Owner、删除后损失及验证方式；优先直接复用原件，不制造共享workflow、兼容桥、第二truth或额外台账。
