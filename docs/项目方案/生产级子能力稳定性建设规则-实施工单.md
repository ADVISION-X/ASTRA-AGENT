### 4.2 固定的安全 proof envelope

每个 Child 的运行 proof 只能是以下安全投影；字段不适用时使用明确的 null 或 Profile 合法枚举，不能删除字段、用自由文字补洞或创建第二 proof schema：

```text
child_capability_id
child_contract_version
child_status = success / failed
child_reason_code
exact_call_identity_hash
internal_decision_code = DONE / ACT / WAIT / FAIL_CLOSED / null
authority_ref_hashes
fact_result_ids
candidate_cardinality
mutation_outcome = no / dispatched / confirmed
postcondition_result = passed / failed / pending
browser_fact = null / {
  exact_call_identity_hash
  child_capability_id
  effect_scope = target_local / provider_effect
  browser_outcome = DISPATCHED / CONFIRMED / REJECTED
  mutation_outcome = no / dispatched / confirmed
  terminal_at
  evidence_ref
  evidence_hash
}
native_failure_code
```

`mutation_outcome` 不含 rejected。Browser 为 DISPATCHED 时 `terminal_at` 必须为 null；CONFIRMED 或 REJECTED 时必须是首次终局写入后不可变的非空时间。外层 outcome 只描述当前 Child，嵌套 Browser fact 只描述自己的 exact effect，两者不得按时间邻近合并。原 confirmed submit 与后续只读失败同时保留各自 exact call identity。Target 和 Document 只保留不可逆 hash。raw DOM、HTML、Prompt、cookie、token、资源 URL、可变本地路径不得进入 proof；现役法案允许的 task-owned exact response artifact 仍由原唯一 Owner 保存，proof 不复制其内容。

### 4.3 固定的摧毁式验收分母

| Gate | 必须覆盖的破坏和不变量 |
|---|---|
| COMMON | exact input、Owner 和 boundary；相同输入加相同权威事实得到相同裁决；公开结果仅 success 或 failed；mutation budget；无跨 Child 副作用；coherent packet；每个机械字段逐项造假；missing、ambiguous、stale、redraw、already-satisfied、known variant、unknown drift；完整正反后置；安全 proof；public Facade 每次只委派一个 handler |
| DOM_OBSERVATION | 候选零个、一个、多个；Document 和 revision 改变；fresh observe 丢弃旧事实；任何路径 mutation 均为零 |
| TARGET_LOCAL_MUTATION | zero-action、唯一 action-qualified、TOCTOU、dispatch 前后中断、新 Document 或 Target generation 禁重做、negative postcondition；wait text/image 的精确频繁提示在同一 exact call 至多确认一次 |
| PROVIDER_EFFECT_ONCE | PREPARED、DISPATCHED、CONFIRMED、REJECTED、return 前崩溃；已 confirmed 后再次 mutation 为零；Target 丢失、进程重启、readback timeout 不重做；Provider 后置、WAL 和 Forensics identity 闭合 |
